<objective>
Build the state a half-finished task move leaves behind, and make it survive the
program closing, before anything is allowed to delete a task at a provider.

Purpose: criterion 1 of phase 5, and decision 1 of 2026-09-06, which is to build
the provider task move with the local cache as the safeguard. That decision
names what makes it safe: the move is a delete on one list and a create on the
other, the failure it is about happens between the two, so the local cache holds
the task's full content across the gap and the recovery reads from it.

**This plan builds the gap and the recovery and nothing that crosses it.** No
call to Google and no call to Microsoft is added, and the refusal that stops a
provider-held task being moved is untouched. `05-08` is the plan that opens it,
and it is the next one. That ordering is deliberate: the only work in these
three phases that can lose somebody's data goes last, after the state its
failure leaves is a visible, testable object rather than a hope.

Output: one additive column, two writes that happen together or not at all, a
deletion that refuses to go out while it would leave the provider holding
nothing, and a test that closes the database and opens it again.
</objective>
