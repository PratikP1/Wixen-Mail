<decisions date="2026-10-02">
- **D1, Pratik's answer:** "yes." on 2026-10-02, to a durable fix for
  ledger 716 so the tests that use the clipboard run whether or not the
  Windows session is locked, instead of failing with "OpenClipboard
  failed".
- **D2, the paste stays a real paste; no seam.** The field's paste is
  Windows' own code by design (premise 4), and wxdragon offers no text
  paste event (premise 3). A seam would put program code between the box
  and a paste, the thing `wx_passphrase.rs` promises not to do, and the
  test would then prove that code instead of the box a password manager
  pastes into. Option (a) of the brief is declined for that reason.
- **D3, split by what each case needs.** The four window cases and the
  two source readings stay in `tests/a_locked_key_asks_for_its_passphrase.rs`,
  which opens no clipboard, and stay coupled to `wx_app.rs` and
  `wx_passphrase.rs`. The real paste and its companion move, names
  unchanged, to `tests/a_passphrase_box_takes_a_real_paste.rs`, coupled
  by a new record to `wx_passphrase.rs` alone.
- **D4, a refusal is a failure that names its cause, never a pass.**
  Four causes, each its own sentence: the session locked as Windows
  reports it, whose sentence begins "the clipboard is refused while the
  session is locked"; another window holding it, named by its handle and
  its process when Windows gives one; refused with the session unlocked
  and no window named; Windows not saying whether the session is locked.
  Each says what was tried and what to do. The field refusing a paste
  keeps its own sentence, `THE_FIELD_REFUSED_A_PASTE`, and the companion
  fails with the refusal's sentence when its own paste was refused, so a
  refused clipboard can never read as a field that refused a paste.
- **D5, the lock state comes from Windows.** `WTSQuerySessionInformationW`
  with `WTSSessionInfoEx`, `SessionFlags` at byte 16 of the answer
  (premise 5), never `LockApp.exe` or `LogonUI.exe` in the process list
  (ledger 716 as 13-44.5 widened it).
- **D6, a bounded retry.** The test's own `OpenClipboard` is tried every
  40 ms for 2 s before a refusal is named: it outlasts a brief holder
  (premise 5: 31 tries for a 1.5 s hold), and under a lock it only
  delays the failure by 2 s. It does not wait for an unlock: a hook
  waiting hours says nothing while it waits.
- **D7, one turn at the test clipboard.** A named mutex,
  `Local\wixen-mail-tests-one-turn-at-the-clipboard`, taken before the
  station and held until the harvest ends, waiting at most two minutes.
  Fixed, not named for the executable as 13-44.2's `OneRunAtATime` is,
  because what is shared is the logon's station (premise 5), not the
  executable.
- **D8, the census.** No file under `tests/` but the paste target names,
  in code with comments and string literals removed, `OpenClipboard`,
  `SetClipboardData`, `GetClipboardData`, `EmptyClipboard`, `WM_PASTE`,
  `WM_COPY`, `WM_CUT`, `Clipboard::`, `TheDesktop::this_one`, `.paste()`,
  `.copy()` or `.cut()`. It lives in the dialog target, which the record
  "a message opened in a reader window asks for its locked key's
  passphrase" runs on every commit touching `wx_app.rs`. Its limits,
  written beside it: a new test file alone reaches it only at the
  phase's full gate and on CI, since the gate couples no file under
  `tests/` to another target; it cannot see a clipboard reached through
  a public function further down or a posted Ctrl+V. The overrule is to
  put it in `tests/house_style.rs`, which runs on every commit, at the
  price of re-measuring the 29 records that name that file.
- **D9, both targets keep a station and desktop of their own,** so no
  window reaches the screen or the screen reader; the paste target's
  desktop is named `wixen-passphrase-paste-test`, not the dialog
  target's `wixen-passphrase-test`.
- **D10, the ledger.** 716 closed as fixed with what was measured; one
  `unrun-verify` opened for what only a real lock shows (the paste
  target's locked sentence, and the dialog target green while locked),

- **D11, nothing spoken or shown changes:** no changelog entry, no push,
