# Phase 13 Plan 21.2: The calendar on this computer's clock Summary

Every calendar surface now says an event's hour as it is on this computer. The calendar's
item carries the zone stored beside its start and end, and `presentation::event_times` is the
one place the two meet. The list's first cell, its out-of-hours note and its order, `Space`,
the full reading and the printed page, the header's range, the Calendar window's Date/Time
column, the due window's alert and its sentence, and the event editor all read through it. An
Outlook meeting stored as 14:00 beside "UTC" is at 09:00 in New York in March, where until
this plan it read 14:00. The full reading and the page say the clock the event was written on
once, where that clock names a place and differs; the rows, `Space` and alerts never do. The
editor shows this computer's clock, saves a typed time as the clock face the event's zone
gives that instant, and hands back an untouched box exactly as before, so saving untouched is
still no change. Nothing stored changes, and the due identity is still the id and the stored
start. Ledger 632 is closed.

## Deviations from Plan

**1. [Test] The Outlook list case holds the instant, not the cell, and was renamed after its
red.** On a machine on universal time, where CI runs, the stored 14:00 and the right hour are
the same words, so a case about the Outlook cell was red here and would be green there, and a
record naming it would fail the sweep on the runners. It is
`test_an_outlook_meeting_stored_in_universal_time_is_read_as_that_instant` since `25d52411`; the
Tokyo cases hold the cell. The same reasoning set the due window's record: its break replaces
the `when_it_starts` binding, so the Outlook due case is red on every machine through its
`when` text.

**2. [Shape] `when_it_starts()` once in the cell.** Bound to `starts` and read by both the
date and the out-of-hours note, so the two cannot disagree; the plan's grep for at least 2
reads 1.

**3. [Test] The later cases build their rows with the zone set by hand** (`in_a_zone`), so they
read the surfaces and not `from_entry`, which task 1's cases hold. That kept the item record's
red list at 6 through both later greens.

**4. [Shape] The Calendar window's column shows an unreadable start whole.** It used to be cut
at 16 characters; the plan's "the stored text for a row that does not read" is taken as
written.

**5. [Scope] The module header is in `event_times.rs`, not `mod.rs`.** `mod.rs` carries no
per-module comments, so the line saying what the module is went into the module's own doc.

**6. [Docs] Two sentences 13-21.1 wrote are superseded in place.** Its changelog entry's "the
calendar itself still shows and says such a meeting at the hour it was written" now says it did
until this entry, dated, and the guide's Meeting invitations paragraph points at Time zones.

**7. [Brief] The banned tools' names, twice.** One pipeline stage was a command name beginning
with one of them, which the shell did not find, and one a do-nothing variable assignment
carrying the other; neither tool ran and nothing was written.
