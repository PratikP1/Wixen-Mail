# Phase 13 Plan 44.3: A rule's changes on arriving mail reach the mail server Summary

A rule's Mark as read, Mark as unread, Flag, Unflag and Add a label on arriving mail are
sent to the mail server by the check that brought the message, on its own session, before
the rule files it and before the flags are read back; what cannot go waits or comes back
and is said once with a count; a rule's Delete moves the message to the Trash at the server
through the menu's own delete parts; and a run's label now rides on its move (ledger 748).

## What works now

- **Sent in the check.** `tell_the_server_what_the_rules_changed` in `mail_sync.rs`, called
  once in `sync_folder` after `apply_rules` and before `carry_out_the_moves` and the flag
  read. Only what changed is sent: a mark the message arrived with, or a label with no
  keyword, sends nothing (`what_the_server_is_told`).
- **What cannot go.** `what_the_change_calls_for` reads a failure through
  `flag_changes_waiting::why_the_push_failed` and `what_to_do_about_it`, as a menu mark does.
  A mark or flag waits in `waiting_flag_changes`, which the next check already sends before
  any folder is read; a label comes off again; a refusal is put back. A message whose mark
  waits stays where it arrived, said with `left_where_it_arrived`.
- **The flag read.** Every flag read in `sync_folder` writes a waiting mark over what the
  server said, for that flag only (`flag_changes_waiting::the_flags_to_keep`), so a Mark as
  Read made with mail changes off is no longer undone by the next check either.
- **What is said.** `Told::clauses`, one clause per outcome with its count, in the folder's
  line through `say_what_the_rules_did`; nothing for a success.
- **A rule's Delete.** `carry_out_the_deletes`, after the moves and before the flag read:
  `where_a_deleted_message_goes`, `what_happens_here` (the row into the Trash here and the
  delete kept in the menu's store), `replay_one` on the check's session (the replay's loop
  body moved out), and `undo_here` on a refusal. Unreached, it waits for the next check's
  replay. Already in the Trash, it is left alone; no Trash known, the menu's sentence once.
  POP marks it deleted here, as before.
- **Ledger 748, first half.** `MarksFirst.keywords`, kept in `moves_waiting.keywords_first`
  (an added column), filled by `the_marks_that_go_with_the_move(&labels)`, handed over by
  `label_these` through `handed_to_the_move`, and sent first by the replay's `mark_it`.

What CI and the scan show is in the pull request's checks, read before the merge. No real
mail server has seen any of it: ledger 680 carries the real account for phase 14.
