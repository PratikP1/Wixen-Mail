## Deviations from Plan

**1. [Shape] Seven guard records, not six.** The plan's filed-here break reddens a target case
and a library case, which are two suites, so it is two records. The plan's calendar-only-file
break reddens only the library's PDF case: the Google-shaped invitation's parts are both
calendar parts, so case 1 keeps its files under that break.

**2. [Shape] Task 2's red added the readings and no stubs.** An empty `spawn_parts_fetch` with
no caller is dead code, which clippy with `-D warnings` refuses; the readings fail on their
missing anchors, and the companions prove each can see its violation.

**3. [Shape] The helper takes the store.** `the_whole_message_from_its_own_account` is handed
the opened store, and `the_store_on_this_worker` opens it, because the parts fetch must ask
whether the parts are still left behind before it asks the server.

**4. [Shape] `keep_every_part` replaces with an empty list too**, then clears the bit, so the
body fetch keeps clearing the rows of a re-fetched body that parses to no parts, as it did.

**5. [Rule 1] rustfmt refused the first red commit** on two long lines in the target; `cargo
fmt` and the same commit again.

**6. [Scope] The data module is `mod parts_left_behind;`, private**, like `messages`: its
methods are on `MessageCache` and public, so nothing needs the module's path.
