<objective>
The directory sign-in, held in the credential store, sent only over an
encrypted connection, and a fix for the panic that throws Active
Directory's answers away.

Purpose: GAP-07's LDAP half at the service end: "an LDAP directory with
a bind, its sign-in kept in the credential store". The bind already
works when a password is passed (`directory.rs:611-613`); nothing stores
one and `finding_people.rs` passes `None`. Reading `ldap3`'s open issues
found #156, six days old: the entry parser panics on a search
continuation reference, which Active Directory returns whenever the
search base is the domain root, and the tree's panic catch turns that
into a failed search that discards every real entry. Directories that
need a sign-in are mostly Active Directory, so that is fixed first.

Output: the reference filter, the store functions, the uninstall and
account-removal erasure, the plain-address refusal, the lookup reading
the password, the privacy page's sentence, the changelog and the ledger.
The screen where a person types the sign-in is 13-27's.
</objective>
