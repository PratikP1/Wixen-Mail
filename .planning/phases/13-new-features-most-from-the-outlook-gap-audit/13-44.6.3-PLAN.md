<decisions date="2026-10-02">
- **D1, Pratik's answer:** "yes to moving the plan as well as others." on
  2026-10-02, as 13-44.6.2's D1.
- **D2, the whole process on the desktop, for these five only.** Each
  window test's first line asks `ran_in_a_child_on_a_desktop_of_its_own`.
  In the parent, the first such call starts one child: the same executable,
  no filter, on a desktop made for the run on the current window station,
  its standard output and error written to a file through an inherited
  handle, the environment the parent's plus
  `WIXEN_TESTS_ON_A_DESKTOP_OF_THEIR_OWN` set to the desktop's name; the
  parent waits at most five minutes, then each window test passes only when
  the child's line `test <its name> ... ok` is there. In the child, the
  variable is set, the helper answers false, and the test runs its body
  exactly as today. 13-44.6.2's thread move is not enough here (premise
  1), and a new window station would drop the translated keys these
  readings send (13-44.6.2 premise 4).
- **D3, the station's name is read, not written.** `lpDesktop` is the
  current window station's name, from `GetProcessWindowStation` and
  `GetUserObjectInformationW(UOI_NAME)`, then `\`, then the desktop's: never
  a written `WinSta0`, since CI's runner may sit on another station.
- **D4, what each reading proves is unchanged.** The child runs every test
  body as it is now; no assertion, key or control changes.
- **D5, a failure says which, and asks the lock.** `what_the_child_said`
  turns the child's run into one sentence: the test failed there, quoting
  its own failure block; the child never reported the test, with its exit
  code and the end of its output; or the child was stopped at its
  five-minute bound. Each sentence ends with what Windows says about the
  session lock, asked with the clipboard plan's `this_sessions_lock` when the
  child has ended: locked, unlocked, or not said with what it answered. A
  child that fails is never retried and never skipped.
- **D6, no keyboard question.** Nothing that sends a key runs on the
  interactive desktop after this plan, so no reading asks whether somebody is
  typing: input cannot reach a desktop that is not the input desktop. The
  overrule is to keep a target on the interactive desktop and ask
  `GetLastInputInfo` there before its window session.
- **D7, one turn, renamed for what it guards.** The four targets whose
  window holds a browser take the clipboard plan's turn in the parent,
  before the child starts and until it ends, because WebView2 runs one
  browser per user data folder and the folder is named for the executable,
  so two runs of one executable at once would share a browser even on two
  desktops (ledger 761, 13-44.2's crossing letters). The mutex's name
  becomes `Local\wixen-mail-tests-one-turn-at-what-runs-share` in the paste
  target and in these four, its doc comment naming both uses, since a
  clipboard name on a browser's turn would say something untrue; one
  kernel object, not a second, as the planner was asked: reuse its mutex, invent no other. The marker
  reading's `OneRunAtATime` is removed. every_spin holds no browser and
  takes no turn.
- **D8, the census finishes.** `NOT_YET_IN_A_PROCESS_OF_THEIR_OWN` is
  removed (a constant left empty would iterate over nothing and pass), and a
  rule is added: a file that sends a key and builds a browser, read in code as
  naming `WebView`, `build_compose_dialog` or `show_conversation_as_page`,
  must name `CreateProcessW` and the turn's name constant. A sibling case
  holds the browser list to functions the program has
  (`pub fn build_compose_dialog`, `pub fn show_conversation_as_page` under
  `src/presentation`), and its limit is written beside it: a new way to build
  a browser escapes the list until it is added.
- **D9, the measurement after.** 20 runs of each of the five one after
  another, and 20 rounds of two a_marker runs at once, the second half a
  second after the first, every exit status read directly; with the turn
  the second waits and both pass, and neither page takes in the other's
  letters.
- **D10, nothing spoken or shown changes:** no changelog entry, no push, no
  pull request.
- **D11, discretion taken here:** one copy of the helper per target, the
  tree's practice; the sentence cases only in the tracer's file, since the
  other four copies are held by the census and by each target running green
  in its child; five minutes as the bound, five times the longest run
  measured (the marker's 55 s with somebody at the machine).
