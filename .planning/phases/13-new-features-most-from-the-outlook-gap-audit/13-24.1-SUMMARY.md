# Phase 13 Plan 24.1: One runner for several actions over a set, and a mark sent to the folder it was made in

A settled `filters::Outcome` is carried out over a `Chosen` by one runner,
`run_these_actions_over`, through the quiet do-halves 13-24 made, in the order flags, labels,
phrase said first, then the move or the delete. The bound and each account's gate are met,
and every folder and label the actions name is found in the message's own account, before
anything changes; a missing one refuses the whole run in words. **The runner answers a
`WhatWasDone` and says no sentence of its own.** Its caller says one sentence and gives one
Confirmed signal, `acting_on_a_set::said` being the default wording. Separately, a mark, a star
or a label now goes to the server naming the folder the message was in when the key was
pressed, so a move recorded in between can no longer send it to another message.

**Nothing calls the runner yet.** Its callers to come, each reading the shapes above from this
summary: 13-25 (the block's move into the junk folder, the first caller, closing ledger 685),
13-40 (`quick_steps::what_a_step_did` takes the `WhatWasDone`, or `said`'s words, never a
sentence the runner gives), 13-42 (Quick Steps), 13-43 (its count reads `acting_on_a_set`'s
answer) and 13-44 (a rule run over a folder).

## Deviations from Plan

**1. [Premise] `set_says_first` is the store's method, not a do-half.** The plan lists it
among the do-halves 13-24 made; 13-24 made five and the phrase has none. The runner calls
`cache.set_says_first` per message, in the order the plan gives, and the reading names it.

**2. [Shape] Grouping lives in the pure module.** `acting_on_a_set::the_work` and `TheWork`
were not in the plan's artefact list. The runner "decides nothing acting_on_a_set decides",
and which messages each write takes, each as the step before left it, is a decision; it is
held by two rows there. Without it the star step would have put back the read state (the
do-halves write the other flag as the message was chosen).

**3. [Shape] The runner's refusals include two the plan did not name**: a message in no
account this program knows, and a message in no folder it knows, each before anything changes.
A stop part way, at a write this computer would not keep, answers one fixed sentence; the
reason was already said where the write was refused.

**4. [Rule 3] `#[expect(dead_code)]` on the runner.** Nothing calls it until 13-25, and
clippy runs with `-D warnings`. Expected rather than allowed, with the reason, so it cannot
outlive its cause.

**5. [Rule 3] `moving_through_the_list_marks_nothing_read` rewritten in place.** It read the
timer's call as `mark_what_was_read(app)`; the call now hands the store, so the reading and its
companion snippet name `mark_what_was_read(app, &message_cache)`, with the reason beside them.
No test added or removed there. The wait is still not a parameter, which
`a_setting_saved_applies_without_a_restart` reads.

**6. [Scope] `remember_these_rows_leaving`.** The runner's delete remembers the set's rows the
way the Delete arm does; `remember_the_set_leaving` now shares that body through the new
function, so the move and the delete cannot drift.

**7. [Verification] No behavioural order case, and no push.** The flag goes through
`spawn_server_change`'s worker and the move through `complete_here_then_tell_the_server`'s push;
each opens its own store at `AppPaths` and signs in through `the_session_at`, so neither can be
driven from a target or from `moves_waiting`'s or `flag_changes_waiting`'s own tests against
one scripted server. The readings stand alone, as the plan allowed, and ledger 687 says what a
harness would need. The plan asked for a pull request because the path every mark takes
moved; nothing said or shown changes, so under Pratik's rule of 2026-09-23 the branch was not
pushed and CI and the NVDA run meet it at the phase's close.

**8. [Tooling] Two read-only `sed` and `awk` calls** were made in diagnostic pipelines early
on, against the brief. Neither wrote to a file.

  13-42's Quick Steps that mark and move meet it on every run. Recommendation: the runner hands
