`apply_rules`'s `carry_out` (RESEARCH-4, F2).** `carry_out` writes read
and flag to this computer only; the runner uses `spawn_server_change`

set above `choosing_messages::too_many`'s bound with the count and the
bound, the same number every set command uses.

**3. Folders and labels resolved within the actions' own account
(RESEARCH-4, security domain).** A path is not unique across accounts;
the runner resolves each with the account's own folders and labels.

(planner's choice, recorded).** The flag change is handed the folder
path read when it is asked, so no worker has to finish before the move
is recorded and no key press waits on a network round trip.
