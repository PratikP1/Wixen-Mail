<decisions date="2026-09-29">
- **D1, Pratik's, item 1:** "yes" to "Undo also takes the junk mark off and
  puts the not-junk mark on, through the same permission-checked step". The
  write is `MailController::set_flag`, the gated write the report used, and
  it is sent only where the folder's PERMANENTFLAGS keep the mark, as the
  report sends it.
- **D2, Pratik's, item 2:** "yes" to "block on the message's own account, as
  Report as Junk does per message". The account is `owner_of`'s answer for
  the selected row, the open account only as that rule's own fallback.
- **The planner's, for him to overrule:**
  - **D3. The report's order, reversed.** The mark comes off first, on a
    worker, and the messages move back when it answers, the way the report
    marks first and moves when the mark is settled. So the mark change and
    the move back cannot reach the server in the wrong order, which is the
    race ledger 688 names for marks and moves sent by two workers. Undo of a
    report therefore answers after a round trip rather than at once.
  - **D4. Asked only where a mark may be on.** The report's own answer
    (`Marked`) is kept with the step. Undo asks the server only after
    `Marked::Kept` or `Marked::Failed`, since a failure part way may have
    left some marks set; after `NotKept` or `NotAsked` it moves the messages
    back and sends nothing, so `$NotJunk` never goes on a message the report
    never marked.
  - **D5. The step is "Report as Junk", and Redo is the report again.** The
    Edit menu and the sentence name the step as the menu that did it names
    it. Redo sets the mark again where one may be kept, through
    `mark_as_junk_at_the_server`, then moves the messages to the junk folder
    again; after each Undo or Redo the step keeps the server's latest answer.
  - **D6. The words.** At the key the one word "Undo" or "Redo", as the
    report says "Report", because the sentence waits for the server. After:
    `after_moving_back`'s sentence, then for Undo "The server was told it is
    not junk." or "... they are not junk." when the mark came off, or "The
    junk mark could not be taken off: {reason}." when it did not; for Redo
    only a failure, in the report's own words, "The junk mark could not be
    set: {reason}."; nothing about a mark the server keeps none of or was
    never asked for.
  - **D7. A message nobody can place.** When `owner_of` names no account,
    the block says "This message is not in an account this program knows
    about.", the report's words, and writes nothing.
  - **D8. A second Undo while the worker runs is not blocked.** The mark
    change is the same change twice at the server, and the answer re-reads
    the store for each message, so the second finds them back and says they
    are already there. No new state is added to guard it.
  - **D9. The gate before the worker.** The account's permission to change
    mail is asked at the key, in the words a refused move says; refused, no
    worker starts and the moved step refuses as it does today.
</decisions>
