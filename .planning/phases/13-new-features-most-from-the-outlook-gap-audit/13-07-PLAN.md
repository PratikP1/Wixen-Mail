<objective>
Undo and Redo of a mark, a star or a label on messages, with the
message named, one step, no timer.

Purpose: #47's second level: "Undo for actions on items: the last
delete, move, copy, mark as read or unread, star ... as 'Undo delete'
or 'Undo move' with the item named, for a bounded time or until the
next action; and Redo of that." GAP-02's `[D]` line: "an undo of a
delete, a move and a mark with the item named as its own plan." This
plan takes the marks, the part whose reverse is a flag set back; 13-08
takes moves, deletes and copies; 13-09 the other five modules. The
decision is pure, mirroring how Undo Send is built
(`application::sending_later::what_undo_send_takes_back`), and the
wiring is thin.

Output: `application::undoing`, the list's meaning for Undo in
`application::editing`, the three paths recording, the undo carried
out, the menu naming it, a reading, the pages, the changelog, the
ledger.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a local undo to a mail server | a second write at somebody's provider |
| state recorded before an action | each message's marks held in memory until the next action |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-21 | Tampering | an undo that sets every message to the opposite rather than to its own state | medium | mitigate | the reverse is computed from `Before`; the mixed-set case and a guard record hold it |
| T-13-22 | Tampering | an undo sent when the account forbids changes | high | mitigate | the undo goes through `spawn_server_change` and the controller it calls, which ask `allowed_for(account).mail` before writing (`mail_controller.rs:437`, `:595`, `:851` at `630e2a67`), the same gate as the action it reverses; the executor reads which of those the flag path reaches and quotes it |
| T-13-23 | Repudiation | a refused undo left looking done | medium | mitigate | the refusal path of `spawn_server_change` puts the local state back and says so, unchanged |
| T-13-24 | Denial of service | one sentence per message on a large set | low | mitigate | one sentence per undo; the bound of 5,000 on a set (`too_many`) already applies to the action |
| T-13-SC | Tampering | npm, pip or cargo installs | high | mitigate | nothing is added to the manifest; the summary says so |
</threat_model>
