<objective>
Keys locked with a passphrase: asked for when a message first needs one,
remembered until Wixen Mail closes, never stored.

Purpose: GAP-03's `[D]` line lists "passphrase keys a decision of their
own", and #49 said the same. The research's question 2 recommended asking
when a message first needs the key and remembering it in memory for the
session, as a plan after the manager, "because without it the manager
serves few real keys": most keys people export have a passphrase, and
today they are refused. The recommendation is taken, so this plan is added
to the group's eleven (it is the only one the research did not number).

Output: locked keys imported and listed, the prompt, the reopening, the
fifth reason sentence, the rewritten limits, the pages, the changelog, the
ledger, GAP-03's box.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the person's typed passphrase to the key | a secret that must never be stored |
| a stranger's message to a dialog | a message can make the program ask for a secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-17.1-01 | Information disclosure | the passphrase at rest or in a log | high | mitigate | held as the crate's zeroizing `Password` inside `service::pgp` only; nothing logs it; a grep in the acceptance criteria |
| T-13-17.1-02 | Spoofing | a message making a prompt appear that looks like the program's | medium | mitigate | the prompt appears only on the person's own open in a reader window, names the key from the credential store, never the message's words |
| T-13-17.1-03 | Information disclosure | a decryption oracle through the prompt | medium | accept | the prompt is shown to the person, not the sender; nothing outward depends on it; the advisory's expiry condition is unchanged |
| T-13-17.1-04 | Denial of service | a flood of messages each asking | low | mitigate | a passphrase once given is held for the session; Cancel stops asking for that open |
| T-13-SC | Tampering | npm, pip or cargo installs | high | mitigate | no crate is added; `zeroize` stays indirect |
</threat_model>
