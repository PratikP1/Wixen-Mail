<objective>
Say, before a saved search that reads message text runs, how much of this
account's text is actually here, and say which search that number is about.

Purpose: roadmap criterion 4, and the half of SEARCH-02 that has no gate and no
untested code in it. `02-CONTEXT.md`'s D-2-09 records that this is a live defect
today rather than one this phase introduces: the FTS index has had a `body`
column all along and `run_a_saved_search` already chooses `TheMessageText::Read`,
so a search can already cover a fraction of a mailbox and look complete.

Output: one counting query, one sentence, one wiring, and the comment D-2-13
owes `evict_bodies_over`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored cache database -> counting query | Rows this program wrote, read back for a sentence somebody trusts |
| coverage sentence -> the person reading it | The whole point of this plan: a claim about completeness |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Information Disclosure | A count crossing account boundaries, so one account's coverage is inflated by another's | high | mitigate | The query joins `folders` on `account_id`, and the two-account test fails if that join is removed |
| T-02-08 | Repudiation | A sentence that overstates coverage, so a short result reads as a complete answer | critical | mitigate | The count agrees with `scan_query` on both the account and the deleted conditions, and the sentence names which search it describes rather than implying one number covers both |
| T-02-09 | Denial of Service | An unbounded count on a large mailbox blocking the worker | low | accept | It reads no body bytes and inflates nothing, so it is strictly cheaper than the search it discloses, and it runs on the same `spawn_blocking` worker. A timing is recorded rather than assumed |
