<objective>
Make a saved search keep the whole scope it was saved with: the field
restriction and the folder, written by one path in one write, and described in
one sentence that works for any question set.

Purpose: SEARCH-01, and roadmap criteria 1 and 2. The live search has honoured
all four In box answers since before this milestone; only the saved one loses
half of what it was given.

Output: the In box's answer reaching the function that saves, a narrower
question set, the folder written alongside it, and a sentence built from the
questions rather than from the typed words.
</objective>

<premise_corrections>
**D-2-03 and `02-RESEARCH.md` both size this as "one function, one caller" and
both are describing the consumer only. The input never arrives.** Verified this
session against commit `67d12c5`:

- `src/presentation/wx_app.rs:4515` calls `show_search_dialog` and receives
  `Some((q, looking_in))`. `looking_in` is the `WhereToSearch` the In box was
  set to.
- Three lines later, at `:4521`, only `q` is kept:
  `lock_state(&state).last_mail_search = Some(q.clone())`. `looking_in` is
  passed to the search that runs and then dropped.
- `save_this_search` at `:6491` reads `held.last_mail_search` at `:6505` and
  nothing else about the search. The state field's own doc at `:361-367` says
  what it holds: "What was last typed into the search box while Mail was
  showing."

So `what_a_typed_search_asks` can be given a scope parameter, compile, pass its
unit tests, and go on writing the same three questions for every In box answer,
because the only production caller has no scope to hand it. Task 1 is that
missing link, and it is a real piece of work rather than an incidental. This is
the same shape phase 1 met repeatedly: an artifact with no consumer is waste, a
parameter with no producer is an unplanned feature wearing a signature's
clothes.

**`WhereToSearch::OneFolder` carries a folder row id and `SavedSearch.folder`
holds a path.** `searching.rs:65` declares `OneFolder(i64)`;
`saved_searches.rs:543` declares `folder: Option<String>` and its doc calls it
the folder to look in. `run_a_saved_search` at `wx_app.rs:6316-6324` resolves the
stored path through `cache.get_folder(&account_id, path)` and refuses with
`THAT_FOLDER_IS_NOT_HERE` when it has gone. So the writer must produce a path.
It is available: `selected_folder` has held `WhichRow::Folder { account, path }`
since `01-05`, and `WhichRow::opens()` answers with it.
</premise_corrections>
