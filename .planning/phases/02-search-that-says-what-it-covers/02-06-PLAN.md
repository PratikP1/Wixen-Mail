<objective>
Build the two things a rule editor needs before it can exist: a way to write a
saved search's whole question list back, and a dialog for one condition built
from the engine's own vocabulary.

Purpose: D-2-01 makes a smart folder a saved search with a fuller editor, "one
stored thing, two doors into it". The second door needs a writer for an existing
search's questions, and there is none. It also makes `Join::All` reachable from
outside a test for the first time.

Output: an atomic replace, a condition dialog, and the All join proved end to
end.
</objective>

<premise_corrections>
**Nothing can change a saved search's questions today, and no phase document
says so.** `src/data/message_cache/saved_searches.rs` has exactly four writers:
`create_saved_search` at `:78`, `rename_saved_search` at `:135`,
`delete_saved_search` at `:154` and `clear_saved_searches` at `:168`. A search's
name can be changed and the whole search can be removed; its question list
cannot be edited at all. D-2-01's second door writes "any of the eleven fields
with any match type" into an existing stored search, so it needs a writer that
does not exist. That writer is task 1 and it is the reason this plan sits before
the editor rather than inside it.

**`Join::All` has never executed outside a unit test.** `grep -rn 'SavedSearch {'
src/` gives eight sites, one of them outside a test module, and that one writes
`WHAT_A_TYPED_SEARCH_JOINS_WITH`, which is `Join::Any`
(`src/application/saved_searches.rs:347`). The matcher honours both arms and both
are exercised at `:769` and `:1064`, but only over `selects`, never through
`run_over`, which is where `what_it_cannot_read` is asked first. D-2-01 makes the
All arm reachable for the first time, so task 3 proves it where it will actually
run.
