<objective>
Fix the second vocabulary that already exists in the presentation layer: the
filter rule dialog builds its own field list and its own match list, both shorter
than the engine's, and both by hand.

Purpose: `Question::as_a_rule`'s comment says inventing a second matcher is what
`application::saved_searches` exists to prevent, and D-2-01 depends on that
staying true. Doing this before the rule editor makes the editor a variant of a
correct dialog rather than a second wrong list to keep in step. It also closes
SEARCH-03's "reaching all eleven fields" criterion for the filter path as a side
effect.

Output: spoken words beside the engine's constants, both Choice controls built
from them, a guard that runs the comparison in both directions, and the first
test in this repository that reads the manager dialogs' control names.
</objective>
