<objective>
Take the page off the message list, so a folder shows everything this
computer holds of it and new mail adds rows instead of pushing old ones off
the end. Measure the list's own read path first, at the tester's size and at
200,000 rows, because the figures on the measurements page time a different
query from the one the window runs, and drop the page only against numbers.

Purpose: #24 in the tester's words: "When new messages arrive, older messages
are no longer available in the message list. Only 500 messages are shown."
08-04 showed a list of 200,000 rows costs under half a second to list and
under a millisecond to paint a page, so the bound protects nothing; but its
harness timed `get_messages_for_folder`, and the window reads
`get_message_list_sorted` with a `LIMIT`, then threads and labels the rows on
the interface thread. Those are the costs this plan takes before it changes
anything.

Output: the list unbounded, the labels read by folder, the before and after
rows, one new target coupled to `wx_app.rs`, and the changelog entry. Closes
#24 on the tree side.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the cache to the interface thread | the whole folder is read, threaded and labelled where the window draws; a read that takes seconds is a window that answers no keys for seconds |
| the row count to the query | a parameter per row is a query that fails above a limit nobody set on purpose |
| a measurement to the page | a number written before it is taken is the shape 08-02 built a reading against |
