# Phase 13.2 Plan 31.8: a mailbox file holding more than its archive records, said plainly Summary

A mailbox file inside a zip that holds more than the archive records about it, which zip 9.0.4
stops partway, is now said at import to make the archive damaged or changed after it was made,
with whether any of that file's mail came in, rather than as one message holding nothing a mail
program recognises. The mail before the stop stays, and the archive's other files come in whole.

## What works now

Read from the cases' output, on zips this project's writer made and then gave a smaller
recorded size:

- One mailbox file of 2,000 messages recorded as 100,000 bytes: no folder made, and "No folders
  were imported. 1 mailbox file in the archive does not match what the archive records about
  it, so the archive is damaged or was changed after it was made, and none of that file's mail
  was imported."
- The same beside an honest file of three: "Imported 1 folder, 3 messages." and the same
  sentence; the honest folder holds its three.
- Recorded as 300,000: the altered folder holds 892 of its 2,000 and the honest one its three,
  and "Imported 2 folders, 895 messages. 1 mailbox file in the archive does not match what the
  archive records about it, so the archive is damaged or was changed after it was made. Its
  mail up to the point where it stopped matching was imported, and the rest was left out."
  Before the green this said "1 message in the archive could not be read, because there was
  nothing in it a mail program recognises."
- The plural of each, from `import_tree`'s case: "2 mailbox files in the archive do not match
  what the archive records about them, so the archive is damaged or was changed after it was
  made, and none of their mail was imported." and "... Their mail up to the point where each
  stopped matching was imported, and the rest was left out."

The four sentences were read for an em or en dash, the six words, and the refused words of
`test_everything_this_module_says_is_a_sentence_and_names_no_machinery`, which builds both
new counts into its two literals and passes.

The kind is decided by `std::io::Error::kind()` alone (`message_files.rs`, `read_into`):

```rust
Err(why) => {
    self.stopped_by = Some(why.kind());
```

and classified by the one rule in `mailbox_archive.rs`:

```rust
impl From<std::io::ErrorKind> for WhyAnEntryWasNotRead {
    fn from(kind: std::io::ErrorKind) -> Self {
        match kind {
            std::io::ErrorKind::InvalidData => Self::ItDoesNotMatchWhatTheArchiveRecords,
            _ => Self::ItCouldNotBeRead,
        }
    }
}
```

Every other stop is counted exactly as before: `a_stop_counted` counts it as a stretch holding
no mail, and `one_entry_read_in_pieces`'s answer is still dropped (ledger 908).

## Deviations from Plan

1. **[Rule 3] No `expect(dead_code)` on the staged function.** The plan asked for
   `#[cfg_attr(not(test), expect(dead_code, ...))]` on the red's new function, after
   observation 883. `message_files` is a public module of a library crate, so `dead_code`
   never fires on a `pub fn` there and the expectation would itself be the warning clippy
   refuses. Observation 1060, logged the same day by 13.2-31.7, already records this.
2. **[Shape] The reader's cases live in `mod tests`.** They were first written at the end of
   the file, inside `a_mailbox_larger_than_this_computer_would_hold`, which cannot see
   `an_archive`; moved before the red commit.
3. **[Wording] "is damaged or was changed after it was made"**, 13.2-31.7's words, rather than
   the plan's "was damaged or changed", so the two sentences for one fault agree.
4. **[Shape] The stop is classified inside the closure** handed to `one_entry_read_in_pieces`.
   The archive answers an error when the whole-archive limit is reached, after the reader has
   already met that stop, so classifying the closure's answer outside it would have counted
   that stop nought times where it counted once before. The plan's "the archive refusing
   counts one stretch" would also have counted a refusal to open the entry, which counted
   nothing before; premise 4's "exactly as today" was followed.
5. **[Rule 1] A third guard record touched**, the short folder-made record, found by the
   re-measure.
6. **[Shape] A shared fixture builder**, `mailbox_archive::for_tests::a_zip_recording_these_sizes`,
   beside 13.2-31.7's, so the import's readings build their zips the way the module's own
   lying-size case does.
7. **[Brief] A do-nothing shell assignment named after a banned tool** (`sed_never=0`) was
   typed once in a read-only grep command, the slip 13.2-31.5 and 13.2-31.6 recorded. The tool
   never ran; every tracked file was changed with Edit or Write, by `cargo fmt`, or by
   `scripts/guards.sh`.
8. **[Measurement] 892 rather than 878.** The planner's measurement on a file of 394,670 bytes
   brought in 878; this plan's fixture is a different file of 2,000 messages, and 892 came in.
   The case asserts some and fewer than all, not a number.

No version moved; `git diff main -- Cargo.toml Cargo.lock` is empty. No schema change, no
