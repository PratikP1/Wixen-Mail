# Phase 13.2 Plan 09: The download asks once and reads the folder less Summary

The download of everything now asks for each message's text at most once in an account's run and carries on past one that will not come, a refused chunk of text ends only its own account, and while a folder you have open comes down it is read again at most every ten seconds, its count shown on the status bar and no longer spoken each time.

## What changed

**Finding #11.** `TextAskedThisRun` keeps the message ids an account's run asked text for. The runner creates it beside `text_to_fetch`, passes `messages_with_no_text_here`'s list through `not_yet_asked` before `what_to_do_next`, remembers each chunk after its fetch, and sets `did_anything` from `a_chunk_of_text_did_work(done.fetched)`. The unfiltered count still feeds the progress line and the budget sentence. `Ending::TheServerStoppedAnswering` in the text arm ends with `break;`, keeping `ended = WhyTheRunEnded::AServerStopped`, so the next account runs and the whole run still waits before the next try; the header refusal's `break 'accounts` is unchanged, as the plan said. `mail_sync.rs` and `bodies.rs` were read and not changed.

**Finding #36.** The `MoreOfTheFolderArrived` arm marks the folder through `ReadingTheOpenFolderAgain::a_chunk_landed(folder, on_screen)` and reads nothing. The main timer, after the held-mail block and before the reminders, asks `the_folder_due(Instant::now())` and calls `reread_folder_if_open` with `WhyTheRowsWereRead::AChunkOfTheDownloadLanded`. `MessagesLoaded` carries a `WhyTheRowsWereRead`; `reread_folder_if_open` and `load_folder_messages` hand it through. Both loaded arms set the status text for every reason and announce the count unless the reason is a chunk; the conversations arm repaints a chunk's rows the way it repaints an arrival's. The rows are still cloned out of the update, as premise 4 said.

`git grep -n "reread_folder_if_open(" -- src/presentation/wx_app.rs` names no line in the `MoreOfTheFolderArrived` arm; the reading `test_a_chunk_arriving_rereads_the_folder_and_grows_no_limit` refuses one.

## Deviations from Plan

**1. [Rule 3 - Blocking] More callers than premise 5 counted.** Premise 5 listed the `MessagesLoaded` sites. Each passes the reason it means, as the decisions above say; no test count changed.

**2. [Rule 2] A chunk in a folder not on screen marks nothing.** With one mark, a chunk in another folder would have replaced the open folder's mark and its last chunk would never have been shown, which the plan's own truth ("once more after the last chunk") forbids. `a_chunk_landed` takes the folder on screen; `test_a_chunk_in_a_folder_not_on_screen_marks_nothing` and a record hold it.

**3. [Shape] Two records for the count reading, not one.** The reading covers both loaded arms, and the conversations arm is the default view, so each arm has its own break.

**4.
