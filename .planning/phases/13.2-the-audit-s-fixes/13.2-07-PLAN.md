<objective>
Make Delete and the Trash schedule use the server's declared Trash and
never a person's own folder that happens to be called Bin or Deleted, and
make Empty Folder say a folder was emptied only when the server really
emptied it.

Purpose: finding #9 (reported as R2) and finding #34 (not reported). A
folder's role falls back to its last name at any depth, even when another
folder declares the role, and the folder sorted first wins: "Bin",
"Deleted", "Deleted Items" and "Deleted Messages" all sort before "Trash".
Every Delete then moves mail into somebody's archive folder, Delete inside
it is permanent, and an emptying schedule expunges it at the server with
nobody at the keyboard. Separately, Empty Folder counts any answer that was
not an error as done, so a server that only marked or copied the messages
is reported as emptied. Both are what phase 14's delete sitting proves.

Output: listing-wide roles, Empty Folder reading the outcome, the
corrected comment and changelog line, the ledger, the four marks, and the
pull request.
</objective>

The verdict corrected the audit's account of the order: the cache sorts by
`tree_position(kind, name)` with `name` the leaf, so among Trash-typed
folders "bin", "deleted", "deleted items" and "deleted messages" come
before "trash" at any depth, and a nested "Trash" ties with the real one
and wins on its lower id. The verdict also found the audit understated the
harm: "When Wixen Mail closes" empties on the first close
(`emptying_the_trash.rs:821-846`).

**2. The audit's fix was not enough, and the verdict's has a hole this
plan closes.** Depth alone leaves a top-level "Bin" beside a declared
"Trash". The verdict's "attributes only when any folder declares one"
would type INBOX as an ordinary folder on every server that declares
`\Trash` but not `\Inbox`, and Gmail and Dovecot list INBOX with no role
attribute; RFC 3501 reserves the name INBOX, case-insensitive, for the
primary mailbox. So the rule is per role: a role any folder in the listing
declares is taken from declarations alone; a role nobody declares falls
back to the name, for a folder at the top level or directly under INBOX;
when two such names suggest one role, the first in that role's list in
`from_name` wins; INBOX is the inbox by name always. That needs the whole
listing, so it lives in `special_use` as a function over the listing, and
`classify` stays as that function over a listing of one so the cases at
`imap.rs:2677-2700` keep their meaning. `test_only_the_last_segment_of_a_path_is_matched`
(`special_use.rs:190`) changes as the verdict says: `INBOX.Sent` stays
Sent, `[Gmail]/Sent Mail` with no attributes becomes ordinary (Gmail always
declares its folders).
