# Phase 13.2 Plan 27: An all-users uninstall says what it left Summary

Uninstalling works again. Since 2026-08-27 every uninstall, per-user and all-users alike,
stopped at an error before removing anything, because `CurUninstallStepChanged` ran the
Windows Search clean-up through `ExecAsOriginalUser`, which Inno refuses while uninstalling.
It now runs through `Exec`. And an uninstall for all users now tells the person which Windows
account's data it cleared and that any other account keeps its own (audit finding #43).

## What changed

**Task 1, the forbidden call** (red `97e4cb9e`, green `eb916235`). Inno 6.7.3 is the version
`find_iscc` finds on this machine. The reading
`test_no_uninstall_step_calls_what_inno_refuses_while_uninstalling` follows the uninstall
event functions through the script's own routines and finds `ExecAsOriginalUser` in none of
them; its companion sees a direct call, a call through a helper, and leaves a name in a
comment or a message alone. A throwaway setup built with ISCC 6.7.3 stopped with an internal
error at uninstall before removing a file, and the same setup with `Exec` uninstalled cleanly.
So the erase step never ran either on any build since 2026-08-27. One guard record.

**Task 2, the message** (red `87aa41b4`, green `87cc5d64`). In admin install mode with the
program present, `CurUninstallStepChanged` shows, as a person reads it:

> This uninstall clears the mail, settings and saved sign-ins that Wixen Mail kept for the
> Windows account NAME, the account it is running as.
>
> If Wixen Mail was used under any other Windows account on this computer, that account still
> has its own copy:
>
> Its mail and settings are in %LOCALAPPDATA%\wixen-mail, or in the folder that account told
> Wixen Mail to use. The downloaded mail in that folder is not encrypted.
>
> Its saved passwords and sign-in tokens are in Credential Manager, under Windows Credentials,
> in entries whose names begin with wixen-mail.
>
> To remove them, sign in to Windows as that account. Paste %LOCALAPPDATA%\wixen-mail into
> File Explorer and delete that folder, then open Credential Manager and remove those entries.
>
> Windows Search may also still be set to read that account's mail. While signed in as that
> account, press the Windows key, type Indexing Options, choose Modify, and untick the Wixen
> Mail location.

The last paragraph appears only when the uninstall key's `Inno Setup: Selected Tasks` names
`searchindex`. The comments over `[UninstallRun]`, `[UninstallDelete]` and
`TheProgramIsAlreadyGone` now quote Inno's help, read 2026-10-18 in 6.7.3:
`runascurrentuser` means "the spawned process will inherit Setup/Uninstall's user
credentials", and `{localappdata}` is "the current user's" folder where "The "user" constants
refer to the profile of the user running Setup". `git show HEAD:installer/Wixen-Mail-Setup.iss
| grep -c 'runascurrentuser is the part that matters'` answers 0, against 1 on `main`. One
guard record, measured by hand and by `scripts/guards.sh`: the one named test went red and
nothing else did. The eight records naming `tests/installer.rs` were re-measured at 28.

`cargo test --test installer`: 28 passed. `cargo test --test the_words_that_say_nothing`: 10
passed. The script compiles with `ISCC.exe /Q /O- /DAppVersion=... /DVersionInfo=...`, exit 0.

**Task 3, the documents.** Two changelog entries under Fixed, one per defect; the first says
an older copy needs a new build installed over it before it can be uninstalled, since its
uninstaller is the old one. `docs/installing.md`, `docs/privacy.md` and `docs/architecture.md`
said uninstalling removes everything, or runs the erase "as the user"; each now says it
clears the account the uninstaller runs as, and the first two say an older copy needs a new
build installed over it. Ledgers 895 and 896, `unrun-verify`, both halves.
