# Phase 13.2 Plan 11: Changes kept from offline go to their own message, and an older flag change no longer undoes a newer one Summary

A read or star that reaches the server now ends any older change to the same message still waiting, and a move, delete, copy, crossing or read or star kept from offline goes, after the server renumbers its folder, only to the one message carrying exactly its Message-ID, or is put back here and said.

## What changed

**Finding #2 (task 1).** `spawn_server_change` takes the time it was asked before its worker starts, and its `Ok(())` arm, for Read and Flagged, calls `stop_waiting_for_what_came_before(row, flag, asked_at)`, which reads the kept change's time with `chrono` rather than comparing text. The flag replay lets go with `stop_waiting_for_this_change(change)`, by message, flag, value and time, so a change kept while the replay waited on the server stays. `stop_waiting_to_send_a_flag_change` had no other caller and went: four lines in `src` before, none after.

**Finding #5, moves (task 2).** `moves_waiting.uid_validity`, through `ensure_column_exists`, filled from the source folder's stored `folders.uid_validity` on the first keep and kept when a later ask replaces the row. `application::renumbered` holds the decision: no numbering kept or the folder unchanged, the kept number; changed, the one number the Message-ID is under; none, several or no identifier, put back. `replay_one` asks it before `send_the_marks_first`; a waiting crossing asks it before its fetch and source removal. `ReplaysAMove` and `TheAccountItIsLeaving` gained `numbering_of`, answered by `MailController` with `select_folder(..).uid_validity`.

**Finding #5, flags (task 3).** `waiting_flag_changes.uid_validity` the same way; `keep_a_flag_change_waiting` fills it from the folder's numbering on the first keep and keeps it on a later one. `send_the_flag_changes_that_were_waiting` asks each folder's numbering once per replay (`the_numbering_now`), asks the decision per change and sends to the number it answers. A change it cannot place is answered by `the_number_to_offer_it_at` as an `InPlainWords` refusal carrying `THE_FOLDER_WAS_RENUMBERED`, so it is put back, stops waiting and is counted in the existing sentence; a folder that could not be asked goes on waiting.

**The exact match (orchestrator's addition).** `HEADER MESSAGE-ID` matches a header containing the text asked for (RFC 3501, 6.4.4). `the_number_to_send_to` now takes a fourth argument, `the_identifier_at`, called only for the one number the search answered, and `the_number_confirmed` sends there only when that message's identifier equals the kept one after `bare` sets aside surrounding space and one pair of angle brackets. `ReplaysAMove::the_identifier_at` (six implementors), `MailController::message_id_at`, the crossing's `the_identifier_held_at` over `the_headers_of`, and `the_identifier_among` reading a header fetch's answer. The reading of the flag replay now also requires `message_id_at(` before the send, with a planted companion that trusts the search unread.
