# Phase 13.2 Plan 03.1: The message keys work in an opened conversation Summary

Inside an opened conversation, the message list's keys for Reply, Reply All, Reply to Sender
Only, Forward, Star, Move to, Report as Junk, the nine labels, Remove every label and the
first three Quick Steps now act on the message under the cursor, and a message read from the
conversation is marked read after the wait. Pratik's fourth report of 2026-10-14, the half
13.2-03 left: "or other commands that can act on a message within the thread".

## What was done

- **Task 1, the keys.** `TreeKey` holds the key code, what is held (`Held { control, alt,
  shift }`), how the page writes it and the command. The message keys are one table,
  `THE_MESSAGE_KEYS`, one `("written", ID_NAME),` per line: 13.2-03's Delete, Shift+Del and M,
  and Ctrl+R, Ctrl+Shift+R, Alt+Shift+R, Ctrl+L, Ctrl+Shift+S, Ctrl+Shift+V, Ctrl+Shift+J and
  Ctrl+0. `THE_TREES_KEYS` is that table read for each key's code and modifiers by
  `pressed_as`, then Ctrl+1 to Ctrl+9 from `tagging::key_for` and `label_id_at`, and
  Ctrl+Shift+7 to Ctrl+Shift+9 from `quick_steps::key_for` and `quick_step_id_at`, 23 keys.
  `the_key_pressed` matches the code and exactly the modifiers held; Alt+Shift+R arrives as a
  system key with Alt down and is found the same way. The one handler 13.2-03 bound reads
  them, so each reaches the Act arm and the main window's dispatch with `acting_on` set.
  Reply to Sender Only joins the commands that do not bring the conversation back. The
  keyboard page's Conversations table names every key, with a line saying they are the list's
  keys and act on the message under the cursor.
- **Task 2, the mark.** `WxUIState::what_reading_may_mark` answers the message whose reading
  began when it is the cursor row's unread message, an unread member of the row's
  conversation among the loaded rows (same account and conversation id), or the row's own
  message when the loaded rows do not hold it; nothing for another conversation or a row the
  cursor has left. `mark_what_was_read` asks it above the rule's call, which with the
  function's first two lines is byte for byte as before, and when the loaded rows do not hold
  the message reads its number and subject from the store through `the_stored_message`,
  leaving it alone when the store says it is read. The write is the one it was:
  `MessageReadToggled`, whose arm writes the store and catches the conversation row up
  (13.2-02), and the server change.
- **Task 3.** The changelog's Fixed entry, ledger 841, LIST-05's and LIST-03's dated lines
  and traceability rows, the four marks, and pull request 172.

## Deviations from Plan

1. **[Rule 3] Three ids are crate-visible only.** The plan's cases expect `ID_LABEL_1`, the
   first Quick Step's id and `ID_REPLY_SENDER` in an integration target, which compiles against
   the public surface; `command_for` reaches Reply, Reply All, Forward, Star and Move but none
   of these. `label_id_at` and `quick_step_id_at` became public in the red commit and the label
   and Quick Step cases expect their answers. Reply to Sender Only's expected id is the tree
   list's line for Alt+Shift+R, which the source comparison pairs with `ID_REPLY_SENDER` and the
   main window's "Reply to Sender &Only\tAlt+Shift+R". Observation 1013.
2. **[Shape] The key list changed shape, and two records moved with it.** The plan had the
   numbered keys "built from their places"; a `const` array of `&'static str` cannot hold
   `Ctrl+1` built from a place, so `THE_TREES_KEYS` is a `LazyLock<Vec<TreeKey>>` and `written`
   a `String`. Each key's code and modifiers are read from how it is written, so the table has
   one line per key the source comparison can read. `the_key_pressed` no longer goes through
   `list_keys::is_a_bare_press_of`; the rule is the same, exact modifiers. The two Delete
   records were rewritten and re-measured, as above.
3. **[Shape] The comparison reads keys, not strings.** The menu writes Delete as `Del` and the
   page as `Delete`, and Mark as Read has no menu key because the list binds `M` itself
   (`wire_letter(&msg_list, 'M'`), so the comparison reads both sides as modifiers and a key,
   and names M as the list's own letter with the line that binds it. It also asks the running
   list for every line and every numbered place, and checks the numbered commands against
   `label_id_at` and `quick_step_id_at`.
4. **[Shape] The "comes back" case reads the whole list.** Rather than naming ids for the
   labels, junk and Quick Steps, it asserts that every key except the four that open a window
   brings the conversation back, and that the list holds 23 keys.
5. **[Order] The first red commit was refused by clippy** (`borrow_deref_ref` in the comes-back
   case, written to compile against both shapes of `written`); the case was rewritten over
   commands and the commit made again.
6. **[Shape] A message filed elsewhere is checked for read in the store, not the state.** The
   state cannot see its read flag, so `what_reading_may_mark` answers it and the timer reads
   the store; the plan put the unread condition on the answer.
7. **[Shape] The page's case was not taken red separately.** The page and the keys went in one
   commit, as the plan says; the reading's planted companion from 13.2-03 shows it sees a key
   left out.
8. **[Tooling] The page's numbered keys are written one by one** (`Ctrl+1`, `Ctrl+2`, ...),
   because the page reading looks for each key in backticks.
