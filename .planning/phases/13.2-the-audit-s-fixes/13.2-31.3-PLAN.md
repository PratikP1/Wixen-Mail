<objective>
Make the Outbox folder's own Delete refuse a message a pass of the send loop has
already claimed, with a sentence saying it is being sent, the way Undo Send has
refused one since 13.2-04.

Purpose: 13.2-04 made the send loop claim each message before it sends it, and made
Undo Send's delete refuse a claimed row. The Outbox's Delete, `cancel_queued`, was left
as the audit's verdict said, so it still takes out a message a pass holds and says
"Taken out of the outbox. It will not be sent." while the pass goes on and sends it.
That is ledger 843, and Pratik answered yes to its recommendation on 2026-10-15. A
sentence that says a message will not be sent while it goes to a stranger is the worst
kind of wrong answer this program can give.

Output: the store's answer, the window saying it once, Undo Send's sentence corrected,
the cases and the reading, the changelog, ledger 843 closed and a row for the ear, the
four marks, and the pull request.
</objective>

**2. How the store tells "being sent" from "not there".** A claimed row has
`sending_since` set (`outbox.rs:428-440`), and a failed send lets go of it in the
statement that counts the failure (`:412-424`). `cancel_queued` takes the row out only
when no pass holds it, and when nothing came out it asks once whether a row with that
rowid is still there: there, it is being sent; not there, it is gone. Between the two
statements a pass can let go of a failed claim, and the answer is then "being sent"
about a message that is back in the queue; the next Delete takes it out. The other order
cannot happen: a claim is never taken on a row that is gone. The rowid is handed in
negative from the list and turned with `abs()` (`:371-378`), which stays.
