# Phase 13.2 Plan 31.9: An unreadable settings file is kept and said Summary

A settings file, or an account's settings file, that cannot be read is copied to a name of its
own before anything touches it, the settings file is replaced by settings that allow no change
at any server, start-up says so once on the status line after the first-run question, and
Settings refuses to open over settings it could not read.

## What works now

- `ConfigManager::keep_what_cannot_be_read` reads `app_config.json` and every `account_*.json`
  through `settings_in` and `account_in`, the same readers `load` uses. A file that does not
  read has its bytes written to `<name>.unreadable-<UTC date and time>`, then `-2`, `-3` and on,
  opened with `create_new` and synced. Then the settings file is replaced through
  `save_app_config`, so through `written_whole` and its lock, by `AppConfig::default()` with
  `allowed_changes` set to `Allowed::NOTHING` and `told_about_the_alpha` false; an account file
  is removed. A file whose bytes cannot be read or copied is left as it is. Every outcome comes
  back as `WhatWasKept`.
- `main` calls it once through `unreadable_settings::keep_at_start_up`, after the log starts and
  after the hand-over decision, before `WxMailApp::new`, logs each file, and hands the value to
  `run`.
- `run` says the sentence through `send_status` inside the `scan_target.is_none()` block, right
  after `ask_about_the_alpha_once`.
- `handle_settings` reads with `load_stored`; on an error it logs, says the refusal through
  `send_status`, and returns `None`. `git grep -n "showing defaults" -- src/presentation/wx_app.rs`
  exits 1.
- `git grep -c "ONE_SAVE_AT_A_TIME" -- src/data/config.rs` answers 2, as before.

The sentences, quoted from their cases:

- Settings kept: "Your settings could not be read, so Wixen Mail started with fresh ones and
  asked again what it may change. The old settings were kept as
  app_config.json.unreadable-2026-10-19-140322 in {folder}."
- One account file kept: "The settings file for an account could not be read, so it was set
  aside and your other settings were read as usual. It was kept as
  account_acc-1.json.unreadable-2026-10-19-140322 in {folder}."
- Several: "2 settings files for accounts could not be read, so they were set aside and your
  other settings were read as usual. They were kept in {folder} as account_a.json.unreadable-1
  and account_b.json.unreadable-1."
- Both, account part: "The settings file for an account could not be read either, and was kept
  as account_a.json.unreadable-1 in the same folder."
- Not kept: "Your settings file, app_config.json, could not be read or set aside, so it was left
  as it is in {folder}. Until it can be read, Wixen Mail sends no mail and changes nothing at
  your mail servers, and Settings will not open."
- Settings: "Settings did not open, because your stored settings could not be read. They were
  left as they are, so nothing was written over them."

Each was read for an em or en dash (a case holds that) and for the six words; none has any.

## Deviations from Plan

1. **[Rule 1] The stamp is `%Y-%m-%d-%H%M%S`.** The first green used `%Y%m%d-%H%M%S`, and
   `test_only_the_calendar_document_writer_builds_a_day_in_the_calendar_format` refused it.
2. **[Rule 1] A doc comment and a guard comment reworded.** The first wording said the plain
   defaults "allow changes at every server"; the code's answer for a fresh profile is mail
   false, tasks, contacts and calendars true, and
   `test_nothing_says_a_new_installation_changes_nothing_while_it_changes_contacts` refused both
   sentences. Both now say what a fresh profile allows.
3. **[Rule 3] No `expect(dead_code)` on the red's new items**, as 13.2-31.8 found: they are
   public in a library crate, so `dead_code` never fires on them.
4. **[Shape] `keep_at_start_up` lives in `application::unreadable_settings`**, so the real-path
   case can call what `main` calls; `main` adds only the logging.
5. **[Shape] `and_taken_away`** is shared by `written_whole` and the keeping, replacing the
   closure `written_whole` held. No record anchors on those lines.
6. **[Shape] `WhatWasKept` derives `Default`**, for the stub and for `main`'s fallback when the
   settings folder cannot be found.
7. **[Measurement] The re-measure ran with `WIXEN_MAIL_DATA` set** to an empty folder, as ledger
   890 recommends, so no measurement read Pratik's profile. Ledger 890 stays open: the tool
   still does not set it by itself.
8. **[Cases] Three cases passed in their red and were not named**: sound settings left exactly as
