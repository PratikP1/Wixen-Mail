# Phase 13.2 Plan 07: The declared Trash and what Empty Folder did Summary

Delete and the Trash schedule use the folder the server declares as its Trash, a person's own Bin or Deleted stays their folder, and Empty Folder stops at a message the server only marked or copied instead of saying the folder was emptied.

## What changed

**Finding #9.** `special_use::roles_of_the_listing` decides every role over the whole LIST answer. INBOX is the inbox by its name, as RFC 3501 reserves it. A role any mailbox declares comes from declarations alone. A role nobody declares falls back to the name, and only for a mailbox at the top level or directly under INBOX; where two names suggest one role the earlier in that role's list wins ("trash" before "bin"), then the earlier listed. `classify` is that function over a listing of one, so the cases in `imap.rs` keep their meaning. `list_folders` decodes the paths, asks the listing-wide function once, and builds each folder from its answer; the closure that builds it kept its indentation, so the two guard anchors in it still name one place each.

**Finding #34.** `server_delete::the_message_left_the_folder` answers over all five `Deletion` endings with no wildcard: `Removed` and `MovedToTrash` left; `MarkedOnly`, `CopiedToTrashAndFlagged` and `CopiedToTrashAndNotFlagged` did not, and carry the deletion's own spoken words. The loop in `spawn_the_folder_empty` turns each delete's answer through it and stops the folder on a message that stayed exactly as on a refusal, with `uids.len() - done` counting that message among those not removed. The comment promising a second run finishes the job is corrected by dating.
