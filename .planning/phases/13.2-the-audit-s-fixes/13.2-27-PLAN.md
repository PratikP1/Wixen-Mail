**1. The erase runs as the uninstaller.**

```
git show main:installer/Wixen-Mail-Setup.iss | grep -n 'Parameters: "--erase-all-data"'   -> :602, flags `runhidden waituntilterminated runascurrentuser skipifdoesntexist`
```

Inno's help, `jrsoftware.org/ishelp/topic_runsection.htm`, read
2026-10-14: `runascurrentuser` means "the spawned process will inherit
Setup/Uninstall's user credentials" and "This is the default behavior when
the postinstall flag is not used"; `runasoriginaluser` is "Valid only in a
[Run] section". Commit `d6fe9361` (2026-07-28) shows the compiler refused
`runasoriginaluser` there and the other flag was taken as its spelling. The
comment at :443-446 already says where `{localappdata}` lands "has not been
measured"; the help settles it for the erase, and the executor reads the
constants topic for `{localappdata}` and quotes it.

**2. Found here, not in the audit: an uninstall step calls a function Inno forbids at uninstall.**

```
git show main:installer/Wixen-Mail-Setup.iss | grep -n 'ExecAsOriginalUser(Tool'   -> :513, inside CurUninstallStepChanged (:474-533), running `remove-scope`
git show main:installer/Wixen-Mail-Setup.iss | grep -n 'wixen-mail-search-setup.exe"; DestDir'   -> :180, installed with no task condition, so FileExists(Tool) at :505 is true on every uninstall and :513 is reached every time
```

Inno's help, `jrsoftware.org/ishelp/topic_isxfunc_execasoriginaluser.htm`,
read 2026-10-14: "This function is not supported at uninstall time." Inno's
source, `Projects/Src/Setup.ScriptFunc.pas` on `jrsoftware/issrc` main, read
the same day: `if IsUninstaller and RunAsOriginalUser then
NoUninstallFuncError(OrgName);`, which raises. So every uninstall raises at
:513, and `unregister-classes` (:519) and the leftovers message (:524-532)
are never reached. The executor reads the same function in the Inno version
the build uses (`ISCC.exe /?` prints it; `scripts/build-installer.sh`'s
`find_iscc` finds it) and quotes the lines, and reads what an exception in
`CurUninstallStepChanged` shows a person, before trusting this premise. The
two install-time calls (:339, :361) run from `PrepareToInstall` and are
supported.

The search task is offered only in admin install mode (:147,
`Check: IsAdminInstallMode`) and `add-scope` runs as the original user at
install (:217). At uninstall, `Exec` runs `remove-scope` as the uninstaller:
the person in the usual case where they consent to their own elevation, the
administrator in the borrowed-password case, which the new message names.
