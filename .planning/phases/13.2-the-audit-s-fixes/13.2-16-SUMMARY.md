# Phase 13.2 Plan 16: Saved files carry the Mark of the Web, and the update check needs this project's certificate profile

What Wixen Mail saves from a stranger's message is now marked as coming from the internet, and the update check no longer accepts an installer on the strength of a name anybody who shares it can buy.

## What works now

- **Finding #22, commit `09289994`.** `fetch_and_write_attachment`, which both Save Attachment commands reach, and `one_message_saved_to`, which File, Save As reaches, call `attachment_name::mark_as_from_the_internet` after `std::fs::write`. It writes `[ZoneTransfer]`, `ZoneId=3` to `path:Zone.Identifier`. On an error each logs "A saved attachment (or message) could not be marked as from the internet: {why}", naming neither the file nor the message, and reports the save as before. `git grep -n -i 'Zone.Identifier' -- src` names the function, its constant and doc, and its case, and nothing else.
- **Finding #24, commit `2d1cc52e`.** `whether_that_signer_is_ours(who, profile)`: a blank name is `NothingSignedIt`, another name is `SomebodyElseSignedIt` whatever its usages, and our name is accepted only when `who.usages` holds `profile` as a whole value; an empty `profile` refuses. `verify` passes `THE_CERTIFICATE_PROFILE_IT_SIGNS_WITH`, empty, whose comment quotes Microsoft's page and says what recreating the profile does. The new sentence: "The update Wixen Mail downloaded carries the name Pratik Patel but was not signed with this project's own certificate, so Wixen Mail will not run it. Anyone named Pratik Patel can get a certificate in that name, which is why the certificate itself is checked. The file has been deleted. Nothing on this computer has changed. You can download a version yourself from {page}." Nobody hears it today: no release is signed, so every installer is still refused as unsigned first.
- Microsoft's page on Artifact Signing certificate management, `ms.date` 2026-09-30, `updated_at` 2026-10-01, fetched 2026-10-16 with `curl`: certificates "are renewed daily and are valid for only 72 hours"; the profile's usage "is associated with the certificate profile, not with the subscriber or identity validation resource"; "If you delete the certificate profile and create a new one, Artifact Signing assigns a new EKU to the new profile." It also says every Public Trust certificate carries `1.3.6.1.4.1.311.97.1.0`, which the cases use as a usage every Artifact Signing certificate has, whoever's profile issued it.
- Windows itself, `Get-AuthenticodeSignature` on 2026-10-16: all four System32 candidates are Valid, Authenticode, and carry `1.3.6.1.5.5.7.3.3` beside Microsoft's own usages (`showdesktop.exe` `1.3.6.1.4.1.311.61.6.1`; `MpSigStub.exe` `.10.3.21`; `MRT.exe` `.10.3.21` and `.10.3.6`; `appverif.exe` `.10.3.20`). The new Windows case reads code signing and more than one usage off the first one present.
- `CertGetEnhancedKeyUsage` is under `Win32_Security_Cryptography`, already enabled in `Cargo.toml`; nothing was added (T-13.2-13-SC).

Counts taken 2026-10-16 on the branch: `cargo test --lib service::attachment_name::` 14 passed; `cargo test --test a_saved_file_carries_the_mark_of_the_web` 3 passed; `cargo test --lib service::update_download::` 47 passed, the Windows cases included.
