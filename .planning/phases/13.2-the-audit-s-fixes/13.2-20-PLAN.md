tick, a due-window completion, a move, a note edit, or a deletion of
something whose create is in flight. Today each push clears the waiting
flag without asking whether the row is still the one it sent, so the change
is never sent or is wiped on this computer. And make the notes editor's
Save mark the note waiting at all, which it never did.

"should", its tasks and notes half. Pratik's request of 2026-10-14 is every
item that needs fixing. The verdict corrected the finding in four places
(premise 5); this plan works from the verdict, plus two gaps found while
re-reading its premise: the notes editor's Save never marks a note
waiting, and the note move, like the task move, marks a row waiting
without stamping it. The events half of #1 is 13.2-20.1, split from this
plan on 2026-10-14 at the plan check's request, so that each plan fits one
executor with its guard re-measurement.

winning), which #1 is; and PIM-04 (notes synced rather than left here), for
the editor's Save, since an edit to a note a backend already holds is today
never sent. A dated line under each, no `[D]` clause, no box touched.
