tree, by asking which copies are there and removing exactly those, so no second entry point is
left that could take the copy just filed. The POP readers that read one folder, whose short
names were the scope that brings deleted POP mail back, are gone, and only the account-wide ones
remain. The scale harness no longer times a folder read no user path took. Nothing a person
does, sees or hears changed.

## Deviations from Plan

1. **[Rule 1] `is_connected` moved, not attributed in place.** Given `#[cfg(test)]` where it
   stood, it became the first `#[cfg(test)]` in `mail_controller.rs`, and
   `application::sent_copy::tests::test_the_one_thing_here_that_reaches_a_server_is_still_behind_the_gate`
   reads the file up to that marker as the production half. It counted one gate opener of two
   and failed; the task 2 re-measure's whole-library baseline reported it as "already failing".
   The method now sits in a `#[cfg(test)] impl MailController` placed after the production code,
   just above the test module. So the plan's acceptance
   `git grep -n -B1 "pub(crate) async fn is_connected"` shows the doc comment's last line above
   it, and the `#[cfg(test)]` stands on the `impl` three lines up. The six re-measured records'
   verdicts were taken with this test excluded as already failing; none of them names it, and
   the move changes no break they make.
2. **[Plan] The harness header does not name the deleted function.** Task 3's acceptance grep
   over `src tests` and its instruction to correct the header by dating could not both hold
   while the dated sentence named it. `6c4a7b61` words it as "an unsorted folder read on
   `MessageCache`" and leaves the name to the measurements page, whose rows carry it.
3. **[Counts] Re-taken.** `bodies.rs` held 52 tests and 14 records named it, not 50 and 13; the
   harness record was re-measured as well, since its red test's message changed. The
   `update_download.rs` and `house_style.rs` line numbers had moved, as noted above.
4. **[Note] The census exercises `remove_these`'s gate and no longer `uids_with_message_id`'s.**
   Before, the census reached the search's gate through the wrapper. The plan chose
   `remove_these(&[4])` alone so its gate's removal reddens the census, which it does. The
   search's gate now has no closed-gate case in `imap.rs`; it guards a read, so what is lost is
   the wording of a refusal, not a change reaching the server.
