# Phase 13.2 Plan 12: Markup nested too deep to walk is read as its words alone Summary

A message nested more than 512 elements deep no longer overflows the window's stack when selected or the worker's when its HTML-only body is saved: one iterative check after each of the three parses that feed a recursive walker reads such markup as its words alone, and the text reader says one sentence before them.

## What changed

**Task 1.** `common::how_deep_markup_nests::nests_deeper_than` walks `traverse()`, counting element opens and closes, and stops at the first element past the limit. It is called right after the parse in three places and nowhere else (`git grep -n 'nests_deeper_than' -- src` names those three, the definition and test helpers): `hidden_text::drop_what_the_sender_hid` returns the markup unchanged and 0; `HtmlToText::convert` reads the text nodes through `the_words_alone`, one line each, sets `read_the_words_alone`, and returns true; `long_text::read_markup` gives the same words as paragraphs with a warning in the log naming no subject, sender or body. `the_words_alone` skips text under `head`, `title`, `style`, `script`, `noscript`, `template`, `iframe`, `object` and `embed`, with a counter rather than an ancestor walk. table_text is unchanged: its one caller is past the converter's check. html_to_text.rs's "Local changes" header names the check.

**Task 2.** `body_text` puts "This message's layout is nested too deeply to show as a page, so only its words follow." before the words when the converter fell back, before the signature landmark is placed. The audit's message, 4,000 nested divs, is previewed (as divs and inside an `h1`) and saved HTML-only, each on a 1 MiB thread, each in a process of its own.

**Task 3.** The parse's own cost timed in a release build and ledgered (857); the changelog's Fixed entry with the cost as a known limitation.

## Deviations from Plan

**1. [Rule 2, a test that would notice] The regression cases run in a process of their own.** The plan had them on a 1 MiB thread in the test program, proven red only by a crash with the fix taken out. Every guard record whose break disables the check would then crash the whole library run, and nothing would be measured. So each inner case is `#[ignore]`d with its reason and a companion runs it as a child of the same test binary with `--exact --ignored`, failing on a non-zero exit or a missing `1 passed`. With the check taken out the companions failed as tests, exit 101, and the run went on.

**2. [Shape] `the_words_alone` lives in the helper module.** The plan's artifacts named only `nests_deeper_than` and the constant; the converter and the reader both need the iterative words, and one reader of them keeps the two from drifting.

**3. [Rule 1] Five records found short by task 2's re-measure.** Two by an artefact of deviation 1: the companion's failure message echoed the child's `test <name> ... FAILED` line, which the runner read as a second failing case. The companion now leaves those lines out, and the snippet record gains the save companion. Three were stale before this plan, each by tests in files they never named, which the count check cannot see: "the shape the person chose decides the picture" by `wx_pgp_keys`'s dates case since 13-36.1 (`9774c35e`); "an opened envelope hands back what windows wrote, not the buffer it sized" by four sending and sent-copy cases in `protecting.rs`, `smtp.rs` and `signed_mail/sending.rs`; "an opened pgp/mime message is its words" by one `smtp.rs` case.

**4. [Process] The check was taken out by one edit, not three.** Task 2 asked for the three calls to be put back as they were; making `nests_deeper_than` never answer yes leaves all three walking exactly as before and is one edit to undo.

**5. [Tooling] The release probe.** The first two builds failed: `LNK1104` under the long scratchpad target path, then wxdragon-sys resolving past the pinned version without the project's lock file. The third, with `Cargo.lock` copied into the probe and the project's `target` directory, ran. Nothing in the tree changed.

**6. [Clippy] The first red commit was refused once** in 16 s for an unused import of `Edge` in the stub; removed and committed.
