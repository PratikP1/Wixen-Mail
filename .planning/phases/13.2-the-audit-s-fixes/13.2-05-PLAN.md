<objective>
Take a sent message's draft out of the Drafts folder, here and at the
server, and stop Undo Send's too-late path filing a copy of a message that
has gone.

autosave files a copy in the account's Drafts folder, on the server for

may send again. The changelog says this was fixed; it was fixed for the
Open Draft list alone. Phase 14's sittings would show it on the first
real send.

Output: the two removers and their cases, the Send arm and Undo Send
wired to them, the corrected changelog, the ledger entry for the tester's

**3. The race the verdict names, and how it is closed.** An autosave's
append runs on its own session in `spawn_draft_append`, and can still be in
flight when Send is pressed. A removal that searches first would miss that
copy, which then lands after. The verdict offers "say so" or "search again
after a delay"; neither removes the copy for certain. This plan holds one
lock, `one_filing_at_a_time`, across every filing and every removal at a
server, so a removal searches only after every filing that began before it
has ended. Nothing files a draft after Send for that draft: the composer
has closed.

**4. Undo Send's too-late path.** Today `undo_send` saves the draft and
files a copy (`:24329`, through `save_as_draft`), then deletes the queue
row (`:24337`); on `Ok(false)` or an error it deletes the drafts row and
leaves the copy (`:24339-24352`). The verdict's fix is a reorder, not a
removal afterwards: save the drafts row, delete the queue row, and file the
copy only on `Ok(true)`. Since 13.2-04, `delete_outbox_message` answers
false for a row a pass has claimed, so `Ok(true)` now means the message was
really caught.
