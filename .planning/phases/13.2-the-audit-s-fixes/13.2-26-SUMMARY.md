# Phase 13.2 Plan 26: The gate reaches every guard Summary

A commit or merge changing a file now runs the library tests of every guard record that
breaks it, in whatever module those tests live, and a change to `build.rs` earns every check.

## What changed

**Task 1, finding #38.** `scripts/check.sh` reads the registry once into three arrays,
`record_files`, `record_suites` and `record_reds`, through `read_the_records_in`, which both
`--suites-for` and the new `the_modules_that_guard_what_changed` use. The scan reads a red
list in both its forms, skips the inside of `"""` and `'''` strings, and is fed by `grep -o`
pieces split in memory. `the_scoped_runs` adds one `--lib <module>:: -- --test-threads=4`
line for each module holding a red test of a suite-less record whose `file` changed, unless
a module already run holds it. `--records-in` prints the arrays for a hand comparison.

Checked on 2026-10-18:

  suite or red name.
- `--suites-for` asked about each of the 302 files the registry names, before and after:
  identical.

## Deviations from Plan

**1. [Rule 2] The scan skips multi-line strings, and `--suites-for` shares it.** The plan
asked that lines inside a `before` or `after` text that look like a red list are not read;
a flag between `red = [` and `]` alone cannot promise that, so the scan tracks `"""` and
`'''` strings. Sharing it with `--suites-for` closes the limit its comment used to name, a
break text holding a column-0 `file = ` line. Its answers were compared before and after.

**2. [Rule 1] Whole lines through `mapfile` were too slow.** The first green read whole lines
and took the check suite from 60 to 146 seconds, because `mapfile` reads a byte at a time
here and the delimiter lines hold 824 KB. `grep -o` pieces split in memory, read into arrays
rather than printed and read back, brought one scan to about half a second, as before, and
the suite to 73 seconds with its eight new cases.

**3. [Plan] Only the cases that fail were named in each red.** Three `check` cases (own
module, a record with a suite, a name with no module) and two `which-checks` cases (on
`main`, the toolchain file) hold today's behaviour, so `red-commit.sh` would refuse them.

**4. [Plan] An eighth `check` case pins the acceptance line** against the real registry, the
way the manager window's case does.

**5. [Plan] STATE's plan number is 28, not 26.** As 13.2-23 to 13.2-25 record, it counts the
plans done; `completed_plans` moved from 284 to 285.

**6. [Plan] The ledger kind is `unmet-truth`**: each row is a claim in CLAUDE.md that a guard
runs on the commits that could break it, which did not hold.

No changelog entry: nothing a person using the program sees changes. No pull request:
nothing spoken or shown changed. Nothing installed. No guard record names the four scripts;
CLAUDE.md's one record anchors far from the lines added.
