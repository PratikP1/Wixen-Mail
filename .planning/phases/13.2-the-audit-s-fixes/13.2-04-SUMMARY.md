# Phase 13.2 Plan 04: The Outbox claims a message before it sends it Summary

A pass of the send loop now claims each ready message with one conditional UPDATE before it
counts or sends, so two passes, a pass and Undo Send, or two copies of the program cannot both
have one message: no message is sent twice (finding #31), and Undo Send says "Too late to take
that back" rather than "Taken back" about a message on its way (finding #6).

## What was done

- **Task 1, the store.** `outbox_queue.sending_since TEXT`, nullable, through
  `ensure_column_exists` with a comment saying what a claim is and why opening the database
  never clears one. `claim_for_sending(id, at)` is `UPDATE ... SET sending_since = ?2 WHERE id
  = ?1 AND sending_since IS NULL`, true when a row changed. `delete_outbox_message`, Undo
  Send's, gains `AND sending_since IS NULL`; its doc says the claim is what tells Undo it lost,
  and dates the old claim. `a_sent_message_leaves_the_queue` deletes by id whatever the claim,
  the send loop's alone. `update_outbox_failure` sets `sending_since = NULL` in the statement
  that counts. `let_go_of_every_claim` frees every claim and answers how many.
  `outbox_messages_that_may_go_now` and `cancel_queued` are unchanged.
- **Task 2, the loop and the start.** `flush_outbox` claims each ready row after every
  account's queue is read and before the count is said, keeping the rows whose claim answered
  true; a refused claim is passed over with `continue`, and a claim that errors is logged with
  the account's name and passed over, never an early return. Read rows with none claimed say
  "The Outbox is already being sent." and end the pass where the empty queue ends it. A sent
  row leaves through `a_sent_message_leaves_the_queue`, keeping the sentence for its failure;
  a failure that cannot be recorded is now logged rather than dropped with `let _ =`, because
  the claim would then hold the message until the next start. `main.rs` turns the running
  marker's answer into `ThisCopy`, which `WxMailApp::new` takes; it lets go of every claim and
  logs the count only on `ThisCopy::Alone`. Comments corrected by dating: Undo Send's order
  comment and its too-late branch in `wx_app.rs`, the handover comment in `main.rs`.
- **Task 3.** The changelog's Fixed entry, ledger 842 and 843 in both halves with the header
  counts, FOUND-04's dated line and traceability row, the four marks, and pull request 173.

## Deviations from Plan

1. **[Shape] Seven cases, not six.** The plan's behaviour lists six lines and its example
   names cover five of them twice over; `a_sent_message_leaves_the_queue` had no case, so
   `test_a_sent_message_leaves_the_queue_although_its_pass_claimed_it` was added. The count is
   35, not the plan's 34.
2. **[Rule 3] `ThisCopy` lives in `src/application/running.rs`,** a file the plan did not list,
   beside the `Claim` it is read from; `main.rs` sets it in the match it already had, so
   `running.rs` gains a type and no behaviour.
3. **[Rule 2] A failure to record a failed send is logged.** It was `let _ =`; with the claim it
   now holds the message until the next start, so dropping it silently would leave a message
   stuck with nothing said anywhere.
4. **[Shape] `sending_later.rs` is unchanged.** Its doc at `:493-509` does not repeat the false
   claim; it says nothing about what the delete proves.
5. **[Order] The first red commit was refused by rustfmt**; formatted with `cargo fmt` and made
   again.
6. **[Tooling] Records named library tests by bare name at first.** The guard runner matches a
   library test by its module path; the first re-measure reported them as never run, the names
   were corrected, and a second call for the two records came back exact. That is two
   re-measure calls in task 1 where the brief asks for one.
7. **[Scope] Ledger 843 opened** for a question the plan did not raise: the Outbox's own
   Delete still takes out a message a pass holds and says it was cancelled. Left as the
   verdict said, with a recommendation for Pratik.
