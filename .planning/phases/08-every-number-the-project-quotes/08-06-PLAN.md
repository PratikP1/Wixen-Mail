So the awk agrees with the reader for the three hot files and for every
file no inline-table record names. It undercounts only for files the four
inline-table records name, by at most one each, and today that is one
file, `wx_send_later.rs`, answering 0 against 1. The research's mechanism
stands: the inline record's line is consumed by `next` before its file is
read, and the flag it sets stays set until a later bare `]`. That
`attaching.rs` and `answered_meetings.rs` come out level is the flag
leaking into the following record's lines, which is a wrong reading that
lands on the right number, stated here as an inference from the code and
not re-derived per record. The finding is smaller than the first draft
said and the correction is the same: a line reader for a structured file
is right for the spelling the file happens to use, and the reader replaces
it. The paragraph that introduces the awk is right about the grep and
wrong about its own remedy, and the correction keeps the grep half.
