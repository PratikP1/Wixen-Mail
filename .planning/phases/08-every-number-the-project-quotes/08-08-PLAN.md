<premise_corrections>
Taken 2026-09-14 against `main` at `b14d6379`, version `0.124.0`.

**1. The count is 12,335 and the tool shards.**

```
cargo mutants --version                  -> cargo-mutants 27.1.0
cargo mutants --list | wc -l             -> 12335
cargo mutants --list-files | wc -l       -> 247
cargo mutants --help | grep -n 'shard\|baseline\|in-place'
-> --shard k/n; --sharding round-robin|slice; --baseline; --in-place
```

`--shard` divides the list the tool builds from the tree it runs in. Two
shards from two commits are two lists, and a mutant can fall between them
or appear in both. So every shard runs at one commit, in a worktree, and
the merger refuses shards whose recorded commit differs.

**2. `scripts/mutants.sh` writes one output directory and cannot pass
arguments through.** `:69-70`: `OUT="target/mutants"`, fixed; `:75-100`:
three modes, none takes `--shard`, and nothing after the mode reaches
`cargo mutants`. `scripts/mutants_report.py:283-303`: `read_run` reads one
directory. Both change.

**3. The rate has to be measured, and there are two candidates.** `cargo
mutants` runs `cargo test` for the package per mutant: every target at
the harness default thread count. Arguments after `--` go to `cargo test`
and after a second `--` to the test binary, so `-- --lib -- --test-threads=8`
runs only the library at eight threads. From 08-01's suite rows, read as
an inference: about 29 s to rebuild plus the suite figure, per mutant.
With every target that is minutes; with the library at eight threads it
is nearer a minute and a half. Over 12,335 mutants the two differ by
weeks, so both are measured on one shard and both products go to the
person.

**Each shard pays a copy and a build from nothing, and that cost scales
with the shard count, not the mutant count.** By default `cargo mutants`
copies the source tree to a scratch directory without `target/` and builds
it there before its baseline, so every `--shard` invocation starts with a
full build, about five minutes at `CLAUDE.md`'s worktree figure. With `n`
near 500 that is up to about 40 hours over the run, about 12 s per mutant
folded into the rate if it were spread, and it is paid whichever suite
shape is chosen. Two ways to stop paying it, both in `cargo mutants
--help` today: `--in-place`, which mutates the source tree it is run in
rather than a copy, and is safe here because the worktree is dedicated,
at one commit, and holds nothing else; and `--copy-target true`, which
copies `target/` into the scratch directory so the build there is
incremental. Task 1 measures the shard's timing with and without
`--in-place` and the rate rows say which was used; the launcher passes
whichever the rows justify, and `--in-place` is the recommendation because
the worktree exists for exactly this. `--baseline skip` on later shards
changes the mix too: the first shard's baseline is a full build plus a
suite run, and skipping it later removes a build from each shard but
also removes the check that the tree is green before the shard starts,
which is acceptable only because the tree does not change between shards
and the first shard proved it. The timing line and the product rows
state the shard count, the copy setting and the baseline setting beside
the figure, so the rate is a rate under named conditions.

**4. One job, still.** `scripts/mutants.sh:60-68`: workers collide on
Windows at `-j 2` and above, cargo-mutants 27.1.0. `MUTANTS_JOBS` stays
at 1 unless a new version is measured to fix it. Sharding is the unit of
resumption, not parallelism; two shards at once on this machine contend the
way `CLAUDE.md` measured for worktrees.

**5. The four refusals still apply and extend to a merge.**
`why_this_is_not_an_answer` refuses a baseline that failed, mutants filed
unviable whose compiler never started, a run in which the suite never ran
against a mutant, and a partial run. A merge of shards is partial if any
shard is, and the merger says which.

**6. Where the tests are.** `scripts/mutants_report.py`'s worked examples
are run and counted by `tests/house_style.rs::test_the_mutation_report_
still_obeys_its_own_examples`, in the tree-reading list; a commit touching
the script on a branch runs it. `scripts/mutants.sh` is reached by
`test_no_mutation_result_is_read_from_the_lists_written_for_people` and
`test_no_mutation_run_has_its_failure_swallowed`, which read it as text.
The summary names all three.

**7. The run may outlast the phase.** If the person chooses the whole
tree at either rate, the shards run for days to weeks of machine time
across idle periods. 08-09 closes the phase on whatever has completed and
says plainly what has not; nothing here waits for the run to finish before
the rest of the phase can close.
