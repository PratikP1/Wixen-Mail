<premise_corrections>
Taken 2026-09-14 against `main` at `b14d6379`, version `0.124.0`.

**1. The runner has no resume and writes nothing back on a plain run.**
`scripts/guards.py:947-990` lists its flags: a name filter, `--touched-by`,
`--named-only`, `--remeasure`, `--recount-everything`. None resumes. The loop
at `:1109-1140` prints `-- <name>` before each record, flushed, and
`say_what_it_found` prints one of five verdict shapes after; a `Wrong`
prints a message and the name goes to `slipped`. So the log already holds
what a resume needs, and the parser is a reading of the log's own lines.

**2. A killed run can leave a break in the tree.** `measure` at `:811-866`
writes the broken bytes and restores them in a `finally`. A `KeyboardInterrupt`
reaches the `finally`; a process-tree kill, a power cut or a closed terminal
that takes the process with it may not. The runner's own docstring says it
"never changes anything through git" and reads git in one place,
`files_changed_since`. A second read, `git status --porcelain -- <the
guarded files>`, before a resume starts, is the check that a break was not
left behind, and it refuses naming the file rather than measuring over it.

**3. "Nothing else may be building while it runs" is a sentence, not a
check.** `scripts/guards.sh:41-43` records that a commit hook running the
suite during a sweep reported three guards green that go red on their own.
Nothing in the runner looks. `tasklist /FI "IMAGENAME eq cargo.exe"` and
the same for `rustc.exe` answer in about a tenth of a second, and a wait
before each record turns the sentence into a condition.

**4. The count and the rate are on the page.** 08-01 wrote the product row
as 783 times today's rate; the runner also prints a timing line per record
since 08-01, so the log of this sweep is its own rate series. Whatever the
page says on the day is what the checkpoint tells the person, and the wall
time measured goes beside it afterwards.

**5. The sweep needs a tree that does not move for its whole length.** A
commit to `src/` during the sweep changes what a break reddens, and the
hook running the suite during one is premise 3's finding. `git worktree add
../wixen-mail-sweep <commit>` gives a checkout that `main` cannot disturb,
with its own `target/`; `CLAUDE.md` measured one worker's worktree at about
a five-minute build and 8 to 9 GB. The sweep runs there, from that
worktree's own `scripts/guards.sh`, and the corrections land on `main`
afterwards. Only records 08-07's own task 3 touches can differ between the
two trees, because no plan runs beside this one.

**6. Where the tests are.** `scripts/guards.py`'s worked examples are run
and counted by `tests/house_style.rs::test_the_guard_runner_still_obeys_
its_own_examples`, which is in `guards_that_read_the_whole_tree`, so a
commit touching the script on a branch runs it. That is the test that
reaches this script, and the summary says so, because `which-checks.sh`
maps `scripts/*.py` to no target of its own.

**7. The log's line endings.** Python translates `\n` on a redirected
stdout on Windows, so the log will hold carriage returns. Nothing reads a
`.log` under `.planning/` for carriage returns (`tests/house_style.rs`
walks `.planning` for `md` only), so the log is kept as written; measure it
with `tr -cd '\r' | wc -c` and say what it holds rather than converting it.
</premise_corrections>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a killed run to the working tree | a break left behind is a source change nobody made on purpose |
| another build to the measurement | a hook or a build running beside the sweep changes what a break reddens |
| a partial log to a conclusion | a log read before the run exits has already produced a wrong commit message here |
| the worktree to main | corrections apply to a tree that may have moved since the sweep's commit |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-28 | Tampering | a break left in the tree by a hard kill | critical | mitigate | `--resume` runs `git status --porcelain` over every guarded file first and refuses naming any that is modified; the checkpoint tells the person the `git checkout` that cleans it. |
| T-08-29 | Tampering | a build running beside the sweep | high | mitigate | `--wait-until-quiet` polls for `cargo.exe` and `rustc.exe` before each record; the sweep runs in a worktree `main`'s hook cannot touch. |
| T-08-30 | Repudiation | verdicts read from a partial log | high | mitigate | the checkpoint forbids reading before the final summary line; task 3 reads the complete log and copies it into the phase directory. |
| T-08-31 | Denial of service | the resume parser misreading a verdict shape and skipping an unmeasured record | medium | mitigate | `verdicts_in` has a worked example per verdict shape and treats a name with no verdict as unmeasured; the shapes are held by `say_what_it_found`'s own examples. |
