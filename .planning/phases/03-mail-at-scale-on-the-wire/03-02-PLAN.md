<objective>
Count the sites that build a `MailController` and connect without going through
`a_session_at`, in a test, so the number stops being a list of line numbers in a
requirements document that has now been wrong twice.

argument for it is the requirement's own history. It named eight sites at eight

against the old list would have been wrong twice over: wrong about which sites,
and wrong by half about how many.

Output: one census, its companion, one guard record coupling it to the file it
watches, and a corrected number in `REQUIREMENTS.md` that a test now holds.

<premise_corrections>
**1. Twelve, not eight, and the eight are not merely stale, they are wrong.**
Measured 2026-09-03 and recorded in both `03-RESEARCH.md` and the corrected
`SCALE-02` text: the connect sites in `src/presentation/wx_app.rs` are at 7555,
8124, 8405, 8627, 8803, 16289, 16450, 17509, 18249, 18350, 18439 and 18713. The
earlier list (11504, 11818, 11978, 12454, 13007, 13747, 13812, 14086) names
lines that are not connect sites now. `a_session_at`
(`src/application/mail_session.rs:21`) has three production callers:
`deleting_at_the_server.rs:112`, `sent_copy.rs:245`, `wx_app.rs:13485`.

**2. Do not write the twelve line numbers into the test.** That would rebuild
the exact artefact whose staleness is the reason for the test. The census
counts occurrences of a shape, and the only number it holds is the total, with
the date it was measured beside it.

**3. The census lives in `tests/`, and that makes a `guards/guards.toml` record
mandatory rather than optional.** `scripts/check.sh` runs an integration target
when its own file changes, or when `guards/guards.toml` couples it to a changed
source module. Without a record, a thirteenth bypass added to `wx_app.rs` would
not run this census at all until a merge to `main`. `CLAUDE.md` names that
failure directly: a guard with no record is a guard that runs on every commit
except the ones that matter.

**4. `tests/` rather than a unit test in `wx_app.rs`, and rather than
`tests/wired.rs`.** A unit test inside `src/presentation/wx_app.rs` would be
reached by `--lib presentation::wx_app::` only when that file changes, which is
in fact the right coupling here, but adding tests to that file flags sixty-one
guard records on the count check every time. `tests/wired.rs` is named by eleven
records and would flag those. A new file is named by none, so it flags nothing
of its own, and the one record this task adds is the only bookkeeping it costs.
That is the whole of the reason and it follows the precedent
`02.1-03-PLAN.md` set when it chose `tests/docs_links.rs` over
`tests/house_style.rs`.

**5. This plan changes no behaviour, so nothing here needs a changelog entry.**
It is listed in `files_modified` only in case the census turns up a site doing
something user-visibly wrong, which would be reported rather than fixed here.

**6. This is decision-independent.** None of the four open questions changes it,
and it is cheap. It is placed before 03-06 because 03-06 is the plan that makes
the number fall, and a census written afterwards could only assert whatever the
new code happened to do.
</premise_corrections>
