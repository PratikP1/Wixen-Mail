<premise_corrections>
**1. This plan rests on an assumption Pratik has not confirmed.**
`03-RESEARCH.md` asks whether the `offline_mode` false promise should be fixed
now as a small separate change or folded into SCALE-05. **This plan assumes it is
fixed within this phase, as task 1**, on the grounds that it is a live defect in
a shipped build and the rest of SCALE-05 is meaningless without it: detection
that switches on a mode which does nothing is detection that does nothing. If
Pratik would rather ship the fix on its own before this phase reaches here, task
1 lifts out cleanly and the rest of the plan still stands.

**2. Criterion 5's last clause is currently satisfied by accident, and this plan
can break it.** `flush_outbox` (`wx_app.rs:15883`) has exactly one caller, the
menu item at `:4877`, so the outbox is never flushed unasked because it is never
flushed automatically at all. Wiring "the network came back" straight to it would
send mail nobody asked to send. That is guardrail 7: publishing happens on
purpose, never as a side effect. The deliverable is an offer, and the offer is
the work.

**3. The outbox itself is complete and must not be rebuilt.**
`queue_outbox_message` (`outbox.rs:38`), `outbox_messages_that_may_go_now`
(`:95`), `when_a_queued_message_may_go` (`:112`), `cancel_queued` (`:256`) and
`update_outbox_failure` (`:287`) all exist. `flush_outbox` already asks only for
messages that may go now, so undo-send holds and scheduled sends are respected
(`wx_app.rs:15925-15935`). The work is a decision that reads offline, not a
second queue.

**4. There is no network detection of any kind.** The requirement's own grep over
five likely names returns nothing. The `windows` crate is already a dependency
(`Cargo.toml:215-229`) with a named feature list, so this is a feature added to a
crate already present rather than a new package, and the package legitimacy gate
does not apply. Say that in the summary rather than leaving it to be assumed.

**5. Windows-first, and detection is one of the things that is Windows-only.**
`CLAUDE.md` requires platform-specific code behind `#[cfg(target_os = "windows")]`
with a fallback that keeps the crate building. The fallback must answer something
honest. Answering "online" on a platform with no detection is the safe answer,
because it leaves behaviour exactly as it is today rather than putting somebody
into an offline mode nothing will bring them out of, and the comment must say
that is why.

**6. Announced once, not per failed request, is the hard part.** A mailbox sync
with several folders and a watch loop produces many failures from one network
loss. The announcement has to be about the state changing, not about a request
failing. Guardrail 5 is the rule: feedback must be distinct and bounded.

**7. Sixty-one guard records name `wx_app.rs`.** The count check fires on every
RED commit that adds a test there.
</premise_corrections>
