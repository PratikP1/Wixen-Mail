<objective>
Put the cursor on the next message after a delete, or on the previous one
when the last was deleted, on the control and not only in the state, and
keep it on the same message when the folder is re-read.

Purpose: #76, the tester on 2026-09-18 under NVDA on `744d05ef`: deleting
a message puts the cursor at the top of the list. The rule he asks for is
already written in `take_row_out_of_the_list`, which sets
`selected_message_index` to the next row or the previous; nothing sets the
control's own focused and selected item to it after the count changes, so
the control reads as the top. And since 10-06 our own expunge wakes the
watch, whose re-read replaces the rows without re-selecting by design, so
the surviving index may sit on a different message.

Output: the rule as a module, the two arms, the reading over a built list,
the changelog entry. Closes #76 on the tree side; that NVDA reads the
landed row once is his ear's. In front of 11-07 because that plan reworks
the same function for a set and lands the cursor after the set through
this rule.
</objective>

since 10-06 it follows every delete on an IMAP account.**

```
sed -n 17482,17497p src/presentation/wx_app.rs   -> MessagesLoaded: "the selection is deliberately not touched, because re-selecting would move focus and take the screen reader's cursor with it"; only ensure_visible under the setting
```

The design holds for a load that changes nothing under the cursor; it
does not hold for a load after a removal, where the same index is a
different message. The fix keeps the rule and narrows it: the cursor's
message is remembered by id before the rows are replaced, its new index
found after, and focus and selection set only when that index differs
from the old one, so a load that moved nothing moves nothing.
