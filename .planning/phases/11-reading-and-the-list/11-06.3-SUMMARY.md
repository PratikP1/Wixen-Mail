# Phase 11 Plan 06.3: The gate's suites leave the repository that runs them alone Summary

**A shell suite the commit hook runs can no longer act on the repository that runs it.
`scripts/shell-suite.sh`, which every suite sources first, unsets `GIT_DIR`,
`GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_PREFIX` and `GIT_COMMON_DIR` right after
`set -uo pipefail`, so a suite that builds a repository of its own with `git -C` builds it
there whatever a hook handed it. Two cases in `scripts/which-checks.test.sh` are red if that
stops, each starting a fresh `bash` that sources the harness with one variable handed in and
the other four absent, the way the hook hands a suite its environment, and asking a
throwaway repository named `elsewhere` whether it moved. Both were red in the shape of
their incident: under an absolute `GIT_DIR` the fixture's commit landed on `elsewhere`'s
HEAD and replaced its hooks path; under an exported `GIT_INDEX_FILE` the fixture wrote to
the handed index and the subject answered `all`. After the green the suite ran under this
repository's own absolute git dir, and again under an absolute copy of its index, to exit 0
with HEAD, the config checksum and the reflog length unchanged. No commit was made from a
linked worktree, so that whole path is proven by its parts and not end to end. Closes #85;
ledger 536 fixed; FOUND-19 ticked.**
