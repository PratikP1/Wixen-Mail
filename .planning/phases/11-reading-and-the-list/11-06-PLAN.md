**3. A plain letter on a native list is taken by the control's own search
unless the key-down is consumed.**

```
sed -n 9985,10000p src/presentation/wx_app.rs   -> wire_read_aloud binds KEY_DOWN on the list and skips in every path, "so the list keeps its own use of Space"
grep -n 'skip(false)' src/presentation/wx_app.rs   -> nothing: no key on any list is consumed today
grep -n 'skip(false)' src/presentation/wx_item_form.rs   -> 594: the one place this tree refuses a key, and its header at :73 says "event.skip(false) is what makes the refusal real"
sed -n 375,385p ~/.cargo/registry/src/*/wxdragon-sys-0.9.17/cpp/src/event.cpp   -> DispatchEvent calls event.Skip(true) before every closure and treats the event as consumed only if (!event.GetSkipped())
grep -n 'pub fn skip' ~/.cargo/registry/src/*/wxdragon-0.9.17/src/event/mod.rs   -> 595: pub fn skip(&self, skip: bool)
```

A `SysListView32` in report view jumps to the next row whose first column
begins with a typed letter, on the `WM_CHAR` that follows the key-down.
wxWidgets does not hand the `WM_CHAR` to the control when the `KEY_DOWN`
event was handled and not skipped (`m_lastKeydownProcessed` in
`src/msw/window.cpp`), which is what makes M consumable. Under wxdragon
"not skipped" is not the same as "did not call skip": the dispatcher
resets `Skip(true)` before every closure (`event.cpp:379`), so a closure
that says nothing leaves the event skipped and the `WM_CHAR` reaches the
search. The handler therefore calls `event.skip(false)` for a bare M (no
Ctrl, Alt or Shift), which is how `wx_item_form.rs:594` already refuses a
key, and leaves every other key skipped as today. Two `KEY_DOWN` closures
on the one list (Space's and this) are fine: the dispatcher runs them in
binding order and stops at the first that cleared skip. The issue asks
that this be shown on a real list and not only in a test that calls the
handler, so the reading in task 2 builds a `ListCtrl` with rows "Alpha",
"Mango" and "Zulu", selects row 0, sends `WM_KEYDOWN` for M followed by
`WM_CHAR` for m the way the message loop would, and asserts the handler
ran once and the selection stayed on row 0.
