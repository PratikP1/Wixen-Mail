## The probe's finding, with its mechanism

The tester, 2026-09-18: "Enter on a message and Enter on a link both open in the same
window; the link does not go to the default browser." Against it, two handlers meant to
veto every navigation and hand the address to the browser: the preview's `on_navigating`
and the page window's, one function apart, each guarded by `!url.is_empty()` so the
control loading its own document was not vetoed.

Read, not watched. `wxWebViewEvent` keeps an event's address in `m_url`, read by
`GetURL()`, and its constructor never sets the command event's string
(`target/debug/wxWidgets/include/wx/webview.h:412-418`). `HandleNavigationStarting` builds
the event with the address in that slot and nothing else
(`src/msw/webview_edge.cpp:595-599`). wxdragon 0.9.17's `WebViewEventData::get_string`
reads `wxd_CommandEvent_GetString`, which is `wxCommandEvent::GetString()`
(`wxdragon-sys-0.9.17/cpp/src/event.cpp:791-800`), and neither crate exposes `GetURL`. So
`event.get_string()` answers `Some("")` for every navigating event, the guard reads the
empty string as the control's own load, and the veto is skipped: for a mouse click, for
Enter on a focused link, for NVDA's Enter, on both surfaces, since 2026-07. A script message
is the one event wx writes the string for (`webview_edge.cpp:809`), which is why the
context menu and the way out worked beside a veto that never did.

Measured, then: the target's live half builds a browser control in a child process, sets a
page with one anchor to `https://nothing.invalid/where-it-went`, clicks it from script once
the page has loaded, and records every navigating event after the load. Three runs of three
on 2026-09-20, under a second each: **one navigating event after the load, carrying
`Some("")` and int 1, the main frame; and the control went on to follow the link**, which
is what the tester heard. The test holds those three facts, so the day wxdragon carries the
address is the day the veto could route again, and the test says so.

So the route does not depend on the veto. `page_links::SCRIPT` catches a `click` on an
anchor, which is what a mouse click, Enter on a focused link and a screen reader's Enter in
browse mode all arrive as, calls `preventDefault`, and posts the address; the window routes
it. The vetoes stay as a second line keyed on what the event does carry, whether it is the
main frame's and whether the window asked for a load, and stop what the listener did not
catch, logging it, since there is no address to route.
