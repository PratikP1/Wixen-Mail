# Phase 11 Plan 08.1: A conversation is Gmail's own, and a late parent joins it Summary

**On a Gmail account a conversation here is now the conversation Gmail shows. `X-GM-THRID`
is asked for with each message's other details where the server advertises the extension,
read into `ImapMessage::gmail_thread_id`, stored as `messages.server_thread_id` and made the
conversation's name, spelled `gm:<id>` so a stored name says where it came from; the server's
word wins over whatever the `References` chain says, a name the server gave is never rewritten
by a merge, and a message Gmail files apart from its siblings is its own conversation. Mail
already stored gets its word once, at the next check of the account, after the moves that were
waiting are replayed and before the folder list is asked for, by one `UID FETCH` of the stored
numbers for the one field per kept folder, recorded per account when every folder answered.

sibling with a fuller chain and a reply naming only its parent; what was wrong, and is fixed,

Message-ID while the conversation row carried the stored name, and the conversation window
looked a row's members up by comparing the two, so it found them only when the root happened
to sort first and on Gmail's names never would have. The loaded page is now grouped and named
as the store groups and names it. Subject matching stays off. Nobody has seen the tester's
split threads become one; #88 is closed from the merge with the ear list.**
