<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the log file to whoever reads it | a line written for a report is a line that may be pasted into a public issue |
| the log filter to the crates beneath | a target switched on for a library logs what that library chooses, which for an IMAP crate at debug is the literals on the wire |
| the version string to the default | a string somebody else built decides how much is written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-15 | Information disclosure | a report line carrying a body, a subject or a secret | high | mitigate | every new line names accounts, folders, counts, levels and clauses; the source guard over every `tracing::` call under `src/`; held-back content logged by length |
| T-11-16 | Information disclosure | a library target switched on at debug | high | mitigate | `filter_for` names one target and its test refuses a second; the environment override is unchanged and documented |
| T-11-17 | Denial of service | a chunk line per chunk filling a disk | low | mitigate | chunk lines at debug; the cost measured and on the page; the level one setting away |
| T-11-18 | Tampering | a version string that parse refuses | low | mitigate | `is_alpha_or_beta` answers false for anything unparsed, so the default is the quieter one |
| T-11-SC | Tampering | npm, pip or cargo installs | high | mitigate | no crate is added to `Cargo.toml`; the summary says so |
</threat_model>
