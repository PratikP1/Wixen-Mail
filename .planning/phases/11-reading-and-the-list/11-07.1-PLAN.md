<objective>
A move completes here first and the server is brought into line
afterwards; Enter on a folder in the Move dialog is the Move.

Purpose: #86, the tester on 2026-09-18 under NVDA against Gmail on
`7573a812`: a move takes a noticeable time before the row leaves and the
sentence comes, because the move is done at the server first and the
list changes only when the server has agreed (`spawn_folder_move`, "the
row goes once the server has agreed and not before"); and Enter on the
chosen folder in the Move dialog does nothing, because nothing binds the
tree's activation and no button is the default. The design chose the
server's agreement over speed for a reason the delete arm states: a
"deleted" that another device contradicts is the wrong nobody finds
until it matters. This plan keeps what that guarded and moves the wait:
the change is made here at once and recorded as not yet at the server,
the server is told in the background and at the next check, a refusal
undoes it here and is said, and a restart replays it. The shape is the
one `application::flag_changes_waiting` and the outbox already have.

Output: the waiting table, the decisions with cases against the scripted
loopback servers, the sync replaying first and forgetting nothing a
waiting move holds, the move and delete arms, the undo, the dialog's
Enter, the readings, the pages and the changelog. Closes #86 on the tree
side. After 11-07, which reworks the commands over a set and whose
delete of a set this changes, and before 11-08. This changes when the
server is asked, so #63's move, copy and delete proofs against a real
account are re-taken after it, and the close comment says so.
