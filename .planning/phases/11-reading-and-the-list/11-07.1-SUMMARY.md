# Phase 11 Plan 07.1: A move, a delete or a copy completes here first, and Enter in the Move dialog is the move Summary

**A move, a delete or a copy of a message within one account now happens on this computer
first. The row leaves the list the moment the folder is chosen or Delete is pressed, the
cursor lands on the next message by 11-06.1's rule, "Moved to Archive: subject" is shown on
the status bar and spoken by nothing, and the change is written to a `moves_waiting` table as
made here and not yet at the server, one row per message keeping the folder and number the
server still has the message under. The server is told once in the background on the
account's held session, and again at every path that lists a folder, the check and the
download, before the first listing, so a restart replays it and a check does not bring the
message back; a server that could not be reached ends that account's check rather than
listing over a change it has not heard of. What the old design guarded is kept by the record
and the undo: a refusal comes back as `MovePutBack`, whose arm puts the row back where the
server holds it and speaks the reason at High; a refusal for a message already where the
move wanted it is read as done. A copy takes the same shape on Pratik's word of the day, its
line spoken as the answer to the key since its row stays. Enter on a folder in the Move
dialog is the move, bound on the tree's activation after a built tree said Enter on a
collapsed parent raises the activation and expands nothing. A move across accounts stays
server-first; 11-07.2 makes it complete here first. Nobody has heard a row leave at once, and
no real server has replayed a move.**
