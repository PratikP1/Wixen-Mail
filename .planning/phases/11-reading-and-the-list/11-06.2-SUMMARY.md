# Phase 11 Plan 06.2: Tab, F6 or a click into the message list lands on a row Summary

**When the message list takes focus with no row under the cursor, the cursor lands on the
row somebody was on when it is still inside the rows, else on the first row under the sort,
selected and focused on the control with the row in view, so the row is what a screen
reader is handed on arrival; a list that already holds a row is left where it was; an empty
list says "No messages" once. The rule is `where_to_land_on_arrival` beside 11-06.1's three
in `presentation::landing_after_a_removal`, four cases; the wiring is
`presentation::list_arrival::wire` on the list's `SET_FOCUS`, the one path Tab, F6 and a
click share, landing only when the control holds no focused item. A built tree and list
proved the four steps and recorded what the control raised: before the fix an arrival
raised one focus event naming the list itself, which is what the tester heard; after it,
the list itself and then row 0 twice, where a list already holding row 1 raises the list
and then row 1. Nobody has heard the row read once.**
