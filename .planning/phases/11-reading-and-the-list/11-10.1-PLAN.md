<objective>
An address written out becomes a link, and the sanitiser keeps the real
links a sender writes.

Purpose: #89, Pratik's ask of 2026-09-19 and his comment the same day
after reading the tester's message from the cache: the FanFiction
message is plain text only, the chapter address is bare text on its own
line, and the sanitiser stripped nothing because there was no link to
keep. A plain-text message is shown escaped inside `<pre>`, the fix of
an older fault in which a bare address vanished for looking like
markup, and nothing since has made the address a link; NVDA's link list
finds nothing. The same is true of an address typed into an event or
task description and of a bare address in a note. So the whole fix is a
recogniser over text, written once, producing anchors through the one
address rule the sender's links already pass, and a smaller check that
the cleaner keeps the schemes a sender writes.

Output: the recogniser with its cases, the plain-text renderer, the
reply's quoted text, `as_markup` and `spoken` using it, `tel:` allowed,
the refused link saying so, the corpus, the readings, the pages and the
changelog. Closes #89 on the tree side; whether NVDA's link list finds
the chapter is the tester's ear. Before 11-11.1, so its activation
reading and its NVDA case cover a made link as well as a sender's.
</objective>
