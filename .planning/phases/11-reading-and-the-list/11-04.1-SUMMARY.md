# Phase 11 Plan 04.1: Alt+A reaches the attachments in both views, and F8 is retired there Summary

**Alt+A moves to the attachments of an open message and back in both message windows.
In the formatted page window, the default, the key arrives the way Escape and F6 already
did, through a script injected into the page that posts it to the window, because a key
bound on the browser control is a key the browser keeps: the F7 and F8 bindings that sat
there never fired, and the sentence read on open promised a key that did nothing. The
window now moves focus to the list on Alt+A and says "Attachments" with the count, to the
warning bar on F7 and says "Security warning", says "No attachments" or "No warning" when
there is nothing to go to, and says "Message" on the way back; the dead binding is gone.
In the plain-text reader the item is on Alt+A and the way back is answered from the menu
handler as well as from the list, because the chord is the item's accelerator and a frame
takes an accelerator before a list box sees the key, which means F8's way back from that
list most likely never fired either. The pages say Alt+A with F8 dated. Nobody has heard
any of it.**

## What the tree contradicted

Every command in the plan's six premises was re-run against `main` at `7573a812` before the
branch. The line numbers had moved by 11-04 (`show_conversation_as_page` at `20984`, the
binding at `21209`, the sentence at `21271-21272`, `wire_the_way_out` at `11959` with the
calls at `1412` and `21087`); the shapes held. Four things the plan did not have:

1. **The phase 10 readings of `wire_the_way_out`'s script are not in `tests/wired.rs`.**
   The plan's read-first sends the executor there; the readings are in
   `tests/a_key_is_documented_where_the_surface_that_binds_it_is.rs`, whose
   `test_every_key_that_closes_the_conversation_window_is_in_its_section` reads every
   `.key === '` in `wx_app.rs` and requires each in the "Getting out" section. Had the
   jumps' script gone into `wx_app.rs` as the plan wrote it, that test would have demanded
   `F7` be documented as a way out. The script lives in `page_jumps.rs`, which that reader
   does not open, and its docs say so.
2. **The preview's handler does not ignore what it does not match.** T-11-55 says
   `on_script_message_received` ignores unknown kinds "as it does today"; the preview's
   handler at `wx_app.rs:1416` treats anything that is not a leave as a context-menu
   request and pops a menu. One shared script posting `attachments` from the preview would
   have opened a menu on Alt+A there. Which keys a page is given is a parameter, and the
   preview takes the way out alone; the preview's handler is unchanged and still has that
   shape, noted in decision 2 rather than fixed, since no page posts it anything else now.
3. **The way back in the reader "works as written" was not measured by the plan, and the
   toolkit says it did not.** The chord on the item is a menu accelerator; wxWidgets
   translates a frame's accelerators before dispatching the key to the focused control,
   except where the control's `MSWShouldPreProcessMessage` refuses, and a list box refuses
   nothing. So F8 on the reader's list went to `ID_GO_ATTACHMENTS`, which set focus on the
   list that had it, and the list's `347` arm never ran. `wired.rs`'s `KNOWN_DEAF` records
   the mirror case: Ctrl+Down reaches the reader's text control and the menu item does
   nothing, because a text control refuses Ctrl+arrows. The menu handler now goes back
   when the list has focus; the list's arm stays for the case the reasoning is wrong.
   Ledger 538 says it was reasoned, not watched.
4. **The plan's criterion `grep -v '^\s*//' src/presentation/wx_reader.rs | grep -c 'F8'`
   is 1, not 0.** The one line is the rewritten test's own `assert!(!said.contains("F8"))`,
   the assertion that the sentence no longer names it. The criterion is met in its meaning
   and the number is quoted as it is.
