# Phase 14 Plan 08.1: a saved draft takes only its own copies Summary

Saving a draft now takes out of the server's Drafts folder only the older copies whose
Message-ID is the draft's exactly, read through the one function Send's removal also uses;
a message whose identifier merely contains the draft's stays (ledger 902 closed).

## What works now

- `replace_the_filed_copy` takes `asked` from `the_drafts_own_copies`, which runs the
  server's `UID SEARCH HEADER MESSAGE-ID` and then `the_ones_carrying_it_exactly` over its
  answer. `take_away_the_filed_copy` takes its numbers from the same function, so the rule
  lives in one place. `git grep -n "\.copies_already_there(" -- src/application/draft_copy.rs`
  names one line (306) and `the_ones_carrying_it_exactly(` one call (307), both inside it.
- A first save, whose search finds nothing, reads nothing. On the loopback holding the
  draft's copy at 4, a save sends the search, then `UID FETCH 4` exactly once, then the
  APPEND, then `UID STORE 4` and `UID EXPUNGE 4`, on the session and the folder the search
  already opened: one more round trip a save, no second `SELECT`.
- A save whose older copy cannot be read files the newer copy, removes nothing and says an
  older copy may still be on the server with the server's words. A refused first save whose
  search found only another message says the draft is on this computer and nowhere else.
- No sentence is added or reworded; no setting, key, letter, control, schema or version
  changes. Not pushed (premise 7).
