# Phase 12 Plan 02.1: The guard sweep's remedy, and the bound that keeps a shard

A guard runner that cannot lose a shard to one record, and 26 records that
now agree with the tree or say why no machine can judge them.

## What was built, and what it cost

**The bound came first, and it is the only part of this plan that changes
what a tool does.** `scripts/guards.py` now holds every record, and every
suite's pre-read, to one wall clock shared by its build and its run. What
passes it is killed along with the processes cargo started under it, reported
unmeasured with the seconds it reached and which term it was in, and the run
goes on to the next record or suite. The closing line counts what a run gave
up on and the run exits 1, so a run that hit the limit cannot read as clean.

The default is 1,800 seconds, just under four times the 456 s the longest
record to finish anywhere in run 35520204784 took, `1800 / 456` being 3.95.
The constant's comment carries that and the shard arithmetic behind it:
eighteen measured records at that sweep's 223 s mean plus two at 1,800 s is
7,614 s, about 127 minutes against the workflow's 360-minute cap.

`--time-limit` is a flag and not an environment variable, because
`tests/the_guard_sweep_runs_on_runners.rs` reads the flags the script accepts
off its `add_argument` calls and holds the workflow to them; a variable set
in a workflow's `env:` would be a coupling nothing checks. The workflow
declares a `time_limit` input at 1800 and the shard step passes it, so the
value a dispatch used is in the dispatch's own record. `timeout-minutes: 360`
stays as the backstop.

## What the sweep really found

Run 35520204784 was dispatched on 2026-09-20 at `0ad66e48` over the 1,029
records the file held that day. Read back on 2026-09-22 with `verdicts_in`
over the 52 shard logs concatenated in shard order: 1,020 records with a
verdict, 994 agreed, 21 short, 5 that could not be measured, against 1,021
`-- ` headers, so one record has no verdict at all.

**The findings document this plan was written from said 1,009 of 1,021 got a
verdict. It is 1,020**, because that document counted all twelve of shard
40's headers as unverdicted and eleven of them have a verdict. The plan's
premises had already corrected that and five other things, and every one of
those corrections held when it was taken again here.
