## What the tree contradicted

Every premise command was re-taken at `342b019f` before the branch. The run records matched
premise 1 word for word (`focusAfterTheFirstReturn` is `wxWindowNR`, the frame, named by the
window's title), and so did the four stale texts. Four things differed.

1. **wxdragon 0.9.17 classes a frame's activate event as `General`, not `Activate`.** The
   plan's binding matched on the typed variant and was red after the green was written.
   A probe (three `eprintln!` lines, written with Edit and removed with Edit) showed
   `activate event: false` on every activation, and every tick read the window as inactive.
   `WindowEventData::new` classes by `get_event_type`, which answers nothing for this
   event. `wxd_ActivateEvent_IsActive` reads the flag through a `dynamic_cast` that answers
   false for anything that is not an activation, so the handler reads it that way
   whatever the class. The reading found this and no unit case could have. It is an
   upstream defect, recorded in the module's doc rather than hidden.
2. **`GetForegroundWindow` answered 264618 during the run, not 395246.** The plan measured
   395246 while it was being written. Both are in the header, dated.
3. **The page-window reading printed another process's window title.** 12-01 wrote the
   reading when nothing was ever in front. With the tester at the machine, the first run
   today printed his window's title in the reading's line. That line is test output, which
   a failing gate prints and a refused red commit copies to `red-run.log`. It now reads the
   title only for the run's own windows.
4. **The corrected calendar case would have been unable to fail at Delete Event.** After
   12-03, Edit Event and Delete Event both say "Choose an event first.", and
   `waitToHearAll` searches the whole speech log since NVDA started. So the second wait
   would have been answered by the first key's sentence. `waitToHearAll` gained an `after`
   count, and each of the case's three waits counts only what came after its own key.

## Deviations from Plan

**1. [Rule 1 - Bug] The activation flag read through its own accessor.** Found during task
1's green, by the reading staying red. The plan's shape matched on
`WindowEventData::Activate`, which wxdragon never produces for a frame. Fixed in
`page_focus.rs`, in `14c3f3a6`.

**2. [Rule 2 - Privacy] The page-window reading no longer prints another process's window
title.** Found during task 1's first red run. Fixed in the reading, in `4ae3d748`. The
module doc and the red commit say why.

**3. [Rule 1 - Bug] `waitToHearAll` gained an `after` count, and the calendar case counts
each wait from its own key.** Found while writing task 3's green. The plan said the green
changes the two cases and adds ties and nothing else; it also changes
`nvda-tests/helpers/nvda-navigation.js`, which is outside `files_modified`, in `d258de45`.

**4. [Rule 2 - Security] The watcher takes the title as a single-quoted PowerShell literal**,
not `JSON.stringify` as the plan and T-12-03.1-04 said. A double-quoted PowerShell string
expands `$(...)`; a single-quoted one expands nothing. In `f90f3ec2`.

**5. [Decision] The classification is a pure function with a unit case of its own,
`where_the_keyboard_is`.** That makes seven unit cases, not six.

**6. [Decision] The reading's record breaks the "says" predicate, not the refusal filter.**
The plan asked for a break making "said by the program" answer yes for everything. Breaking
