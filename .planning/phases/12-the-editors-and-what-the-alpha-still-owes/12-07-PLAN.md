<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a typed name to five stored fields | a guess written into fields the person can send to a provider |
| a typed address or number to a refusal | a rule that refuses a real one keeps a person from saving a contact |
| the three providers to the store | three field names each way, and a card other clients read |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-24 | Tampering | a guess overwriting what the person typed | high | mitigate | the typed flags; a guard record holds that a typed family name survives a Name change; the reading drives it |
| T-12-25 | Denial of service | a real address or number refused | medium | mitigate | the address rule is 11-10.1's recogniser, already tested over real shapes; the number rule refuses only letters or no digit; the cases say what passes |
| T-12-26 | Tampering | a five-part N card refused by another client | low | mitigate | vCard 3.0's N has five parts by the standard; the writer fills them in order; the reader round-trips |
| T-12-27 | Information disclosure | a prefix or suffix sent to a provider the person did not expect | low | accept | the fields are the person's own entries and go where the rest of the name goes; the guide says which provider carries what |
| T-12-SC | Tampering | npm, pip or cargo installs | high | mitigate | no crate is added; the country table is data in the tree with its source; the summary says so |
</threat_model>
