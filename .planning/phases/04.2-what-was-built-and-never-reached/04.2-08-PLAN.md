<objective>
Make a column layout belong to the kind of folder it was made in.

Purpose: `ColumnLayout` carries a `kind` and `message_columns.rs:547` says why:
so the window can leave the layout alone when moving between folders that want
the same columns. Three facts defeat it. `to_stored` does not write the kind,
every read hands `Inbox` in, and a kind change replaces the layout with defaults
rather than restoring one. So somebody who sorts a column in Sent writes the
Sent layout into the one stored string, and after a restart the inbox opens with
no Unread column, sorted by the date the sender claimed, which
`message_columns.rs:54` warns puts forged-date spam permanently on top. Nothing
anywhere says the layout is one global setting.

Output: the kind stored and read back, one layout per kind for the session, the
Columns dialog told which folder it is in, and the user guide saying what is
remembered where.
</objective>

<premise_corrections>

**1. This is two defects and one of them is not storage.** The stored string not
carrying the kind is what survives a restart. Separately,
`wx_app.rs:2737-2748` replaces the layout with `defaults_for(kind)` whenever the
kind changes, so within one session a hand-chosen inbox arrangement is thrown
away by a trip to Sent and back, before anything is stored at all. Fixing only
the first leaves the second, and the second is the one somebody meets first.

**2. The stored format already has a convention for adding a field, and it must
be used.** `to_stored`'s own comment says the second sort level "is appended
after a semicolon, so a layout written before there was one still reads here and
one written here still reads in a build that only knows the first". Every
existing user has a stored string with no kind in it, and
`test_a_layout_stored_before_there_was_a_second_level_still_reads` exists because
losing somebody's arrangement over a format change was judged a poor trade. Add
the kind the same way, and add a test in the same shape for a layout written
before there was a kind.

**3. A layout read back with no kind in it is not an Inbox layout, it is a
layout of unknown kind.** Today's four call sites all say `Inbox`, and for an
existing user the string may well be a Sent layout. Decide what an unknown kind
means and write the reason down. Defaulting to Inbox repeats the bug for one
more restart; treating it as unknown and rebuilding from the open folder's
defaults loses one arrangement once, for people who have one, and is correct
from then on. Say which was chosen and why, in the code.

**4. The Columns dialog fix is one line and the value is already in hand.**
`wx_app.rs:4042` passes `message_columns::FolderKind::Inbox` as a literal, and
`column_layout.borrow().kind` is the kind of the layout in effect, which
`wx_app.rs:2741` set from the open folder. `message_columns.rs:517` already
records this exact shape being half fixed by `98546f8`, which fixed the
folder-switch site and left the dialog. Read that comment before writing
anything: it is the finding, written down by whoever caused the remainder.

**5. Where the tests go was measured.** 624 records in `guards.toml` at
`5f57d3a`, counted by parsing `tests_last_seen` blocks.
`presentation/message_columns.rs` is named by 1 record, `presentation/wx_columns.rs`
by 0, `presentation/wx_app.rs` by 40 and `presentation/wx_settings.rs` should be
counted rather than assumed. Tests go in `message_columns.rs` and
`wx_columns.rs`. Nothing goes in `wx_app.rs`.

**6. Neither test being rewritten is named by any guard record.** Measured
2026-09-06: `grep -c` on `test_reset_returns_to_the_folder_default` and on
`test_both_levels_survive_being_stored` against `guards.toml` answers 0 for
each. So the renames will not make a record unmeasurable. Re-check after plans
01 to 04 have added records rather than trusting this line.

**7. `docs/USER_GUIDE.md:220` is not wrong and must not be treated as a
correction.** It promises per-folder memory for the Thread column, and that one
is genuinely per folder through `cache.set_folder_thread_column`. What is
missing is any sentence about the rest. So this is an addition to a page, not a
false claim being fixed, and the summary should say so rather than filing it
with the phase's other document corrections.

</premise_corrections>
