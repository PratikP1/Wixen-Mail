<objective>
Make a meeting reply arrive as a reply. The document is right, the content type
that says what it is has been written since `592ba56`, and nothing on the path
that ships has ever asked for it.

Purpose: `docs/changelog.md:2490` tells users the organiser "learns where you
stand instead of waiting". A standards-conforming client receiving
`text/calendar` with no method does not fold the answer into the meeting, which
is what `the_calendar_part`'s own doc comment says will happen. So the feature
this entry describes has never worked and the entry has been wrong since it was
written.

Output: a reply declared as a reply, carrying the name this program chose for
it; one test that measures the shipping path instead of a function nothing
calls; and a changelog that stops making the claim.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a calendar document somebody else wrote -> a MIME header on an outgoing message | attacker-controlled text one layer away from a header line |
| a file on disk -> the bytes read at send time | the file can change between being picked and being sent, which `read_all`'s doc already treats as the intended behaviour |
| a reply document -> a folder under the cache directory | written by this program, read by this program, and named so two concurrent replies cannot collide |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4.2-01 | Tampering | a `METHOD` line from a forwarded document reaching a Content-Type header | high | mitigate | `content_type_of` returns `&'static str` chosen from a closed match over `WhatItAsks`. Nothing interpolates. A test attaches a calendar document whose `METHOD` line holds a header separator and asserts the declaration is one of the four fixed strings. |
| T-4.2-02 | Denial of service | a malformed or enormous `.ics` attachment handed to the method reader | medium | mitigate | the reader is `invitations::what_it_asks`, which already runs over attacker-controlled mail on the receiving side and returns `SomethingElse` for anything it cannot read. Bytes that are not UTF-8 short-circuit before it is asked. A test drives a truncated document and a document that is not a calendar at all. |
| T-4.2-03 | Spoofing | a forwarded invitation presented to the recipient's client as one | low | accept | this is what the document says it is, and what every other mail client does. The `ORGANIZER` inside is unchanged, so the recipient's client attributes it to whoever called the meeting rather than to the forwarder. Named in the changelog rather than shipped quietly. |
| T-4.2-04 | Information disclosure | the reply document left on disk under the cache directory | low | accept | pre-existing and unchanged by this plan. The document holds a meeting name and one answer, both of which the person already has in their mailbox. The folder moves from one file per reply to one directory per reply and nothing else about it changes. |
| T-4.2-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan adds no dependency. `Cargo.toml` changes only for the version bumps, and the diff is read rather than assumed. |
