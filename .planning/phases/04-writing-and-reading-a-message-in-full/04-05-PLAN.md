<objective>
Let a filter rule ask how safe a message was judged to be, and make the warning
bar say who judged it.

Purpose: success criterion 6. A spam and phishing verdict already exists, is
merged from up to four sources, stored on the row, shown as a message-list
column and read out in the reader's warning bar. What it is not is a thing a
rule can ask about: `A_FIELD_A_RULE_MAY_NAME` holds eleven names and `safety` is
not one of them, while `CachedMessage.safety` is on the very struct the matcher
is handed. And the bar's sentences name their source unevenly, so somebody
hearing several cannot tell which came from where.

Output: a rule that can name the verdict, and a bar in which every sentence says
who said it.
</objective>

<premise_corrections>
**1. READ-03's title is the wrong question and its evidence says so.** "Hook
into an external spam classifier" is accurate as an absence and it is not what
criterion 6 asks for. `src/service/safety.rs`'s own module header argues, with
reasons, that the most reliable free detection available is the detection that
has already happened, and that asking an outside service means handing it links
out of private correspondence. **Do not add an external classifier.** Criterion 6
is one entry in one list plus a wording change.

**2. Adding one name to that list touches five things, and the fifth is a green
test asserting the size of the vocabulary.** Found by grepping the test tree for
assertions about this list before planning, which is the sweep this phase
exists partly to institutionalise:

- `A_FIELD_A_RULE_MAY_NAME: [&str; 11]` — the array size is in the type.
- `WHAT_EACH_FIELD_IS_CALLED: [(&str, &str); 11]` — the same.

  `test_every_field_the_list_names_is_one_the_reading_really_handles` plus

  two together in both directions.
- `test_every_field_a_rule_may_name_has_words_and_nothing_else_does`, which
  requires the words.
- **`saved_searches::test_no_other_field_a_rule_may_name_carries_a_sentence`
  asserts `quiet.len() == 8`**, and its own comment says the count is there so
  the list is read again rather than the number moved. It goes to 9, and the
  summary has to say the list was read again rather than that a number was
  bumped.

**3. Both rule editors and the dialog-label integration test build their lists
from the constant**, so nothing in `wx_managers.rs` or
`tests/manager_dialog_labels.rs` should need editing. Confirm that by running
them rather than assuming it: `test_a_condition_this_build_can_show_stops_nothing`
and `test_every_field_and_every_comparison_reaches_a_row_in_its_own_words` both
loop over the constant and would fail loudly if the words were missing.

**4. The stored form already exists and it is not `label()`.**
`Safety::as_str()` gives `ordinary`, `suspicious`, `spam`, `phishing`, is what
the column holds, and its doc comment says why words rather than numbers.
`Safety::label()` gives an empty string for an ordinary message, which the
engine would read as an absent field, and its own comment says the empty answer
is for a list column. Use `as_str()`.

**5. The bar's sentences name their source unevenly, and that is criterion 6's
second clause.** The four provider readings all end at the same phrase, "Your
mail provider's filter", so a reader cannot tell which header reached it, and
that is probably fine. What is not fine is that `from_analysis`'s sentences name
nobody at all: "A link points at a bare numeric address rather than a name" is
this program's own reading and reads as though the provider said it. The folder
signal and the Safe Browsing verdict merge in the same way. **Read all four
before deciding the wording**, and the summary quotes a bar carrying sentences
from more than one source, before and after.

**6. Nothing deletes on a verdict today, and this plan must not make it
possible for something to start.** Criterion 6's "never as a silent deletion" is
satisfied today by nothing automatic acting on the verdict at all. Adding the
field lets a user write a rule with a deleting action, which is their decision.
Read `FilterAction` and what `mail_sync` says when a rule fires before writing
anything, and if a rule's action is not said out loud that is a finding to
record rather than to fix here.

**7. Everything was located by symbol on 2026-09-05.** `04-RESEARCH.md` carries
