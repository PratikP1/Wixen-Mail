<objective>
Say out loud what the application already works out on every message it reads
and tells nobody: that this message is encrypted, and that nothing here can open
it.

Purpose: `MessageSecurityReport` carries eight fields, computed on every message
read on a live path. Its only production consumer, `body_safety::from_body`,
reads two. So a person opening a PGP-encrypted message today gets a screenful of
armour with no explanation beside it, while three lines above, the program has
already decided the message is encrypted. This is the half of success criterion
5 that needs no cryptography at all.

Output: an encrypted message that says it is encrypted, and ordinary mail that
is unchanged.
</objective>

<premise_corrections>
**1. Do not wire all six dropped fields. Four of them must not be wired, and
two of those would be a second answer to a question already answered better.**
`04-RESEARCH.md` and READ-02's evidence both say six fields are computed and
thrown away, which is true, and neither says what wiring each one would mean.
Read `SecurityService::analyze_message_security` and its four detectors before
acting:

- `smime_signed` and `signature_status` are substring searches over the body
  text: `application/pkcs7-signature`, `.p7s`, and a guess at a status.
  `application::checking_signatures::for_message` already answers that question
  properly, with a DER reader, a certificate store and a real Windows
  implementation, and its answer already reaches the bar through
  `ReaderDocument::with_signature`. Wiring the weak answer beside the strong one
  is two answers to one question, which is the failure this codebase keeps
  finding. **Leave both, and say why in the summary.**
- `smime_encrypted` searches the body text for `application/pkcs7-mime` and
  `smime-type=enveloped-data`. **It can never fire through this path, and that
  is a finding rather than a detail.** An S/MIME enveloped message has no
  `text/*` part at all, so `mime::parse`'s `first_of_kind` yields nothing for
  both bodies, `from_body` is handed two empty strings, and the detector
  searches an empty string for the thing it is looking for. A test wired through
  `from_body` for that field would be a test that could not fire in production.
  The S/MIME case is 04-09's and it is answered from the message's
  `Content-Type` rather than from its body.
- `phishing_score` is the number behind `phishing_risk`, which already reaches
  the bar. Showing the number as well is READ-03's "a stated score with its
  source named" and belongs with 04-04's work if anywhere, not here.

**So this plan wires two: `pgp_encrypted` and `pgp_signed`.** Those are the two
that can fire, because a PGP armoured block *is* a text part and does reach
`from_body`, and they are the two with no other answer anywhere in the tree.

**2. This must not be gated behind `look_at_message_contents`.** `from_body` is
called from `wx_app.rs`'s message-open path only when that setting is on, and
`Verdict::ordinary()` is used when it is off. That gate is right for a phishing
scan, which reads what a message says. It is wrong for this, which reads what
form a message is in. Somebody who has turned content scanning off would get the
unexplained blob, which is the exact defect this plan exists to fix. Ask the
encryption question outside the gate.

**3. `looks_unsafe` stays false.** `ReaderDocument`'s own doc comment argues it:
the bar now also holds what a signature is worth, and a signed message nothing
has flagged is not an unsafe one. An encrypted message is not an unsafe one
either, and `pdf_document`'s `looks_unsafe: false` line carries the same
reasoning. `with_signature`'s `NotKept` arm is the precedent to copy: the bar
changes and the flag does not.

**4. Everything was located by symbol on 2026-09-05.** `04-RESEARCH.md`'s line
numbers are from commit `d3c6c7d`. Five of phase 3's nine plans found theirs
stale.

**5. Guard-record cost, measured by parsing `tests_last_seen` rather than by
grepping for a file name. Six plans in phase 3 quoted the grep and all six were
corrected.**

| file | records fingerprinting it | test functions today |
|---|---|---|
| `src/application/body_safety.rs` | 0 | 13 |
| `src/presentation/reader_text.rs` | 0 | 76 |
| `src/service/security.rs` | 4 | 15 |
| `src/presentation/wx_app.rs` | **39** | 199 |

New tests go in `body_safety.rs` and `reader_text.rs`, which cost nothing.
`security.rs` is not modified by this plan, so its four records are not touched.
**No `#[test]` goes in `wx_app.rs`.**

**6. An integration target cannot see anything behind `#[cfg(test)]`.** Task 2's
census reads source text and needs nothing from the library, which is what makes
`tests/` a safe home for it.
</premise_corrections>
