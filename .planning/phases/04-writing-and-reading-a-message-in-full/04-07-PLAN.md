<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a path from the operating system's drop -> `Chosen::at` | the path is chosen by whoever dropped it and can name anything the process can read |
| the clipboard -> `Chosen::at` | the same, by a different route, and a clipboard can be written by any process on the machine |
| a file name -> what a recipient receives | `safe_file_name` is the only thing between a path's last component and a name in somebody else's mailbox |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-27 | Tampering | a dropped path naming a directory, a device, or a name that walks out of its folder | high | mitigate | every route goes through `Chosen::at`, which refuses a directory, and through `safe_file_name` for the name. The census in task 2 is what keeps that true when a fourth route is added. Add a fixture with a traversing name and one with a reserved Windows device name, and say in the summary what `safe_file_name` did with each. |
| T-04-28 | Information disclosure | a drop attaching a file the person did not mean to send | high | mitigate | every file that goes on is announced by name and the running total is said, which is the existing behaviour and is what the batch wording must preserve. A batch that says only "3 attachments" would lose that, so the names are said. |
| T-04-29 | Denial of service | a drop of several hundred files | medium | mitigate | `over_the_limit` is asked once after the batch and refuses on total size. Decide whether a count bound is needed as well and say why either way; reading metadata for several hundred paths on the interface thread is a window that cannot speak. |
| T-04-30 | Elevation of privilege | the page handling a file path, if the fallback design is ever taken | high | transfer | not built here. Task 3 records it as a different security boundary and it gets its own plan and its own threat model if it is ever taken. |
| T-04-31 | Spoofing | a file whose name says one kind and whose bytes are another | medium | accept | pre-existing and unchanged: the picker has always attached what it was given. The recipient's client decides what to do with it, and this program does not claim to have checked. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package is added. Drag and drop and the clipboard are already in `wxdragon 0.9.17`, which is already a direct dependency, and need no feature flag. `Cargo.toml` is touched only by version bumps, confirmed by reading the diff, and the summary says so. |
</threat_model>
