# Phase 2.1 Plan 02: Two guards that can fail Summary

The version guard can now see a violation on the pages it really reads, proved
by making its reading answer nothing and watching the guard stay green while the
new companion failed. A second guard names any comment telling a reader that a
test cannot build a live wxWidgets window; it was red on eleven sentences in ten
comment blocks, and all ten now say the budget.

## Criterion 7: the version guard can see a violation

`THE_STATUS_PAGES` is `README.md` and `docs/IMPLEMENTATION_STATUS.md`. Neither
names any version, so the guard's inner loop never ran and the assertion was
over an empty list. That premise was correct and was re-checked here.

The per-page reading came out into `wrong_versions_on(page, text, shipped)`, the
guard still calls it over the real files, and
`test_the_version_reading_can_see_one_on_a_real_page` calls the same function
over each real page's own text with one line naming `0.0.0-notashippedversion.1`
spliced into the middle. It asserts the whole complaint string, so page, line and
version are all three proved at once. It also asserts each page opened and held
text, and that the pages as they stand name nothing, which is the vacuity
recorded rather than assumed: if a version ever returns to a page, that assertion
fails and names the page.

**How it was proved it can fail.** `wrong_versions_on` was made to answer
`Vec::new()` and the three tests were run:

| test | result |
|---|---|
| `test_no_status_page_names_a_version_the_code_does_not_ship` | ok |
| `test_the_version_reading_can_see_one` | ok |
| `test_the_version_reading_can_see_one_on_a_real_page` | **FAILED** |

The failure was `left: []`, `right: ["README.md:62: names
0.0.0-notashippedversion.1, and the code ships 0.46.0"]`. The guard and the
older literal-fed companion both stayed green against a reading that had stopped
reading, which is exactly the gap the criterion is about. The stub was reverted
before committing; the commit adds 67 lines and deletes none.

No version was put on either page.

## Two premises of the plan that were wrong

**1. The plan said to read source through `common::what_ships`.** That deletes
`#[cfg(test)]` items, and the flattest instance of the claim, `wx_app.rs:19806`,
sits on a `#[cfg(test)]` helper. A guard following that instruction would have
been blind to it and green. The guard reads whole files, because a comment
steers the next person whether or not it ships.

**2. The plan expected five places.** Ten, in five files. The plan's file list
named three. Two of the extra files, `accessibility/names.rs` and
`wx_folder_choice.rs`, were changed anyway, because the criterion is "no file in
the tree" and an exception list would have been narrowing the guard until it
could not see the two worst cases.

## What the new guard sees and what it cannot

Two ways to say the claim, because the tree says it both ways: a refusal landing
on a verb that puts a window up, within four words, in a sentence naming a test
and a window; or a comment naming the one-application-per-process ceiling and
stopping there.

The first draft asked only that a sentence hold a test word, a negation and a
window word somewhere in it. **It named sixty places, almost all saying the
opposite**, such as "a test can build the real dialog and read back the real
colour a live control holds, and never call `show_modal()`". Adjacency is what
made it usable. The distance of four is measured against the longest real
instance, "nothing in this crate builds", not picked.

Stated in the guard's own comment as its blind spots:

- It reads one sentence at a time, so a claim split across a full stop is two
  halves it never joins.
- A refusal further than four words from its verb is invisible, and so is one
  worded with a verb the list does not hold. `show` and `raise` are deliberately
  not on that list: no wording in this tree needs them, and `shows` put
  `occurrences.rs` on the list for "a window the product no longer shows", where
  the window is a span of time.
- The exemption is a wording rather than a meaning. A comment that says the
  number some other way is named anyway, and the fix is to add the wording with
  the comment quoted beside it.
- `tests/house_style.rs` is not read, because its companion holds the claim as
  data. That is a hole and the code says so.

## How the second guard was proved it can fail

Both arms, by hand.

| what was done to the reading | `test_no_comment_says_a_test_cannot_build_a_window` | `test_the_window_claim_check_can_tell_the_two_apart` |
|---|---|---|
| made to answer nothing | ok | **FAILED**: "a claim the tree really carried was not named" |
| made to answer everything | (red, as it should be) | **FAILED**: "a comment stating the budget correctly was named as a claim" |

The guard staying green against a reading that answers nothing is the whole
defect this plan closes, reproduced on the new guard so that the companion is
the thing standing between it and the same fate.

**The companion found a real defect while it was being written.** It asserts the
reported line, not only that something is reported. A sentence span opens on the
character after the previous full stop, which is whitespace still belonging to
the line before, so every fault after the first in a comment block was reported
one line early. Fixed to report the trimmed sentence's own offset. Nothing about
presence would have caught it.
