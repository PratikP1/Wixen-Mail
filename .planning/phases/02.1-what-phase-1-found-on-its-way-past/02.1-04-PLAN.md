<objective>
Make a guard that lives under `tests/` run on the commits that could break it,
by reading the coupling `guards/guards.toml` already declares.

Purpose: criterion 9. `scripts/check.sh` maps a changed `src/a/b.rs` to
`cargo test --lib a::b::`, so an integration target guarding a `src/` module is
reached only when the test file itself changes. A guard that runs on the wrong
commits is the shape guardrail 4 in `CLAUDE.md` is about: it reads as covered.

Output: the gate reading the registry, the two uncoupled targets gaining a
record, and a suite over the mapping.
</objective>

<premise_corrections>
**1. The criterion is right about the mechanism and half right about the
coverage.** Measured 2026-09-02, `guards/guards.toml` holds `suite` on records
whose `file` is not a `src/` module reachable by `--lib`, and on four whose
`file` is one. The couplings that exist and point from a source module to an
integration target are:

- `src/presentation/wx_managers.rs` to `manager_dialog_labels`, one record
- `src/presentation/wx_app.rs` to `wired`, five records
- `src/main.rs` to `wired`, one record
- `src/application/draft_copy.rs` to `house_style`, one record

**2. Two of those four gain nothing, and the criterion names one target that has
no record at all.** `scripts/check.sh` already runs `--test house_style --test
wired` on every scoped run, under "the guards that read the whole tree". So the
only coupling this change makes real today is `wx_managers.rs` to
`manager_dialog_labels`. `tests/checkbox_labels.rs`, which the criterion names
explicitly, appears nowhere in `guards/guards.toml`, so reading the registry
will not reach it. Neither does `tests/manager_delete_stays_open.rs`. Reading
the registry is still the right mechanism; what is missing is the records, and
task 2 is that.

**3. What each of those two guards, measured today.**
`tests/checkbox_labels.rs` builds a real item-form dialog and checks that a
check box carries its own label on both accessibility channels, so it guards
`src/presentation/wx_item_form.rs`. `tests/manager_delete_stays_open.rs` builds
real manager windows and checks a delete that leaves the list empty, so it
guards `src/presentation/wx_managers.rs`. Each holds exactly one `#[test]`
function, for the one-live-window-per-process budget, which means a record's red
list for either of them will name one test however wide the break is. That is
not a red list shrinking and the record should say so, the way the existing
`manager_dialog_labels` record already does at `guards/guards.toml:12400-12406`.

**4. The change is to a script, so the tests reaching it are its own suite.**
`scripts/check.sh` runs every `scripts/*.test.sh` in every mode before anything
else, which is where `check.test.sh` will run from. `which-checks.sh` answers
`affected` for a commit touching a shell script, and
`run_the_tests_that_reach_what_changed` has no case for `scripts/*.sh`, so the
Rust half of that commit is the tree-reading guards only. That is correct and is
not a gap: what changed is the gate, and the gate's own suite is what judges it.

**5. Do not have this plan run `scripts/check.sh all` or `scripts/guards.sh`
unfiltered.** The merge gate and the sweep belong to whoever merges. Task 2's
records are measured by hand, one break each, which is a different thing from a
sweep.
</premise_corrections>
