## The short answer

Twelve of the thirteen criteria are closed. The thirteenth, criterion 6, is
open by a decision the developer has already accepted and the ledger already
records.

The phase did what it claims. Every fix I checked is reachable from a
non-test path, not merely compiled, and every criterion has a test that would
have gone red on the day its defect was live. I went looking for the failure
this project keeps finding, a check that reads something and finds nothing to
read, and did not find a new instance of it. The two criteria most exposed to
it, 7 and 8, both carry companions that put the reading to a real violation
and watch it speak.

The unusual thing about this phase is real and is worth stating plainly: **six
of the thirteen criteria were closed by something other than what they
described.** In every case the correction is the better answer and the
evidence for it is in the tree, not only in the summary. In one case,
criterion 12, acting on the criterion as written would have added a second
defence to a case that cannot arise while leaving the actual defect in place.

### Criterion 6, in detail

Reported as not met, at the developer's instruction and on the evidence.

The source read does what it claims. `tests/wired.rs:3368` reads the body of
`ask_about_the_folders_that_have_gone` out of the shipping half of the file,
asserts the body is non-empty before doing anything else, and then checks four
things: that the one-question gate's answer is passed, that both ways somebody
can be typing are read, that nothing opens when there is nothing to raise, and
that the question is written down before the window opens rather than after.
Its companion, `test_the_reading_of_the_vanished_folders_question_can_see_a_missing_argument`,
puts the reading to a correctly written body and to one body per break, so the
four assertions cannot be quietly reading an empty string.

So the specific regression the criterion described, the call site dropping
`turn.is_none()` or the focus question while every test stays green, is now
caught. What remains untrue is the criterion's own wording. The window has
never been opened in a running build.

The reason is sound and is recorded at ledger 42. Every path that tells a right
argument from a wrong one ends at `MessageDialog::show_modal`, which blocks
until somebody answers, and in a test there is nobody. A wrong argument would
hang the commit gate rather than fail it, and a check that hangs is a check
that gets deleted. Worth noting that the plan's own assumption here was
corrected too: a live window **was** available, since each file under `tests/`
is its own process. It was not used for the reason above, not for want of a
budget.

**This looks intentional.** To carry it as accepted rather than as a gap, add
to this file's frontmatter:

### One thing left in the tree that is worth your attention

Two comments in `src/presentation/wx_app.rs` state things about this codebase
that are false, and one of them was made false by this phase.

- `:10289-10296` says the checks in `tests/wired.rs` cannot use `what_ships`
  because it is `#[cfg(test)]`, and that the convention of keeping test modules
  at the foot of the file "is load-bearing until those ten have a shared
  answer". They have one now, and they use it. This comment instructs the next
  person to follow a convention for a reason 02.1-01 removed.
- `:19770-19773` says `the_window_itself` reads this file and stops at the first
  line that is exactly `#[cfg(test)]`, so an earlier test module would cut the
  reading off. It uses `what_ships` (`:22444`), which drops each `cfg(test)`
  item where it really ends, so an earlier module would not.

This is not hidden. Plan 01 surfaced both under "Awaiting your decision", and
they are recorded together at ledger 37, open. I raise it because it is the
exact shape this phase exists to close, a document describing a capability as
unavailable when it ships, and because the second one instructs future work to
keep paying a cost that no longer buys anything. It fails no criterion, so it
does not change the score.
