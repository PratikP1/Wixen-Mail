# Phase 2.1 Plan 01: What ships, read once Summary

The sixteen checks in `tests/wired.rs` that read `src/presentation/wx_app.rs`
now read the whole shipping half of it through `common::what_ships`, which is
behind a cargo feature dev builds turn on and release builds cannot. Nothing the
widened reading uncovered failed.

## What was built

Twelve checks cut the file at the first `#[cfg(test)]` and four used a
line-walking reader of their own. All sixteen now ask one function. The
line-walking reader is deleted rather than left unused, because a second answer
to this question is exactly what `src/common/what_ships.rs` exists to prevent.

`common::what_ships` was gated `#[cfg(test)]`, which the library's own unit tests
reach and an integration test does not. It is now gated on a `what-ships`
feature, turned on by a dev-dependency of this package on itself and by nothing
else.

## What the widened reading found

Nothing failed. That is a measurement rather than a shrug, and here is the
measurement.

| | lines |
|---|---|
| `src/presentation/wx_app.rs` | 26,593 |
| what the prefix cut read | 19,728 |
| what `what_ships` reads | 20,117 |
| what `what_ships` drops from the first 19,728 | 0 |

So the widening is purely additive: **389 lines of production code** that no
check in this file had ever read, and nothing that used to be read has been
taken away. All twelve checks reach the same verdict over 20,117 lines as over
19,728.

**The figure the phase was scoped against is wrong by a factor of about
seventeen.** Criterion 4 and this plan both say the twelve were blind to about
6,863 lines, which reads as 6,863 lines of exposure. 6,865 lines sat below the
cut; 6,476 of them are test modules, which these checks should not be reading.
The real exposure was 389, in `ask_about_the_alpha_once` and `block_the_sender`
and the code around them. Both corrected comments now say 389.

**Nothing guards the twelve against going back.** Measured by hand: putting a
prefix cut back into `test_no_two_items_on_one_menu_claim_the_same_letter`
reddens nothing at all, because its verdict does not depend on the extra 389
lines, and the same holds for the other eleven. The only thing that would notice
a reader reverting is the one test written to ask that question directly. The new
guard record says so in its own comment rather than leaving the impression that
the twelve are defended.

## The feature, measured both ways

`--cfg 'feature="what-ships"'` occurrences in verbose builds, each with a
positive control in the same run, and each run forced to recompile the library
first:

| run | compiles of the library | feature enabled |
|---|---|---|
| `touch src/lib.rs && cargo build --release -v` | 2 | 0 |
| `touch src/lib.rs && cargo test --test wired --no-run -v` | 2 | 4 |

The only mention of the name in the release build is rustc's own
`--check-cfg 'cfg(feature, values("what-ships"))'`, which says the name is
spelled correctly and enables nothing.

The positive control is not decoration. The first two attempts at this
measurement both counted zero, and the second counted zero because the tree was
warm and cargo reported every unit `Fresh`, emitting no compiler invocation to
search. A count of zero from a build that compiled nothing reads exactly like
the answer.

The wanted failure direction was demonstrated by hand: with the dev-dependency
commented out, `cargo test --test wired --no-run` fails with
`error[E0432]: unresolved import wixen_mail::common::what_ships`. It fails to
compile rather than reading nothing and passing.

`git diff main -- scripts/ .github/` is empty. Nothing about how this is built
or shipped changed, which is what the measurement was for.

## Deviations from Plan

### 1. [Rule 1 - Bug] A dependency census went red three commits after the cause

**Found during:** after task 3, running the library suite by hand.

**Issue:**
`service::outward::completeness::test_every_dependency_has_been_told_apart_from_a_way_out`
reads `Cargo.toml` and requires every dependency to be classified as able or
unable to reach a server. The self dev-dependency put a new name in the manifest
and nobody had classified it.

**Fix:** `wixen-mail` added to `A_CRATE_THAT_CANNOT`, with a comment saying why
the other list would have been wrong. No test added, so `src/service/outward.rs`
still holds 38 and the four guard records naming it need nothing.

**Commit:** 546a02a

**Why the gate could not catch it, which is the part worth keeping.** On a
branch, `scripts/which-checks.sh` runs the tests reaching what changed and maps
a changed file to a module by its path. `Cargo.toml` maps to no module, so a
manifest-only commit runs formatting, clippy and the two tree-reading guards.
Clippy compiles every target, so a manifest change that breaks the build is
caught; this one did not break the build, it broke a test that reads the
manifest. That is the same shape as the case already written into
`which-checks.sh`, where a markdown change still runs the document-reading
targets because `house_style` reads prose. A manifest is a document to whatever
reads it, and nothing extends the rule that way.

### 2. [Ordering] The six guard records were re-measured a task early

The plan puts the re-measure in task 3. It is in task 1's green commit instead.
The count check goes red on the commit that adds the test, re-measuring needs a
green tree, and the tree is only green once the green half lands, so any later
placement puts a `Fails-until-green` marker on every commit in between. All six
agreed, each reddening exactly the one test it names and nothing else.

### 3. [Premise] Cargo.lock is not left untouched

The plan says adding a `[features]` section rewrites nothing in `Cargo.lock`. It
adds one line: this package's own name in its dependency list. Committed with
the change.

### 4. [Premise] CRIT-2.1-04 is not a tracked requirement

The plan's frontmatter names `CRIT-2.1-04`. `.planning/REQUIREMENTS.md` holds no
entry for it and no phase 2.1 entries at all, so
`gsd-tools query requirements.mark-complete CRIT-2.1-04` reported it not found
and wrote nothing. Phase 2.1's criteria live in `ROADMAP.md`, as its context
file says. Nothing was invented in `REQUIREMENTS.md` to make the call succeed.

### 5. [Premise] The off-by-one in the unread-line count

The plan and the criterion say 6,863 lines. The cut keeps 19,728 lines, so 6,865
sat below it. Neither number is the interesting one; see above.
