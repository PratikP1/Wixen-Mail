# Phase 13.3 Plan 04: a change goes to the message's own account, and waits for a replay Summary

Every command aimed at a message now reaches the server of the account the store files that
message under, so in All Inboxes a mark, star or label on a conversation no longer reaches
the account last opened for a reply in Sent the list never loaded (review item 3). And a read
or star made while a check replays that account's waiting changes now reaches the server after
them, a change let go meanwhile never sent (review item 18).

## What changed

- **Item 3.** `destinations::whose_message_a_command_reaches(on_the_list, filed_under, open)`
  answers the loaded row's account, else the store's, else the open account only when the
  list holds the row with no account; a row neither the list nor the store can place answers
  nothing. `the_account_a_command_reaches(on_the_list, row_id, store, open)` asks
  `MessageCache::the_account_a_message_is_in` only for a row recording no account, logging a
  store error as not knowing. `owner_of` answers through it with a fifth argument, `store`.
  `whose_folders_a_move_is_about` lost its last caller and is gone; its doc's reasons moved to
  the new rule.
- **Every call hands a store.** `git grep -n "owner_of(" -- src/presentation/wx_app.rs` at
  `649a4882`: `:12211` quick step (`cache.as_deref()`), `:26115` move window's folders and
  `:26248` each message moving (`Some(cache.as_ref())`), `:26645` junk
  (`Some(cache.as_ref())`), `:27153` `spawn_folder_move` (`store`), `:28493` `delete_if_local`
  (`Some(cache.as_ref())`), `:28546` `the_account_a_row_is_in` (`Some(store)`), `:28771`
  `spawn_receipt` (`store`), `:29677` `spawn_server_change` (`store`), `:30725`
  `read_attachment` (`store`), `:30861` `save_attachment` (`store`), `:39021` Block Sender
  (`Some(cache.as_ref())`); `:23154` is the definition, and `:38568`, `:38585` and `:38599`,
  `owner_of`'s three unit tests, are the only `None` stores.
  `git grep -n "whose_folders_a_move_is_about" -- src tests` names no line (exit 1).
- **Item 18.** `mail_session::one_flag_change_at_a_time(account_id)` waits for the account's
  flag turn in a map of its own, found through `the_turn_in`, which `one_check_at_a_time`
  shares, so `turns.entry(account_id.to_string()).or_default().clone()` is still one line
  (`mail_session.rs:202`). The replay takes it through `handle.block_on` before
  `flag_changes_waiting_for(` and holds it to its end (`wx_app.rs:19010`); the push's worker
  takes it after the delete arm and before the session (`wx_app.rs:29825`) and holds it past
  its STORE, `stop_waiting_for_what_came_before(` and a failed push's keep. The anchored block
  from `let controller =` to `let outcome = match flag {` is untouched.
  `the_numbering_a_flag_change_was_kept_under` answers `Result<Option<Option<u32>>>`, the
  flattening wrapper gone and the keep reading it; the replay's let-else binds
  `Ok(Some(numbering))`, so a change let go since the list was read is passed over.

## For 13.3-13

`spawn_server_change(app, store, message_row_id, uid, subject, asked_in, change)`: the store
is the second argument, `Option<&MessageCache>`, and every caller hands the window's. Its
worker takes the account's flag turn before it opens a session and holds it to its end, so a
reading mark pushed during a check's replay waits a few seconds for it.

## Deviations from Plan

1. **[Rule 3] Two callers more than the plan listed take the store.** The receipt commands,
   `receipt_for_the_open_message` and `send_receipt_for_the_open_message`, and
   `send_server_first_what_cannot_be_held`, the large-message path of a move across accounts,
   sit between a caller holding the store and a function the plan named, so each takes it and
   hands it on.
2. **[Rule 1] A fourth record broke, and the anchor check did not say so.** "landing on a row
   makes mark as read say which way it will go" anchors on the receipt line above the refresh.
   `test_every_guard_record_still_names_one_place_in_the_tree` passed over it and over the
   three the plan named, because `wx_app.rs` reads as mid-measurement (ledger 545). A count of
   every record's anchor with the TOML reader found all four, rewritten in the green.
3. **[Rule 1] The cases that ask only whether a turn comes wait four times the usual wait.**
   Under the one-lock break the side-by-side cases hold the merged turn for one usual wait each,
   and the "it comes back" cases waited the same time behind them, so the red set changed from
   run to run. A first shape of the case that the two turns do not wait on each other also took
   a second turn unbounded while holding the first, and under that break it waited on itself:
   one measuring run hung nineteen minutes until its test process was stopped. Every wait in
   the new cases is bounded, the case holds the flag turn and then asks for the check turn, and
   `AFTER_THE_OTHERS` gives the existing check cases' "it comes back" waits the same bound. Four
   runs under the one-lock break and two under the fresh lock then reddened the same set each
   time.
4. **[Plan] The wired reading's parser skips line comments,** so a comment inside a call hides
   no argument; the plan asked for a line break or a comment not to hide one.
5. **[Plan] The flag turn's cases are four:** the wait, another account, a panic, and the two
   turns apart; the red is the first, the other three hold what must stay true.
