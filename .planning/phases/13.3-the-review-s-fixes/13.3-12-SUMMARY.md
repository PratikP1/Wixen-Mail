# Phase 13.3 Plan 12: an import says what it left out, and a broken packed zip entry is said to be damaged Summary

An import of a zip or folder of mail now says, after what came in, how many files its first
look could not read, how many do not match what the archive records, and how many folders were
nested too deeply to follow, each file said once; and a packed zip entry whose packed bytes are
broken is said to be damaged or changed after it was made, never cut short.

## What works now

Read from the cases, run through `an_archive_brought_in` with a real store and a file on disk:

- A zip holding `Altered.mbox`, recorded as 10,000 bytes and holding about 400 KB, beside
  `Honest.mbox`: `Honest` comes in with its three messages and the sentence is "Imported 1
  folder, 3 messages. 1 file in the archive does not match what the archive records about it,
  so the archive is damaged or was changed after it was made, and that file was left out."
  Until this plan it was "Imported 1 folder, 3 messages" alone.
- A chosen folder with `Locked.mbox` held open with no sharing beside `Honest.mbox` (Windows):
  "Imported 1 folder, 3 messages. 1 file in the archive could not be read and was left out."
- A chosen folder with one message 33 folders down beside one at the top: the sentence ends
  "1 folder in the archive is nested too deeply for Wixen Mail to follow, so the mail in it was
  left out."
- A zip whose only entry is packed and broken at its first packed byte is refused with the
  damaged sentence of 13.2-31.7, and neither "stops partway through" nor "another copy". The
  same entry beside `Honest.mbox` is said once as a file that does not match what the archive
  records.
- `a_stop_counted` for a zip stopped with `InvalidInput` counts a mailbox file that did not
  match; for a chosen folder it counts one unreadable stretch, as before.

The window's import worker returns the sentence unchanged (`wx_app`), so this is what is shown
and spoken at the end of File, Import.

## Deviations from Plan

1. **[Shape] The red kept the archive's new count at nought.** The plan put the real value in
   the red; that would have left the widened archive assertion green and never red. The red's
   `MailboxArchive::of` wrote `did_not_match: 0`, so the archive case was named red too, and
   the green carried `found.did_not_match`.
2. **[Expected value] No full stop after a bare opening.** The plan quotes today's sentence as
   "Imported 1 folder, 3 messages." with a stop; the program says it without one, as two
   existing assertions spell it (`import_tree.rs`, the folder-count case). The nought
   assertion follows the program; caught by reading the red run before the red commit.
3. **[Shape] The zip rule is `KindOfArchive::why_a_read_failed`,** answered by
   `MailboxArchive::kind()` before the loop, rather than a second conversion. The
   `From<ErrorKind>` match, the anchor of "told apart by its kind", is untouched, and
   `is_a_folder` now asks `kind()`.
4. **[Shape] `a_folder_nested` moved into `mailbox_archive::for_tests`** with
   `a_folder_one_deeper_than_followed`, which reads the private depth limit, so the import's
   case builds one without knowing the number. The helper carries its own message bytes.
5. **[Rule 1] Two re-measure calls for task 2's green, not one.** The single call found "a
   file the first look found not matching its archive is said once" one test short: the
   packed case is also left out at the first look as not matching, so the subtraction's break
   reddens it. Corrected by hand with a comment and measured alone, agreeing. Predicting it
   before the run would have saved the second call.
6. **[Brief] Two read-only commands carried do-nothing shell assignments named after a banned
   tool** (`sed_unused=;` and `sed_never=;`), the slip 13.2-31.5 to 13.3-11 recorded. No sed
   or awk ran; every tracked file was changed with Edit or Write, by `cargo fmt`, or by
   `scripts/guards.sh`.
7. **[Order] The pull request was opened on the four code commits,** and the summary and the
   marks went in the one documents commit after its runs were read, as 13.3-09 did.
