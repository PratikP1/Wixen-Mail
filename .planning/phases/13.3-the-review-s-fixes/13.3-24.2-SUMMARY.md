# Phase 13.3 Plan 24.2: A quote knows a message with no text Summary

The store now tells a message that came down with no text from one never fetched, so Reply and
Forward quote it as nothing and the list stops downloading it at every landing; from the list,
Reply and Forward read the store and never the preview's placeholder; Forward with nothing
chosen refuses in Reply's words, "Choose a message first.".

## What changed

- `src/data/message_cache/bodies.rs`: `KeptText` (`NotHere`, `CameWithNoText`,
  `Here(MessageBody)`) and `MessageCache::the_text_kept_for`, which reads the four columns: no
  row is not here, all four null is came with no text, otherwise the halves decoded as before,
  both gone being not here. `get_message_body` is written through it and answers as it did.
  Four cases.
- `src/application/reply.rs`: `what_quoting_finds` takes `&KeptText`; came with no text is the
  text, online and offline. The case for the rule it reverses is replaced by one for the new
  rule.
- `src/presentation/wx_app.rs`: `what_the_store_keeps_of` (a store that cannot be read keeps
  nothing here, logged); `what_the_list_shows_of`, which the landing asks, a message with no
  text going through the arm that sends a stored body; `NO_READABLE_BODY`, the one place the
  sentence is written, which the fetch's arm for no text uses too; `the_body_a_command_quotes`
  reads the store for every message and no longer reads `message_preview` or `acting_on`;
  `msg_info` answers nothing when no message is for the command; `no_message_is_chosen`
  signals `ActionRefused` with `nothing_chosen(Thing::MESSAGE)`, called by `start_reply` and the
  Forward arm, which is one match over `msg_info`'s answer.
- Readings: `test_a_message_that_came_down_with_no_text_is_shown_and_not_fetched_again` and its
  companion (eight plants) in the parts target;
  `test_reply_and_forward_quote_from_the_store_and_never_the_preview`,
  `test_forward_with_no_message_chosen_refuses_as_reply_does` and one companion (nine plants)
  in the conversation target.
