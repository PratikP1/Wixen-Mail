# Phase 13.3 Plan 22: Two functions only tests call are compiled for tests only Summary

A normal build no longer contains `MessageCache::match_labels_to_keywords`, which reads an
account's labels for one message, or `special_use::classify`, which decides a folder's role from
a listing of one. Both stay where they stand under `#[cfg(test)]`, every case that used them
passes unchanged, and a reading of each file through `what_ships`, red first, goes red again if
somebody takes the attribute off. The guard refusing sed and awk is now tracked in
`.claude/guardrails` with its tests; the hook that runs still points at its old copy (ledger 943).

## What works now

- `match_labels_to_keywords` (`tags.rs:39`) carries `#[cfg(test)]` over its signature. Its doc
  says it is the cases' way of matching one message and why it is test-only. The rules it used to
  give (the server is right, only labels with a keyword take part, a keyword from another client
  is left alone) now sit on `match_these_labels_to_keywords`, the function the flag pass calls,
  with no link to the wrapper.
- `special_use::classify` (`special_use.rs:78`) carries `#[cfg(test)]`, `pub` kept so the case
  at `imap.rs:2724` still reaches it. Its doc says it is the cases' way of asking
  `roles_of_the_listing` about one folder. The doc over `list_folders_asks_over_the_whole_listing`
  now says a normal build refuses a per-folder call, and that its reading stays because a test
  build would not.
- The two comments in `imap.rs`'s cases that called the attribute strings the input to `classify`
  name `roles_of_the_listing`.
- `cargo check --lib` builds after each green, which is a normal build without either function.
- `tags.rs` holds 16 tests, from 15; `special_use.rs` holds 23, from 22; `imap.rs` holds the 102
  the registry names, unchanged. The hook's runs of `data::message_cache::tags` and
  `service::protocols::imap` passed.
- dead-code-hunter over `tags.rs`: every other public function there has a caller outside the
  file's tests. Nothing else changed.
