<objective>
Make a calendar read ask only its own calendar's deletion notes, so a deletion in one calendar
stops reaching the same meeting in another; and give the store's single-event lookups the
shape its sibling modules use.

Purpose: every calendar read asks one set built from every deletion note of the account, on
the stated ground that a provider's name for an event names one event. The store's own
`event_in` doc says the opposite, and 13.2-31.6 said two calendars may carry the same meeting.
Since 13.2-19 a hit in the fold also calls the day off the series of the calendar being read.
So a day deleted in a class feed hides or freezes the same assembly in the school feed for
good, since a feed's note is never let go, and two server calendars or two Google calendars do
the same to each other for a week (item 22, ledger 825). Separately, the one-calendar lookup
13.2-31.6 added is the fourth hand-written copy of a first-row match that rusqlite's
`optional()` already does (item 40). Pratik answered yes to both on 2026-10-20.

Output: the notes narrowed to the calendar being read for all four reads, the cases for each
direction, the four lookups in the shorter shape, the changelog, ledgers 825 and 904, the
four marks. Nothing is spoken or shown, so the branch is not pushed.
</objective>
