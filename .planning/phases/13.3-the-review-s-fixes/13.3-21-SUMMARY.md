# Phase 13.3 Plan 21: A draft's older copy said once per draft Summary

On a server without UIDPLUS a draft's save now finds only its live copy, because the search asks
`UNDELETED`, and the sentence that an older copy may still be on the server is said once for
each draft while the program runs instead of once a minute; Send takes every unmarked copy of a
sent draft out of a Drafts folder on this computer in one statement, and a blank identifier
removes nothing.

## What works now

- `ImapSession::uids_with_message_id` sends `UID SEARCH HEADER MESSAGE-ID "<id>" UNDELETED`. Its
  doc names every caller and why none wants a flagged copy. The loopback cases on the session and
  through `MailController` assert the key on the wire.
- `Filed::needs_saying_for(draft_id, &mut told)`: `Replaced` never, the first
  `FiledAndAnOlderCopyMayStillBeThere` for a draft yes and later ones for it no, whatever the
  server's words, and both refusals every time. `Filed::needs_saying_once_per_draft` runs it over
  a process-wide `Mutex<BTreeSet<String>>` beside `THE_TURN`, taking a poisoned lock's inner
  value.
- `spawn_draft_append` says the answer only when `needs_saying_once_per_draft(&draft_id)` says
  so; `git grep -n "needs_saying_once_per_draft(" -- src/presentation/wx_app.rs` names one line,
  20650, inside `fn spawn_draft_append(`.
- `forget_the_filed_draft` passes the identifier through `thread_identity::bare`, answers
  `Ok(false)` for a blank one, and runs one `DELETE ... WHERE folder_id = ?1 AND message_id = ?2
  AND filed_here = 0`. `git grep -n "self.message_uid_by_message_id(" --
  src/data/message_cache/drafts.rs` names no line.
