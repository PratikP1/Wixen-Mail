# Phase 13.3 Plan 13: a message read in a conversation window turns read in the message view Summary

In the message view, a message you open from the conversation window that Enter opens on a
row is now marked read after the wait, while the list's cursor stays on a message of that
conversation, as it already was in the conversation view. A message read aloud with Space from
its own row and then left for a sibling is still not marked.

## What works now

Read from the cases, built through the store, `MessageItem::from_row` and `apply_threading`
with `Showing::Messages`:

- A, B and C of one conversation, nothing read, the cursor on A and B chosen in A's window:
  `what_reading_may_mark` answers B, where it answered nothing before; with the cursor moved to
  C it still answers B; with B already read it answers nothing.
- B's reading begun with no conversation, as Space and the list's Enter begin one, or said to
  have begun in another conversation's window: nothing.
- B chosen in its window and the cursor moved to D, a message of another conversation: nothing.
- The four conversation-view cases of 13.2-03.1 pass unchanged, and so does
  `test_under_the_message_view_reading_may_mark_the_selected_row_alone`.

The timer, `mark_what_was_read`, asks this rule and writes the mark as before, so the row, the
list and the server are told and the folder tree's count moves. The window's Message arm passes
the conversation to `open_single_message`, which writes it beside `reading_began`; the Space
reading writes none and the timer clears it where it clears the reading, held by a reading over
the shipped source with two companions.

## Deviations from Plan

1. **[Shape] The opener takes one argument for the conversation and the way back,** a
   `FromAConversation { whose, again }`, rather than an eighth parameter beside `closed`. Only
   the window's Message arm passes either, and an eighth parameter would need
   `#[allow(clippy::too_many_arguments)]`. So the plan's grep for `opened_from_a_conversation`
   names the field, its initial value, the opener's write, the rule's read, the Space reading
   and the timer's clear, and not the Message arm, which passes
   `FromAConversation { whose: whose.clone(), again }`.
2. **[Count] Records naming the target were five, not four:** 13.3-05 added "Forward on a
   message whose text is not here says so and fetches it". Line numbers had moved too
   (`what_reading_may_mark` at `:998` rather than `:949`, the opener at `:16242`, the Message
   arm at `:30172`, the Space write at `:4261`, the timer at `:13221`); everything the plan
   cited was found by its text.
3. **[Measure] "Running the whole library."** Both new records name the target as their suite,
   which is what `scripts/guards.sh` runs; each break was also run against the whole library
   by hand, and nothing in it went red.
4. **[Wording] The reading names a site** by the nearest function signature above it at any
   depth and the line itself, since the Space closure sits in a method of `impl WxMailApp` and
   the nearest top-level function above it is unrelated.
5. **[Brief] Three read-only commands carried a do-nothing shell assignment named after a
   banned tool** (`awk_unused=`, `sed_never=`, `sed_x=`), the slip 13.3-11 and 13.3-12
   recorded. No sed or awk ran; every tracked file was changed with Edit, by `cargo fmt`, or by
   `scripts/guards.sh`, and each break was taken and undone with Edit.
