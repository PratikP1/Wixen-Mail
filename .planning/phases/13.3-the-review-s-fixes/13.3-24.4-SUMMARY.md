# Phase 13.3 Plan 24.4: A partial CardDAV answer is asked for again Summary

After a CardDAV answer that is not whole, because the server stopped at its own limit or some
cards could not be read, the address book's change marker now stays where it was, so the next
sync reads the address book again and the contacts it left out arrive once an answer holds
them. A whole answer still writes its marker, and an unmoved marker still skips the read.

## What works now

- `sync_carddav_address_book` writes `seen.ctag = marker_now` and saves the address book only
  inside `if arrived.is_whole() {`, after `take_off_who_a_whole_answer_left_out`. The block's
  comment says why, and keeps the old comment's point about a read that failed.
- Three cases, red first in `ad03fbd8`:
  `test_an_answer_the_server_stopped_short_leaves_the_change_marker_where_it_was`,
  `test_an_answer_with_a_card_that_could_not_be_read_leaves_the_change_marker_where_it_was`
  and `test_the_cards_past_a_servers_limit_arrive_at_the_next_sync` (two syncs, the second
  given the address book read back from the cache, the server's marker unmoved between them).
- `application::carddav_sync` holds 24 tests, 21 before this plan (20 on `0aff0451`, one
  added by 13.3-18). `service::carddav` is unchanged.
