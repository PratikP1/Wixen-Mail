# Phase 13.3 Plan 24.8: A locked session leaves the clipboard tests out

On a locked Windows session, a run of `scripts/check.sh` that reaches
`a_passphrase_box_takes_a_real_paste` now leaves out its four tests that need the clipboard, by
name, and says so: the target, the four names and that CI's Test Suite runs them, where it
happens and at the end of its closing line. A red commit naming one of them is refused there
before anything runs. Unlocked, or when the lock cannot be read, the run hands cargo exactly
what it did before. A reading in `tests/a_locked_key_asks_for_its_passphrase.rs`, red first,
holds the list to the code, with two guard records.

Branch `13.3-24.8-a-locked-session-leaves-the-clipboard-tests-out`, cut from `main` at
`404fc358` (13.3-24.7's merge), not merged (merge train: a merger merges it after 13.3-24.7,
which is already on `main`) and not pushed, since nothing the program says or shows changes.

## What works now

- `python -I scripts/session_lock.py` printed `unlocked` on this machine at the proof below. It
  asks `WTSQuerySessionInformationW` with `WTSSessionInfoEx`, the question the paste target
  asks, and its rule for Windows' answer is six worked examples, run by the check suite with
  `python -I -m doctest -v` and counted from its "6 tests in 3 items." line.
- `check.sh --what-a-locked-session-leaves-out locked --all-targets --no-fail-fast` answers
  `-- --exact --skip test_a_pasted_passphrase_is_taken_and_ok_hands_it_back --skip
  test_the_paste_reading_sees_a_field_that_refuses_one --skip
  test_a_clipboard_held_throughout_is_refused_naming_the_window_that_held_it --skip
  test_a_clipboard_held_briefly_is_waited_for`; the same for `--test` with the target; nothing
  for other targets, for `unlocked` and for a lock not said.
- The proof on the real target, unlocked, with those words: `cargo test --test
  a_passphrase_box_takes_a_real_paste -- --exact --skip ...` read `test result: ok. 7 passed;
  0 failed; 0 ignored; 0 measured; 4 filtered out`.
- On a locked session the run prints "-- the session is locked, so the tests that need the
  clipboard do not run here", the reason, "CI's Test Suite runs them on every push and pull
  request", the target and the four names, and its closing line ends "; left out because the
  session is locked: 4 tests of a_passphrase_box_takes_a_real_paste, which CI's Test Suite
  runs". Each mode's closing words gain one sentence saying the same. Seen through the check
  suite's stand-in `python` and `cargo`; no real locked hook run has reached it yet (ledger 956).
- A red naming one of the four on a locked session is refused with "This red commit names tests
  that need the clipboard: ... and Windows says this session is locked. A test that cannot run
  neither passes nor fails, so this red cannot be judged here. Unlock the session and commit
  again. Nothing was run." The stand-in `cargo` saw no call.
