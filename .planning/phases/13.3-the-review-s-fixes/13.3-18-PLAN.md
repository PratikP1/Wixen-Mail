<objective>
Keep an edit or a deletion a person makes to a contact while a sync is sending it, and keep
contact names out of the log.

Purpose: when Google or Outlook has made a contact typed here, the sync writes down the copy it
read before the network call with its new name and the waiting flag cleared. An edit made in
the meantime is written over and never sent; a contact deleted in the meantime is put back,
and stays at Google too (item 23). 13.2-17 made that create run on every sync, and a vCard
import makes it run for minutes, one contact at a time. 13.2-20 fixed the same race for tasks
and notes; contacts were left out. The Contact Manager has a second half of it: it saves from
the copy it opened, so a contact made at Google while the window was open loses that name and
is made again. And a refused create writes the contact's name into the log on every sync,
where every other sentence in the module uses the id (item 25). Pratik answered yes to both
on 2026-10-20.

Output: the store's one transaction, the six places that write a contact down after an address
book answered, the Contact Manager's re-read, the two sentences, the cases, the changelog, the
ledger rows, the four marks. Nothing is spoken or shown, so the branch is not pushed.
</objective>
