1. **[Brief] ctutils moved as well, and the held-open list emptied in the same commit.** The
   plan was written for two crates before RUSTSEC-2026-0385 was published. The brief carries
   Pratik's yes of 2026-10-23 to ctutils 0.4.4 and the instruction to take all three ids off
   `scripts/audit.sh`'s held-open list in the commit that moves the lock, so `scripts/audit.sh`

   13.3-20 held the ids open, and with them held open the audit exits 0 on the unchanged lock.
   Emptying the list first is what made the run say what CI's plain `cargo audit` says.
3. **[Brief] The clipboard target was not run alone first.** The brief forbids running by hand
   what the commit's hook runs; the hook's whole suite ran it, green.
4. **[Brief] Not merged and not pushed.** This run is a merge train, so the plan's `git merge
   --no-ff` is the merger's. Nothing a person sees or hears changes but a changelog line, so
   the branch is not pushed (decision 4).
5. **[Found] Seven warnings in the same run, none failing it.** Besides the three ledger 357
   named in 2026-09, the plain run now prints zvariant, zbus_names and zvariant_derive
   unmaintained (RUSTSEC-2026-0370 to 0372) and tokio 1.53.1 unsound (RUSTSEC-2026-0386,
   against `tokio::io::unix::AsyncFd::new`, patched in 1.53.3). Recorded on ledger 357 in both
   halves, not acted on: moving tokio is a package change that waits on Pratik.
6. **[Ledger] Row 914's fix is written in its description as the plan asks and in `reason` as
