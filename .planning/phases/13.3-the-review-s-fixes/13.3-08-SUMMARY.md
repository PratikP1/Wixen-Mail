# Phase 13.3 Plan 08: The download leaves new mail for the check, and a filed message is held only where it is

Mail that arrives while the download of everything runs is left for the next check, which runs
the account's rules over it and says it arrived, and no folder is called stopped because of it
(review item 9). A message a rule files, or a replayed move settles, is held at a number only
once the message there carries its Message-ID; one with no Message-ID is never searched for and
comes back once from the next read (review item 8).

## What was done

- **Task 1, red then green (tracer).** `mail_sync::uids_a_download_takes`, a sibling of
  `uids_to_fetch` sharing its split through `missing_above_and_below_the_newest_held`, answers
  the newest `limit` missing below the newest held and how many above it it left.
  `sync_folder` matches on what it is for: a check keeps `uids_to_fetch`, a download chunk takes
  the sibling's answer and reports `FolderSync::left_for_the_check`.
  `bringing_everything_down::how_much_a_chunk_left_here(&FolderSync)` takes what was left off
  the server's count, never below what is held, and the runner's chunk arm in
  `start_the_download` sets `entry.here` through it. Red at `ae65c371`, green at `f6526c72`.
- **Task 2, red then green.** `settle_a_moved_row` lets a row with a blank Message-ID go before
  any search, and reads the one number found with `the_identifier_at`, keeping it only when
  `renumbered::the_number_confirmed` answers it. `where_it_is_now` answers `NotThere` for a
  blank identifier before any search. Both guards go through `carries_no_message_id`, whose
  comment names RFC 3501's empty search. Red at `81329ad0`, green at `e00383cc`.
- **Task 3.** The changelog entries and the dated correction of 13.2-08's entry; ledger 925 and
  row 850's dated sentence in both halves with the header counts; the dated lines and
