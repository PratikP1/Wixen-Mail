Prove the whole folder-writing architecture on one path: a user creates a folder
called `Entwürfe` on an IMAP account, from the keyboard, and it appears in the tree.

This is the phase's tracer. It touches every layer the phase will modify —
presentation command, application routing, application facade, service verb,
wire encoding — and carries a real end-to-end check. Nothing else in this phase
is built until this path works, because if the shape is wrong it is wrong here,
after one commit, rather than after ten.

first one and everything around it, so plan 01-04 adds its two verbs to a proven
path instead of inventing one each.

`MailController::create_mailbox`, `ID_NEW_FOLDER` and its handler, two guard
records, a changelog entry.

## Waves, and why this phase is mostly sequential

Thirteen plans, thirteen waves. Two shared files make genuine parallelism
dishonest here rather than merely awkward: `guards/guards.toml`, which most plans
append a measured record to, and `docs/changelog.md`, which every user-visible
change must touch in the same commit under CLAUDE.md. `src/presentation/wx_app.rs`
is touched by most plans too. Same-wave plans must have zero `files_modified`
overlap, and these three make that impossible for any pair worth running together,
so the wave numbers encode order rather than opportunity.

The dependency chain is real in its own right. The `thread_id` producer (01-02)
must land before anything reads a thread id, which is four later plans. Nesting
(01-03) must land before the tree renders it (01-05) and before the depth-first
delete walks it (01-04). The tree (01-05) must exist before favourites hang on it
(01-08) and before a folder can be shown as gone (01-10).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → folder name → IMAP command | A name typed by a person is interpolated into a protocol command sent to a server. |
| application → `Allowed::mail` → server | The only thing standing between a new install and a write to somebody's mailbox. |
| server → error text → log and screen | A server's own words reach a log file and a screen reader. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `ImapSession::create_mailbox` argument | high | mitigate | The name goes through `async-imap`'s `validate_str`, which quotes it and rejects `\r` and `\n`; a newline is the only way to start a second command.
