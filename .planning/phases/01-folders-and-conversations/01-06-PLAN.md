<objective>
Three things that belong together: the order accounts sit in, the way a parent
counts its unread, and the settings machinery that every later plan in this phase
hangs a setting on.

D-24 is the first of the five settings this phase adds. CONTEXT.md is explicit
about why that matters: a setting the model holds and no screen writes is
FEEDBACK-01, sitting in Phase 6 because it has already happened here once. Ten
settings were once found with a real labelled control that saved, survived a
restart, and were read by nothing. The guard written for that walks every shipping
file except `config.rs` and `wx_settings.rs`, by name, with a stated reason — so
it catches a setting that is offered and ignored, and is structurally blind to one
that is stored and never offered. That blind spot is exactly the risk of adding
five settings at once, and D-43 closes it.

Each of this phase's five settings lands in the same plan as the code that reads
it, so neither guard is ever red between plans.

Purpose: roadmap criterion 3, the second half of criterion 2, and criterion 8's
machinery.

Output: an account order, the D-24 setting end to end, the group constant, and the
mirror guard.
</objective>

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-23 | Denial of service | A settings file that no longer parses | high | mitigate | `#[serde(default = "...")]` on every new field, which is why an existing file keeps working. `test_a_settings_file_written_before_directories_existed_still_reads` exists because this has been a real failure, and this plan adds its own older-file test. A settings file that fails to parse takes the whole application's configuration with it. |
| T-01-24 | Tampering | A hand-edited settings value outside the two options | low | mitigate | The choice is read back by the words shown and an unrecognised value falls to the default rather than to an arbitrary branch. A test feeds an unknown string and asserts the default. |
| T-01-25 | Spoofing | A reorder reaching a server | medium | mitigate | D-14 and FOLDER-03 both require that ordering and pinning never write to a server. Task 3 adds a call-counting test and a guard record whose break routes it through the network, so the rule is measured rather than written in a comment. |
| T-01-26 | Repudiation | A setting stored and offered by nothing | medium | mitigate | The D-43 mirror guard, taken red once against a deliberately added field. Its absence is the FEEDBACK-01 shape this project has already hit. |
