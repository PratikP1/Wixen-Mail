<objective>
Pin a folder to the top of the tree.

FOLDER-03's stored shape carries a constraint beyond making pinning work: it must
let IMAP subscription back it later without a migration, and which of the two wins
when they disagree has to be recorded as a decision **before** the second half is
built, not settled by whichever code path runs last. A local pin and a server
subscription are two answers to one question, and this project has been bitten by
that shape before.

D-30 makes pinning a copy: the folder stays in its account branch, so unpinning
cannot lose anything and the tree the user learned does not change under them.

Purpose: FOLDER-03 and roadmap criterion 5.

Output: a pure favourites module, a table keyed by the same identity the tree uses,
the group at the top, pin and unpin commands, and the recorded decision.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → pin → stored identity | A keyboard action writes an identity string as a primary key. |
| local pin ↔ future server subscription | Two stores that will one day answer the same question. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-32 | Spoofing | A pin reaching a server | medium | mitigate | FOLDER-03 and D-30 both forbid it. Task 3 counts calls and a guard record breaks the rule, so it is measured rather than asserted in a comment. Pinning must not consume a server write quota or reveal interest in a folder. |
| T-01-33 | Tampering | A pin surviving a folder's real deletion and pointing at a new folder that reuses the path | medium | mitigate | D-32: a real deletion takes the pin. The pin is removed in the same operation that deletes the folder, not lazily, so a later folder created at the same path is not silently pre-pinned. A test drives delete-then-recreate and asserts no pin. |
| T-01-34 | Repudiation | A local pin and a server subscription disagreeing later | medium | mitigate | The decision about which wins is recorded in task 1, in the module doc comment and in the Key Decisions table, before the storage shape is fixed. FOLDER-03 requires this explicitly and names the reason. |
| T-01-35 | Denial of service | An unbounded pin list | low | accept | A pin is one short row written by a deliberate keyboard action; a user cannot realistically create enough to matter, and the group is built in one pass over a set already in memory. |
</threat_model>
