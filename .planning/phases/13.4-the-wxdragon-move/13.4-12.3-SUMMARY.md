# Phase 13.4 Plan 12.3: Questions that say what each answer does Summary

Every question Wixen Mail asks with two answers now goes through `asking::ask`, which opens
Windows' own task dialog with two buttons named for what each does (Delete and Keep, Run and
Don't Run, Send Anyway and Back to the Message), Enter on the answer it gave before except in
the Calendar window, and Escape and Alt+F4 closing it with nothing done.

## What works now

- **The table.** `asking::answers` gives each of the 22 questions its two labels, and
  `asking::enter_gives` its Enter: the second answer on nineteen, the first on Run a Rule (a rule
  that does not delete), Move the Mail a Block Catches and Send Despite Spelling. No box gives one
  letter to both buttons, and no button takes `G`, which 13.4-12.4's check box takes; the test
  that holds that plants a shared letter, a `G` and a missing letter and sees each.
- **The box.** `asking::the_box` is the task dialog's configuration as data; `asking::show`
  disables every other shown window of the thread through a value whose drop enables them again,
  builds `TASKDIALOGCONFIG` by value, and reads the button through `answered_from`, so `IDCANCEL`
  or a failed call is `Answered::Neither`. `asking::ask` takes the owner as the top-level window
  of the window asking when it is shown. Off Windows it falls back to wxWidgets' message box
  relabelled; nothing this plan runs compiles that branch (`.github/workflows/other-platforms.yml`
  runs only when dispatched).
- **Every call site moved.** 22 questions in seven files, read with Python over each asking
  function's body: `asking::ask(` once in each, `show_modal` and `MessageDialog` in none. The
  conversation delete and Empty Folder pick one of two questions each; the rule picks
  `RunARuleThatDeletes` where `enter_answers_yes` is false. The hand-built Confirm Delete in the
  Calendar window and its builder are gone, with `theme_reach.rs`'s check of it.
- **The two sentences.** The folders question ends "The mail cached in it goes with it." and
  "... in them goes with them.". The decorative question reads "Mark as Decorative sends it with
  no description at all ..." and ends "Describe It is what Enter does.".
- **The readings.** Every source reading of premise 6 reads `asking::ask(`, `Answered::Yes` or
  `Question::<Variant>` and keeps a planted wrong shape. House style's Enter check reads twice:
  the calls and flags that put two answers on a box anywhere but `asking.rs`, and a Yes or No
  label in shipping code under `src`, comments aside, with planted proofs of both. A new census,
  `tests/every_question_is_asked_by_something.rs`, holds every variant named in shipping code.

## Deviations from Plan

1. **[Rule 3] The window test opens its box on a desktop made for the run.** The tracer's first
   green was refused by two censuses in `tests/a_locked_key_asks_for_its_passphrase.rs`: every
   target that posts a key must make a desktop for its run and set the modifier keys. The plan did
   not name them. The reader makes the desktop and moves its own thread onto it, since window
   messages pass only between threads on one desktop, and the window process moves there and
   clears its modifiers before the box opens. Two window-target records were measured again.
2. **[Rule 3] `tests/wired.rs`'s shared-letter check reads `asking::answers` at run time.** It read
   the table's 22 boxes as one dialog and called Delete and Don't Move a clash. `answers` joins
   `build_account_edit_dialog` in `READ_AT_RUN_TIME_INSTEAD`, with the reason; its letters are
   judged box by box in `asking.rs`.
3. **Two processes, not three.** The window process runs no wxDragon, so the test process can be
   the reader; nothing needed a third.
4. **`TheBox` holds two flags, not three.** Placing the box on its owner depends on the owner,
   which `the_box` does not see, so `show` decides it, as wxWidgets does.
5. **The census is a new file**, `tests/every_question_is_asked_by_something.rs`, rather than a
   test in a file records count, so no record was flagged for it. `tests/house_style.rs` gained no
   test function.
6. **The tracer gate ran in its autonomous form.** The tracer's verify, the window test and the
   unit tests, passed through the hook at `5e9ae964`; no checkpoint was raised, under the merge
   train's brief.
7. **The guard runner stopped once.** The sixth of sixteen records left its break in `asking.rs`
   with `OSError(22, 'Invalid argument')` on the put-back (row 927's error, again). The stop worked;
   the line was put back by hand and compared with `cmp` against the kept copy. `--resume` then
   refused the plan's own uncommitted edits as a break, so the sixteen were measured again from
   the start. Ledger 976.
8. **Tests that pass at red, as the plan expected:** the Enter table, the split, the read-back, the
   chooser, the letters (Y and N already differ and are not `G`) and the census of `ALL`, which was
   taken red by hand once by listing one variant twice. Each lib one is held by a record whose
   break reddens it.

9. **`Alt+F4` joins wired's list of keys bound outside this source.** The documents commit's
   first try was refused by `test_the_shortcuts_document_names_no_key_the_code_has_never_heard_of`,
