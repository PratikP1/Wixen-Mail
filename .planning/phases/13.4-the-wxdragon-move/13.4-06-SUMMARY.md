# Phase 13.4 Plan 06: The main tick never runs inside itself

The main window's tick no longer opens a window from inside its own handler. The seven windows
it can open now go to `presentation::after_the_tick`, a queue on the interface thread drained by
a `call_after` closure that captures nothing, so each opens a moment after the tick returns, one
at a time, while the tick goes on running beside it. At wxDragon 0.9.17 this changes when the
windows appear and nothing else; at 0.9.23, which skips a handler called inside itself, it is
what keeps mail, sync and send results and reminders handled while a reminder sits open. A live
test over the real Due now window and five readings of `wx_app.rs` were red first and pass.

## What was done

- **The queue.** `after_the_tick(work)` pushes onto a thread-local queue and, when no drain is
  waiting, queues one with `wxdragon::call_after(Box::new(drain))`. A drain that finds another
  running returns at once; the running one takes each piece with the queue's borrow released
  before it runs it, until the queue is empty. A guard clears the running flag however the drain
  ends and queues another drain if a panic left work behind. No `unwrap` or `expect` in the
  module (`git grep -n "expect(\|unwrap()" -- src/presentation/after_the_tick.rs` names nothing).
  Three unit tests beside it: work waits for the drain; work handed on while a piece runs waits
  for that piece (the modal case, with a nested drain); a panicking piece does not stop the queue.
- **The seven windows.** Each decision stays in the tick and only the window and what follows its
  answer move into the queued work, with owned copies:
  - `raise_what_is_due`: the turn is taken, the rows marked and said, then the window and its
    answers are handed on with the turn; the answers are written by
    `write_down_what_was_answered`, the old loop moved unchanged.
  - `ask_about_the_folders_that_have_gone`: the turn, the decision and `.raised(` stay; the
    question and its answer are handed on with the turn.
  - `AnUpdateDidNotHappen`: still only for a check asked for by hand (13.3-23); the status line and
    announcement stay, the dialog and the browser are handed on.
  - `AnUpdateIsReady`: the dialog and everything after it are handed on; Yes still quits through
    `really_quit` alone (13.3-24).
  - `ARuleWasCounted`, `KeyAttachmentOffered` and `WhatABlockCaught`: the whole call handed on.
  `git grep -n "after_the_tick(" -- src/presentation/wx_app.rs` names seven lines, one in each
  place, and no other.
- **What carries the turn and the rest.** `OneAtATime` shares its cell through an `Rc` and `Turn`
  owns a clone, so a turn can leave the function that took it; the look's `BetweenLooks` is an
  `Rc`; `UpdateTargets` hands the arms `&Arc<Accessibility>` and `&Rc<Cell<bool>>` for the Quit
  flag, so a queued arm can clone them.
- **Comments.** The ones that said the tick runs inside these windows (`wx_app.rs` at the folders
  question's gate and `.raised(`, the look's gate and marking; `one_question_at_a_time.rs` at
  `raised` and in one test; `due.rs` at `OneAtATime` and its test; three in `tests/wired.rs`) now
  say the tick keeps running while the window is open. Read again with Python joining each line
  with the next, markers stripped: the remaining hits are the new sentences and the ones that stay
  true, a command's own dialog (`wx_app.rs:6727`), the composer and item editors
  (`wx_app.rs:13965`, `one_question_at_a_time.rs:323`), the scan's modal loop (`wx_app.rs:20969`)
  and the editor inside the Due now window (`wx_reminder_alert.rs:768`).

   rule and the key, and the fourth reading covers it.

   new case, since nothing it does changed, and a case for "a turn can move into a 'static

   "everything from the window to the end of the function" into the closure; the loop that writes
   the answers became `write_down_what_was_answered`, byte for byte, and the closure calls it.
