# Phase 13.4 Plan 07: The automatic save has a timer of its own

The message window's automatic save now runs on a timer of its own. The composer hands its save
to `wx_compose::save_on_a_timer_of_its_own`, which makes a repeating timer on the message body
with the save as its own handler, at the interval the setting gives. At wxDragon 0.9.17 its ticks
reach only that handler, because the message body owns no other timer; at 0.9.23 a timer reaches
only the handler bound to its own id. So the save keeps happening on its own after the move, and
it no longer starts a spelling check, a look-up or Send Later's question early. The window's
other timer, `later`, lost the arm that saved when nothing was waiting and the clock it kept for a
save that came due during other work. A live test of the timer and four readings of the composer
were red first and pass.

## What was done

- **The timer.** `save_on_a_timer_of_its_own(owner, every, save)` makes the timer on `owner`,
  binds `save` with `on_tick`, and starts it repeating. The milliseconds go through
  `i32::try_from`; an interval that does not fit is held at `i32::MAX` and logged, and a timer
  that will not start is logged. Its doc says why the owner is not the window, with the two
  versions' `timer.rs` lines.
- **The composer.** `_autosave_timer` became `autosave_timer =
  autosave.interval().map(|every| save_on_a_timer_of_its_own(&body_editor, every,
  save_draft_now))`; `save_draft_now` moves into it, since nothing else calls it now. The stop
  before the window goes stays.
- **`later`'s handler.** `saved_at`, `save_every`, `keep_the_message` and the clock check are gone;
  the empty arm is `Some(Deferred::AnAnswerToASearch) | None => {}`, with the answer-polling arm
  above it as a guard (decision 2).
- **Comments.** The five of premise 7 rewritten: above `save_draft_now`, above `later.on_tick`, the
  clock's comment (removed with the clock), the `None` arm, and above the save's timer, which also
  lost a duplicated two-line paragraph. A sixth, the stop's "Both are owned by it", now says which
  timer each part owns. Read with Python joining each comment run with its markers stripped: the
  one hit for "reaches every handler" is the new comment explaining 0.9.17, not a claim that one
  handler serves the window.
