<objective>
Bridge the `log` crate into Wixen Mail's log file and let wxDragon's warnings and errors through,
so what the window toolkit reports about itself is written down rather than dropped.

Purpose: wxDragon 0.9.23 reports two new things through the `log` crate, a handler call it
skipped because the handler was already running and a panic it caught in a callback from C++, and
0.9.17 already reports a few more, such as a tree item it refused. Wixen Mail's logger keeps only
this crate's records and installs no bridge from `log`, so every one of them is lost today, and
after the move a session could go on running with an empty name or a skipped update and leave no
trace. Guardrail 9 asks that an upstream failure the program papers over is said, not swallowed.

Output: the filter and the bridge, a unit test and a live test that were red first, the idle
run's count, the alpha page and the changelog, LIST-02's dated line, the guard records, and the
completion marks.
</objective>
