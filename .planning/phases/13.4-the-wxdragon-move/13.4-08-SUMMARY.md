# Phase 13.4 Plan 08: The toolkit's warnings reach the log Summary

wxDragon's own warnings and errors, which it writes through the `log` crate, now reach Wixen
Mail's log file at every level, because `init_logging` installs its subscriber with `try_init`,
which installs tracing-log's `LogTracer`, and `filter_for` admits `wxdragon=warn` beside this
crate; no other library's lines are written.

## What works now

- `filter_for(level)` answers `wixen_mail=<level>,wxdragon=warn` for all five levels.
- A real wxDragon warning lands in the file. The live test's run after the green, read once with
  `--nocapture` to quote it:
  `2026-10-25T04:27:48.287677Z  WARN wxdragon::widgets::treectrl: Warning: C++ returned invalid TreeItemId pointer 0x22f1c1c75c0, rejecting`.
  Target `wxdragon::widgets::treectrl`, from asking an empty tree for its selection. In the
  same run a `tracing` warning under `some_library` and an info line under a `wxdragon` target
  were not in the file.
- `logging.rs`'s tests still number 12 (`cargo test --lib common::logging::` at the red: 11
  passed, 1 failed).
- `main.rs` reaches the change: its one call to `init_logging` (`main.rs:119`) is the one the
  live test exercises.
