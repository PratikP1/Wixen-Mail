# Phase 13.4 Plan 12.4: A question somebody stopped Summary

Every question Wixen Mail asks with two answers now carries Windows' own "Don't ask me again"
check box, `Alt+G`, unticked when it opens; ticked with the answer the question remembers it
stops that question, which then goes ahead with no window and says what it did, and an eighth
Settings tab, Questions, brings any stopped question back.

## What works now

- **The box.** `asking::the_box` gives every one of the 22 questions the verification text
  "Don't ask me a&gain", left unticked (`TDF_VERIFICATION_FLAG_CHECKED` is never set), and
  `asking::show` answers `Shown { answered, ticked }` from `TaskDialogIndirect`'s fourth argument,
  whichever way the box closed.
- **The rule.** `remembers` answers the first answer for 21 questions and `No`, Describe It, for
  `MarkAPictureDecorative`. `what_to_remember(question, answered, ticked)` stops a question only
  when it is ticked and the answer is the one it remembers; Keep, Escape and an unticked box stop
  nothing. `answered_without_asking` answers the remembered answer for a stopped question.
- **`ask`** reads the stored settings once, returns the remembered answer with no window for a
  stopped question, and otherwise shows the box and, on a stop, writes it to the settings read
  again (`keep_the_stop`). A stop that cannot be read or saved is logged with the question's name
  and the question is asked again next time. `stop_asking` turns `check_spelling_before_send` off
  for the spelling question and adds every other question to `questions_not_asked`.
- **The setting.** `AppConfig::questions_not_asked`, `#[serde(default)]`, a `QuestionsNotAsked`
  stored as a list of each question's stored name; a name this build does not know is passed over
  with a warning rather than failing the file.
- **Settings, Questions.** An eighth tab after Advanced, built the first time it is shown from the
  stored set read then: a line saying what the boxes are, 21 check boxes "Ask before ..." in
  `Question::ALL` order with premise 5's letters, each named on both channels, in a scrolled list,
  and a line saying the spelling question comes back on General. At OK the set stored now is read
  again and only the boxes the person changed are applied (`QuestionsNotAsked::with_changes`).
- **Opening the releases page** says "Opening the releases page in your browser." on the command
  topic and in the status bar once the answer is Yes, before `open::that`, and still says when the
  browser does not open.

## Deviations from Plan

1. **[Rule 3] The check box is not a window of its own.** Premise 9 left it open; the probe of
   2026-10-25 found the box's only `Button`-class windows are its two buttons, and the check box is
   a part of the dialog's `DirectUIHWND`. The reader gives it the keyboard with
   `TDM_CLICK_VERIFICATION` (`wParam` 0, `lParam` 1) and reads it there: on MSAA as the check
   button in that window's tree, its state saying focused, because `get_accFocus` answered an
   empty VARIANT from another process; on UI Automation as the element with the keyboard, read by
   asking every element, because a property condition needs a VARIANT feature the `windows`
   dependency does not carry. The red commit's version of this case looked for a `Button` window;
   it failed then, as named, and the green reads it where it really is.
2. **[Rule 1] The save's merge is in `show_settings_dialog`, not `handle_settings`.** Applying the
   page's changes in `read_settings` against the copy taken at open and then again in
   `handle_settings` against the set stored now loses a box ticked back on for a question stopped
   between opening Settings and building the page. So the merge happens once, against the set read
   again at OK with the set the page was built from, the moment before the window saves;
   `SettingsResult` stays as it was.
3. **[Rule 2] The 21 boxes are in a scrolled list.** They are taller than the 560 by 520 dialog,
   and a box out of sight is one somebody moving by keyboard cannot see they are on.
4. **[Rule 3] The Questions target shows Settings on a desktop of the run's own.** A box in a
   hidden dialog cannot be given the keyboard, so the window process shows it on a desktop made
   for the run and the reader moves onto it, as the other window targets do.
5. **[Rule 3] `tests/the_settings_dialog_opens_in.rs` counts eight tabs** and times Questions'
   first visit; it was not in the plan's files.
6. **[Rule 3] `remembers` has a wildcard arm.** The first red try was refused by
   `test_every_guard_record_still_names_one_place_in_the_tree`: an exhaustive list of the other 21
   repeated the anchor of "a deletion that cannot be undone does not let Enter answer Yes". A
   question added later remembers its first answer, which is its call site's go-ahead.
7. **[Rule 3] The Questions page's boxes are built in a loop pushing into the list.** The first
   green try was refused by `test_no_settings_control_is_built_and_then_forgotten`, which reads a
   control pushed into a list handed back and not one collected from a closure.
8. **The frozen record's run hung.** "the settings dialog is frozen while its pages are built"

   once the frozen test fails inside its `wxdragon::main`. The binary was stopped by its id and the
