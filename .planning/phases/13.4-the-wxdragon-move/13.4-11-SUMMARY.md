# Phase 13.4 Plan 11: The smaller workarounds Summary

The manager dialog check compares a list cell whole, the Enter-does-not-answer-Yes flag is the
binding's own `NoDefault`, and leaving the composer's message body is one function a live test
holds to its direction both ways.

## What works now

- `tests/manager_dialog_labels.rs`: `a_cell_holding` and its doc are gone. The condition row is
  compared as `message_text != Some(second_row.as_str())`, so a field with no words, `None`,
  cannot pass for an empty row. Taken red by hand with `populate_questions` writing the stored
  field name into the row's first cell: "a condition row about the message text: reads
  "body_plain" rather than Some("Message text"), the words the editor's own list offers", the one
  test failing on that line alone. Undone.
- The two `LVM_GETITEMTEXTW` readers keep their code. Their docs now say they read the text the
  native list holds, which is what a screen reader is given for the row, rather than what the
  binding reports.
- `src/presentation/asking.rs`: `ENTER_DOES_NOT_ANSWER_YES = MessageDialogStyle::NoDefault`
  (0.9.23's `message_dialog.rs:26`, `NoDefault: ffi::WXD_NO_DEFAULT`). The doc says the binding
  names the flag and this project calls it by what it does; the assert comment names `NoDefault`;
  the labels sentence says the binding can now set button labels and this module keeps Yes and No.
  `house_style.rs`'s two checks on the module are untouched.
- `wx_compose::leave_the_message_body(body: &WebView, back: bool)` carries the arm's comment,
  shortened, naming upstream #248 as what would flip it; the timer arm calls it. 0.9.23's
  `window.rs:2002-2014` still passes `WXD_NAVIGATION_NEXT` (0) for `true`, which wxWidgets reads
  as backward.
- `tests/tab_leaves_the_message_body_both_ways.rs`: one live test builds the real composer with
  `build_compose_dialog`, shows it, sets a page, waits for the browser's `on_created`, puts the
  keyboard in the body, settles ten ticks of 30 ms, and calls the function each way. Run by hand
  with `--nocapture`: "leaving forward: Save Draft", "leaving backward: the Subject line", 1
  passed. With the argument swapped inside the function: "leaving forward landed on the Subject
  line, not Save Draft" and "leaving backward landed on Save Draft, not the Subject line". Save
  Draft is the next control because the attachment line is static text and the attachment list is
  hidden until a file is attached; the Subject line is the last field made before the body.
