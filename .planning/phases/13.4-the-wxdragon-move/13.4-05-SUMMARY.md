# Phase 13.4 Plan 05: Every window test ends its loop on the thread that owns it

Every test that opens a live window now ends its event loop by asking for the application
inside the queued closure, `if let Some(app) = wxdragon::get_app_instance() { app.exit_main_loop(); }`,
instead of capturing the one `wxdragon::main` handed it. That is what wxDragon 0.9.23 needs,
because the application object is no longer `Send` there, and at 0.9.17 it changes nothing:
every one of the 69 targets passes at the count it had before. A new reading,
`tests/every_window_test_ends_on_the_thread_that_owns_it.rs`, was red against all 72 sites
first and refuses the old shape until the move makes the compiler refuse it. Nothing a person
sees or hears changes, so the branch is not pushed.

## What was done

- The reading: for each `wxdragon::main(` closure in each file under `tests/`, its parameter's
  name, then every `wxdragon::call_after(` closure inside it that names that parameter without
  binding the name itself, reported as `file:line` with the shape to write instead. Its bracket
  matcher steps over string, raw string and character literals and line comments. It skips its
  own file by name, since its planted text holds the shape. Two companions: the old shape in
  both forms and inside a timer handler is refused at the right line; a closure that asks for
  the application itself, with or without the outer parameter still named, is accepted.
- 72 sites in 69 files changed by hand with Edit: 62 of the block shape and 10 of the
  expression shape. 70 of the 71 `wxdragon::main` closures now take `_`, keeping `move`.
  `the_page_window_keeps_the_document_focused_when_it_comes_back.rs` keeps `app`, which its
  error path still uses directly on the main thread. The five closures that never named the
  application were not touched. No test was added, removed or renamed, and no assertion moved.
- One guard record, "a window test's queued ending asks for the application rather than
  capturing it", with its break in `tests/tree_selection_raises.rs`.
- Ledger 962 opened.

## Deviations from Plan

1. **[Rule 3, gate] Both halves in one green commit.** Premise 9 said the hook in `red` "runs
   what the commit names". It does not: it runs what reaches the staged files and then requires
   the named test to have run. The first half stages none of the reading's file, so
   `red-commit.sh` refused it: "test_no_window_test_hands_the_application_to_call_after was
   named as failing and never ran." The only ways to a red commit there were to stage an edit
   to the reading made for the gate's sake, or to add an unmeasurable record, and the record
   coupling would not have helped either (deviation 3). So the first half, already staged and
   with its targets passing, went into the green beside the second half. The resilience the
   split bought, a committed half if the context were lost, was not needed in the event; the
   red commit `22888e89` still stands as the reading's red.

   green, it said the record runs the reading on a commit changing its file. The green's own
   hook list showed it does not, which is ledger 962; the documents commit says so instead.
   The green's commit message carries the same wrong sentence and was not amended.
3. **[Found] The gate skips a changed test file when it reads the guard couplings**
   (`the_suites_that_guard_what_changed`, `case tests/*.rs) continue`), so no record makes a
   test-file change run another target. Ledger 962.
4. **[Order] The record was measured with both halves on disk before the green commit,** as
   13.4-01 to 13.4-04 measured before theirs.
5. **[Merge train] No merge here.** The plan's task 3 merges; under the train a merger merges

6. **[Marks] Three, not four.** `requirements` is empty: no requirement covers test plumbing,
