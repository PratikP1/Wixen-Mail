# Phase 13.4 Plan 12.1: A Test File's Guard Records Reach Their Suites Summary

**The commit gate now runs a guard record's suite when the record's file is a test file and the
suite is another target: a commit changing `tests/tree_selection_raises.rs` runs
`every_window_test_ends_on_the_thread_that_owns_it`, and one changing
`tests/a_passphrase_box_takes_a_real_paste.rs` runs `a_locked_key_asks_for_its_passphrase`.
Ledger 962 is closed.**

## What changed

`the_suites_that_guard_what_changed` in `scripts/check.sh` used to skip every changed
`tests/*.rs` before reading the registry's couplings. It now works out the changed test file's own
target (its name without the folder and `.rs`) and skips only a coupling whose suite is that
target. Every other coupling is answered like any other file's. The comment keeps the old reason,
quoted and dated, names the two records it hid, and says why the self-coupling is still skipped:
a deleted test file stays in the staged list, and answering its own record would put its target
back on cargo's line, where cargo refuses the whole call.

The ledger's question and its neighbours, after the green:

```
bash scripts/check.sh --suites-for guards/guards.toml tests/tree_selection_raises.rs              -> every_window_test_ends_on_the_thread_that_owns_it
bash scripts/check.sh --suites-for guards/guards.toml tests/a_passphrase_box_takes_a_real_paste.rs -> a_locked_key_asks_for_its_passphrase
bash scripts/check.sh --suites-for guards/guards.toml tests/installer.rs                          -> (nothing)
```

The green's own hook list shows it: its scoped run named `a_locked_key_asks_for_its_passphrase`,
reached through the record on `scripts/check.sh`'s clipboard list as premise 7 said.
