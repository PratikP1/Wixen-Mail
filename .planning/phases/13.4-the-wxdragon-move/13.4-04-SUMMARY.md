# Phase 13.4 Plan 04: A refused draft save is said once until one reaches the server

While the mail server cannot be reached, the sentence that it would not take a draft is now said
once for each draft, and again only after a save of that draft reached the server and a later
one was refused. The first save that reaches the server after a said refusal is said once, "The
server has taken the draft, so your other devices will have the newest copy.", so it cannot be
heard as one more of the composer's "Draft saved.". On Pratik's answer of 2026-10-24, "Fold the
other items in.", a server that refuses every copy and holds none follows the same rule, and Save
Draft and Undo Send are told the server's answer every time. Ledger 941, on Pratik's yes of
2026-10-23. Pull request #222.

## What was done

- `ToldSoFar` in `src/application/draft_copy.rs`: the older-copy set, and the drafts told of
  each refusal since a save of them last reached the server, `refused_beside_an_older_copy` and
  `refused_with_no_copy_there`, with a `const` constructor for the process-wide record and
  `forget_the_refusals_of`, which answers whether a refusal had been said.
- `Filed::needs_saying_for(draft_id, told)`: `Replaced` answers whether it ends a said refusal;
  the older copy answers that or whether it is new to its set; each refusal answers whether it is
  new to its own set. The doc says each answer's rule and why `Replaced`'s sentence names the
  server.
- `Filed::needs_saying_when_asked_for`: the automatic rule for the record, then anything but an
  ordinary save said.
- `Replaced`'s sentence in `what_happened` became "The server has taken the draft, so your other
  devices will have the newest copy."
- `Save { Automatic, AskedFor }` carried by `save_as_draft`, `file_draft_copy` and
  `spawn_draft_append` to `needs_saying_once_per_draft(&draft_id, save)`: the composer's saver
  passes `Automatic`, the Save Draft answer and Undo Send pass `AskedFor`. The comment above the
  call and the doc of `spawn_draft_append` say the new rule.
- The changelog entry under `[Unreleased]`, `### Fixed`, and two dated sentences in 13.3-21's
  entry; ledger 941 fixed and 961 opened; FOUND-04's dated line, with Pratik's answer of

## Deviations from Plan

1. **[Pratik's answer of 2026-10-24] The two draft gaps were fixed here, not ledgered.** The
   answers file said "Fold the other items in." So the refusal with no copy anywhere is said
   once per draft like the other, and a save the person asked for is told the server's answer
   every time. Their cases went into the one red commit, named in its trailers; two more records
   and the changelog entry cover them; the two `todo` rows of C-2 and C-3 were not opened. The
   every-save case the plan would have narrowed was rewritten to the fold-in's rule instead,
   `test_a_draft_with_no_copy_anywhere_is_said_once_for_each_draft`.
2. **[Design] Two sets, one for each refusal,** rather than one refusal set. The two refusals
   say different things about where the copy is, so each is said once per draft, and a network
   that comes and goes cannot alternate them every minute.
3. **[Design] Undo Send passes `AskedFor`.** It always files a new draft, so both rules give
   the same answer there; `AskedFor` is the one that reads true for a person's action.
4. **[TDD exception, glue] `Save` and its passing through three functions have no case of
   their own.** The rule each value selects is held by the cases; which value each of the three
   callers passes is wiring, the exception the project allows for glue code, and a reading in
   `tests/wired.rs` would have flagged every record naming that file.
5. **[Rule 3] The older-copy record's anchor moved in the red,** not only in the green: the red
   put the older-copy set inside `ToldSoFar`, so the record would have named no place.
6. **[Order] The re-measure ran with the green on disk before the green commit,** as 13.4-01 to
   13.4-03 did.
7. **[Process] The first green commit was refused** after 601 s by
   `the_planning_files_agree_with_themselves`, which read the roadmap row and `completed_plans`
   already moved on disk, unstaged, before this summary existed. A placeholder summary made the
   files agree and the second try passed. The marks are written after the green from now on.
8. **[Count] Five cases, not four,** and six new records, not four, for the fold-in.
