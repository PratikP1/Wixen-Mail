# Phase 13.4 Plan 12: Every window on both channels Summary

**The move changed nothing a scan can see: all 49 windows read the same on MSAA and on UI
Automation before and after, the combo boxes' typing fields are named on both channels, and six
name checks now read the name instead of asking whether an object was attached.**

## What works now

- **The window diff.** A script in the scratchpad read both trees of every window in both runs
  and closed with: `read 49 windows in each run on MSAA and 49 on UI Automation; 0 differ on MSAA
  (0 differences), 0 on UI Automation (0 differences)`. Shown a planted copy first, it found all
  three planted changes under their channels, and it refused a run of one window. All 49

## Deviations from Plan

1. **[Premise] The Prefix and Suffix fields were already read at the edit.** Premise 2 said
   `the_contact_editor_fills_the_name_and_its_parts_from_each_other.rs` measured the combo box
   itself; it reads the first `Edit` inside each box, in its own process, with the colon trimmed.
   The new target reads them from a reader process at the handle `GetFocus` answers, and the words
   as heard, "Prefix:".
2. **[Premise] The Category break reddens nothing.** The plan said to take the new target red by
   removing the Category box's naming call. With it removed the field still reads "Category" on
   both channels, named by its label "Cate&gory". The target's record breaks the label of the
   Prefix and Suffix boxes instead, which reddens it. The naming call still carries the field's
   help sentence as a description, which this reading does not read.
3. **[Premise] The plan's first companion was wrong.** A combo box named on its own handle alone is
   heard with that name where typing lands, the reverse of a spin control. The companion asserts
   what was measured, and a second companion, a box named by nothing, shows the reading sees a
   nameless field.
4. **[Hook] One commit rather than one per file.** The hook refuses a commit while other tracked
   files are unstaged, and stashing is not open to an executor here, so the four test files and
   their records went in one commit.
5. **[Brief] The live size reading was not taken.** No copy of Wixen Mail was running, which the
   plan's condition allowed, but the brief forbids starting the release program on this machine.
   The arithmetic and the runner's 100% sizes stand in; the document says it is owed.
6. **[Brief] Not pushed, no pull request, not merged.** The plan's task 3 pushes and merges; under
   the merge train the merger merges, and the brief pushes only a plan that changes what the
   program says or shows. This one changes tests and documents. So the second diff against this
   branch's own Accessibility run was not taken; there is no code change for it to see.
7. **[Scope] The value box's reading covers the Say this first dialog too**, so the call that
   follows the label is measurable; the first call is redundant and stays, written down.
8. **[Scope] Two side readings beside the script**: every element whatever its process, and the
   window sizes at 100%, both unchanged.

No schema, setting, key, control, label or mnemonic letter changed; no changelog entry, since
nothing a person hears or sees changed. The version stays `1.0.0-alpha.1`.
`git diff main -- Cargo.toml Cargo.lock` is empty.
