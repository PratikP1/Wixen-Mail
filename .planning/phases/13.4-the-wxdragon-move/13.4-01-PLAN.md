<objective>
Count a contact typed here that Allow Changes holds back from Google or Outlook as waiting on the
setting, the way CardDAV's create already counts it, instead of as an error on every contacts
sync.

Purpose: ledger 936, found by 13.3-18 (premise 4 there). With Allow Changes off, a contact typed
here on a Google or Outlook account reaches the create loop, the write gate refuses it before any
request is built, and the refusal lands in the sync's errors. So every contacts sync from then on
says one error per such contact and writes it to the log, while the same refusal from a CardDAV
address book says the Allow Changes sentence once. A warning repeated at every sync is a warning
people stop reading, and this one names the wrong cause: nothing is broken, a setting is off.
Pratik said yes to the recommendation on 2026-10-23 (D-01).

Output: the two arms, the scripted address books' create answering the gate, two cases taken red
first, two new guard records and the flagged ones re-measured, the changelog, ledger 936 closed and
a tester row opened, REAL-01's dated line, the four marks, and the pull request.
</objective>
