<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a stored `feedback_channels` string to this module's parser | a file written by an older or newer build, or edited by hand, and the only route into a per-event override that exists today |
| a per-event override to whether anything is said at all | a wrong answer here is silence about new mail, a failed send or an account that needs attention, for somebody who cannot see the screen |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | a hand-edited or newer-version `feedback_channels` string reaching `from_stored` | medium | mitigate | already handled and must stay handled: unknown events and channels are skipped rather than fatal, and `test_stored_settings_ignore_names_they_do_not_recognise` holds it. This plan forbids tightening it into a refusal, and the acceptance criteria require the diff of `from_stored` to be empty. |
| T-06-02 | Denial of service | an override that silences an event somebody needed, written by a caller that meant to clear it | high | mitigate | `use_the_default_for` removes the entry and an empty set is separately meaningful, with a test asserting the two are told apart and a guard record whose break is exactly the confusion between them. |
| T-06-03 | Repudiation | a settings screen showing a state the model does not hold | high | mitigate | this is what `what_was_chosen_for` exists for. Without it a panel built on `channels_for` reports ticks nobody set, which is a screen telling somebody they chose something they did not. 06-02 is held to reading the chosen set and announcing the effective one. |
| T-06-SC | Tampering | npm, pip or cargo installs | high | mitigate | no package is added. `Cargo.toml` is not in this plan's file list and nothing here needs a dependency. |
