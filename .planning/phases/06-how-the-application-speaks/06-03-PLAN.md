**4. Two mechanisms are needed, not one, and the research names only the
first.** Microsoft's `LOCALE_SMONTHNAME` page says a month name looked up on its
own is "the standalone, or nominative, form", and that to get the genitive form

date picture contains both a numeric form of the day (either d or dd) and the
full month name (MMMM)".

of twelve month names in a Choice, where there is no day, wants the standalone
form, which is `GetLocaleInfoW` with `LOCALE_SMONTHNAME1` to `12`. Using the
picture for the Choice puts Russian and Polish months in the wrong case in a
list, and using the lookup for a date puts them in the wrong case in a sentence.

## The reason Fluent won, which is specific to this project

A Fluent message carries attributes, so a control's visible label, its
accessible name and its keyboard mnemonic live in one translatable place.
Firefox's `browser.ftl` uses `.aria-label` 21 times, `.accesskey` 51 times and
`.label` 93 times in one file. That maps onto what this project does with a
visible label plus `set_accessible_name`, and onto the problem nobody
anticipates until the first translation: an `&` mnemonic must be a letter that
exists in the translated label. No other candidate is designed for an
application whose audience hears the interface.

## The three that lost, and what each lost on

- **ICU4X, as the translation half.** `icu_plurals` 2.3.0 is Unicode's own
  rules and is excellent as a formatting primitive, but ICU4X carries no
  message system: `icu` 2.3.1 re-exports fifteen modules and none is
  message-related, the reserved `icu_message` crate has been an empty stub since
  2021, and upstream issue #3028 has been open since January 2023. Its licence
  is `Unicode-3.0`, permissive with a no-name-in-advertising clause. Its MSRV is
  exactly 1.88, this project's floor with zero headroom, and it has raised its
  floor in minor releases: 1.67 in 1.5, 1.86 in 2.2, 1.88 in 2.3.1. It also
  ships `icu_experimental::relativetime`, which produces "2 days ago" in every
  CLDR locale, but that crate is explicitly pre-release, 0.1 to 0.6 in two
  years, breaking roughly every six months.
- **`intl_pluralrules` alone, the minimal stack.** Its plural data is CLDR 37
  against a Unicode that has moved on, its repository has been untouched since
  November 2022, its published tarball ships no licence text, and it returns
  `Result<_, &'static str>` with the message `"unknown locale"`
  (`intl_pluralrules-7.0.2/src/lib.rs:104-121`), which this project's rule
  about stringly-typed values would have you map at the boundary into nothing.
  It is in the chosen closure regardless, one layer down, where `fluent-bundle`
  wraps its error and negotiates around its lookup.
- **A hand-written CLDR table.** Rejected on this project's own guardrails: a
  private copy of an open standard, which goes stale with no commit to this
  repository and no one pressured to fix it.

**Which of those reasons could change, and which could not.** ICU4X's is a
missing crate and an unstable one, and both are the kind of thing a project
ships eventually: read the comparison again if `icu_message` gains a release
or `icu_experimental::relativetime` reaches 1.0. The minimal stack's reason is
that it is one primitive where a message system is needed, and that will not
move. The hand-written table's reason is a guardrail, and it will not move
either.

## The one open question, closed empirically

`fluent-bundle` depends on `intl_pluralrules` directly, and that crate
binary-searches the full locale identifier with no fallback, so
`GetLocaleInfoW` returning `en-GB` looked like it might miss. Probed on
2026-09-13 in a scratch project against `fluent-bundle` 0.16 and `unic-langid`
0.9, with `set_use_isolating(false)`:

en-GB    2 -> 2 days ago             errors=0

ru-RU    1 -> 1 день назад           errors=0
ru-RU    2 -> 2 дня назад            errors=0
ru-RU    5 -> 5 дней назад           errors=0
ru-RU   21 -> 21 день назад          errors=0
pl-PL    1 -> 1 dzień temu           errors=0
pl-PL    2 -> 2 dni temu             errors=0

pl-PL   22 -> 22 dni temu            errors=0

xx-YY    2 -> 2 days ago             errors=0

Region-tagged locales select the right category; Russian's four-way split and
Polish's come out right. **The concern does not bite, and the reason is
readable rather than lucky.** `fluent-bundle-0.16.0/src/types/plural.rs:11-21`
constructs its plural rules by negotiating the bundle's locale against the list
`intl_pluralrules` knows, with `en` as the default and
`NegotiationStrategy::Lookup`, so `en-GB` becomes `en` before the binary search
and `xx-YY` becomes `en` too. That is the last two lines of the probe: **an
unknown locale silently produces English plural behaviour with zero errors.**
It is what criterion 2 asks for, "falling back to English silently", and it
means the error-vector guard below cannot see an unknown locale. The fallback
gets its own test, and the test is there because the default that produces it
is a line in somebody else's crate.

## The four conditions, from Firefox's production use of these crates

Not optional. Each is a task 3 requirement with its own test.

1. **`set_use_isolating(false)`**, as Firefox does. The default is `true` at
   `fluent-bundle-0.16.0/src/bundle.rs:641` and `src/concurrent.rs:39`, and it
   injects U+2068 and U+2069 around every placeable. Microsoft's text stack has
   been shown to render them as junk in a window title, and a screen reader
   given them reads what its synthesiser makes of two invisible characters.
   Every exact-string test in this plan is also a test of this: a string
   holding `\u{2068}2\u{2069} days ago` does not contain `2 days ago`.
2. **A `set_formatter` backed by `GetNumberFormatEx`**, so Fluent's numbers
   agree with the Win32 answers this project already trusts from
   `GetDateFormatEx` and `GetLocaleInfoEx` rather than becoming a second
   opinion. For every value the four messages pass today, integers under 60,
   its output equals Fluent's default `f64::to_string` in every locale, so its
   test has to use a value where the two differ: 1234 under `de-DE`, which
   Windows writes "1.234" and Fluent alone writes "1234".
3. **Pass counts as numbers, and assert `format_pattern`'s error vector is
   empty.** Both silent failure modes are otherwise invisible. A string count
   matches no plural keyword (`fluent-bundle-0.16.0/src/types/mod.rs:188-197`)

   produces "1 days ago" and only the singular assertions see it. A missing
   argument writes `{$days}` into the output and pushes one error
   (`src/resolver/inline_expression.rs:102-114`), so the empty-vector
   assertion sees that one. Plus, per the probe, a separate test that an
   unknown locale behaves as English.
4. **The loader and the completeness check are written in this tree**, about
   fifty lines and a guard test, not a dependency. Every message id the code
   can ask for exists in the English catalogue, and every message in the
   catalogue is one the code can ask for, both directions, because a check
   that asks only one of them passes on an orphaned message forever.
