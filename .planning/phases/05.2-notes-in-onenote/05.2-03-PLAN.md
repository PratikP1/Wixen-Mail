    RED first, on a branch.

    **This is the case the whole seam argument turns on.** Every other backend
    this program talks to gives a marker that changes when and only when the
    content changes: a CalDAV ETag, a Graph contact's `@odata.etag`, a task's
    `remote_updated`. OneNote gives `lastModifiedDateTime` and nothing else, and
    a timestamp is a clock. `whose_copy_wins`'s doc comment says it compares
    markers rather than clocks on purpose.

    So: what does this backend compare? Two candidates and both have a cost.

    - **The timestamp, treated as a marker.** Cheap, and it is wrong whenever the
      service touches a page without the content changing, which produces a
      conflict nobody caused and a question nobody can answer well. It is also
      wrong in the other direction across a clock skew.
    - **A digest of the content this program last saw.** Correct about content,
      needs somewhere to keep it, and a note already has a place for a version
      marker if `05.1-03` added one. It compares what actually matters and it
      costs one stored string per note.

    **Argue for one in a paragraph, and write the reasoning in the seam's
    document rather than only in the code**, because the fourth backend will meet
    the same question.

    **Do not let this backend decide a conflict.** The contract already forbids
    it and `conflict_choice` exists. If a backend with no marker cannot be made
    to raise one through `conflict_choice` without changing that module, say what
    changed and why, and put it at the top of this plan's list.
