<objective>
Turn a note into a OneNote page and back, measure exactly what that loses, and
put the one requirement it breaks in front of the person who wrote it.

Purpose: PIM-07 for the third backend, and PIM-04's byte-identical criterion,
which is the reason this is a phase rather than a plan. `src/application/new_item.rs:19`
has said since before any of this was planned that a OneNote page is an HTML
document inside a section inside a notebook rather than a title and a body, so
the mapping is a decision somebody has to make rather than an afternoon's work.
That sentence is the name of this phase and this plan is the decision it names.

**Nothing here touches a network.** The whole mapping is text in and text out,
which is this project's thin-transport rule and is also what makes the fidelity
measurement possible at all: a round trip that needs a server cannot be measured
by anybody who does not have one, and nobody here has one.

Output: the two conversions, a table of what is lost with the input that
produced each loss, and a criterion that says what is true.
</objective>

<premise_corrections>
**1. Half of the mapping already exists and the plans that preceded this one did
not know it.** `src/application/long_text.rs` holds a matched pair:

- `pub fn as_markup(written: &str) -> String` renders Markdown to HTML with
  `pulldown_cmark::html::push_html` and then runs `ammonia::clean` over the
  result. Its doc comment says "The other direction from `from_markup`, and the
  pair is the point: what somebody typed is kept as markdown, which is legible
  on its own, and the markup is made from it when a message needs one. Nothing
  is stored twice, so the two halves cannot drift apart the way a hand-written
  HTML copy does."
- `pub fn from_markup(html: &str) -> String` runs `ammonia::clean`, parses with
  `scraper`, walks the tree in a private `markup` module with a block pass, an
  inline pass and a list pass, and collapses blank lines.

`grep -n "pub fn as_markup\|pub fn from_markup" src/application/long_text.rs`
finds both. **So this plan does not write a Markdown to HTML converter and does
not add a dependency for one.** What it writes is the page envelope, the
restriction to what OneNote accepts, and the measurement.

`as_markup` also turns every `SoftBreak` into a `HardBreak`, deliberately, with
a comment saying a box somebody typed three lines into is not a document. **That
is right for a signature and is a decision to re-examine for a note**, which is
a document. Say which way it was decided and why.

**2. What a OneNote page's input HTML is, read from Microsoft's reference on
2026-09-06.** (`learn.microsoft.com/en-us/graph/onenote-input-output-html`)

The envelope is an `html` element with a `head` holding a `title` and
optionally `<meta name="created" content="..."/>`, and a `body`. The page's
title is the `title` element, not a heading in the body.

**3. What OneNote does to the body, and each of these is a loss to name.** The
same page says at the top, flatly: "Output HTML won't be the same as input
HTML."

- **Everything is wrapped in a div carrying `data-id="_default"`.** A div that
  carries no semantic information is flattened into its parent; one carrying a
  `data-id` is preserved.
- **Supported inline character styles are `b`, `i`, `u`, `em`, `strong`,
  `strike`, `sup`, `sub`, `del`, `cite`.** There is no `code` and no `pre`. **So
  a Markdown code block and inline code have no representation at all.** That is
  the sharpest single loss and it is knowable before any code runs.
- **Styles set on a parent come back inline on children**, and on `span`
  elements that were not in the input. A `p` with a style attribute comes back
  as a `p` containing a styled `span`.
- **List styles set on the `ol` or `ul` come back on the `li` elements.**
- **Tables lose `rowspan` and `colspan`, which are not supported at all**, and
  gain `border:0px` on every cell.
- The supported inline CSS properties are a fixed list of nine.
- `blockquote` is not in any supported-element list on that page. **Check it
  rather than assuming**: a Markdown quote is a `Piece::Quote` in this
  program's own model and losing it silently would be worse than losing it
  loudly.

**4. `Piece` is the list of constructs this program's own model has**, and it is
the right basis for the fidelity table rather than the whole of Markdown.
`src/application/long_text.rs:30`: `Heading { level, text }`,
`Item { ordered, text }`, `Quote(String)`, `Image(String)`, `Paragraph(String)`.
Five, and the table has at least a row for each, plus the inline styles
`as_markup` can emit and the code construct that `Piece` does not model but
`pulldown-cmark` does.

**5. The obvious idea for keeping the source, and why it is not obviously
right.** A `data-id` survives the round trip, and a div carrying one is
preserved. So a hidden div holding the Markdown source looks like a way to make
the round trip exact. It is worth trying and it is not free: the text inside
that div is still normalised into styled paragraphs, so the source would come
back with its blank lines and its leading `#` characters reshaped. It also puts
a copy of the note inside the note, which is the second stored copy
`as_markup`'s own comment says the pair exists to avoid. **Try it, measure it,
and report it, and do not build on it without the measurement.**

**6. This is a requirement change and the checkpoint is where it belongs.**
PIM-04's `[D]` line says the stored form is the Markdown source and that a note
round-trips through **any** backend byte-identically when nothing changed. If
the measurement says OneNote cannot, the criterion is either narrowed to
backends that can, or the seam refuses backends that cannot, or the criterion
becomes something weaker like "no information is lost". **Those are three
different products and the choice is not the executor's.** The checkpoint is at
the end of this plan so the two conversions and the measurement are done and
merged whichever way it goes.

**7. Guard-record cost.** Re-measure with the awk in `CLAUDE.md` at the tree you
are on. At `9611b70` on `main`, `src/application/long_text.rs` carried **18**
records and `src/service/microsoft_graph.rs` carried **0**. A new file under
`src/service/` carries none. **Put every new test in the new file.** A `#[test]`
in `long_text.rs` fires the count check inside the commit gate and puts 18
builds and 18 full library runs on the critical path, and if `long_text.rs` has
to change at all, changing it without adding a test there is free.

**8. Adding a record to `guards/guards.toml` changes the census at the top of
the file in the same commit.** A commit touching `Cargo.toml` makes
`scripts/which-checks.sh` answer `all`; run those detached. A red commit is
allowed only on a branch and names every failing test in `Fails-until-green:`
trailers at column 0, naming test functions.

**9. No new dependency.** `pulldown-cmark`, `scraper`, `ammonia` and
`html-escape` are all already in `Cargo.toml`. If a new one seems necessary, use
the `dependency-audit` skill and put the justification in a comment above it the
way `ring`, `x509-parser` and `image` carry theirs. The likely answer is that
none is needed.
