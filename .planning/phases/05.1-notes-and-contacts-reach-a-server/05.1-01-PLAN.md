<objective>
Make a note's stored form say what a note's body really is, and prove the round
trip that PIM-04 promises.

Purpose: PIM-04. Three of its six criteria already ship and the requirement did
not know it: the content model reuses `long_text.rs` rather than inventing a
second one, the stored form is the Markdown source, and a screen reader reads
the rendered structure. The remaining three are about sync and belong to PIM-07.
What is left inside PIM-04 is one loose end that the requirement, the research
and this project's own observation log all name: the `notes.format` column is
written as the literal `"plain"` at every site and read by no production code,
while the editor calls the box "Body, in Markdown" and the reader parses it as
Markdown.

Output: a column that means something or is honestly retired, and a test that
puts a note's body through storage and back and asserts nothing changed.

This is the first plan of phase 5.1 and it touches no server. What it settles is
what a note *is* on this computer, which every backend after it has to
round-trip. Getting it wrong here is wrong in three backends.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a note body from an imported Outlook data file -> storage and then the reader | the body comes from a file somebody else made and is spoken aloud |
| a stored column value from an older or a later build -> this build's reader | a value this build did not write can be in a database it opens |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-17 | Denial of service | a stored column value this build does not recognise stopping a note being read | medium | mitigate | follow `AddressBook::Other(String)`: an unrecognised word survives being read and written back. A test drives it. |
| T-05-18 | Tampering | a body silently changed on its way through storage | high | mitigate | task 1's fixtures, aimed at trimming, at line-ending normalisation and at a byte-length assumption, with a guard record whose break is a trim in `save_note`. |
| T-05-19 | Information disclosure | a note's body in a log line or an error message | medium | accept | pre-existing and unchanged. `CLAUDE.md` forbids logging a message body and `tasks_sync.rs`'s comment about ids rather than titles is the precedent. Nothing added here logs a body. Check any new error message against that before writing it. |
| T-05-20 | Information disclosure | a note body read aloud in a room | low | accept | pre-existing. The mute this project's fifth guardrail names already exists. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package is added. `pulldown-cmark` is already a direct dependency, imported by `long_text.rs`. `Cargo.toml` is touched only by version bumps and the diff is read rather than assumed. |
