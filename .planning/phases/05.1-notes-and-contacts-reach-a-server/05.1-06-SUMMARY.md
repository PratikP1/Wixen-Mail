# Phase 05.1 Plan 06: An address book added by its address, and a password that does not outlive the program Summary

**Somebody can add a CardDAV address book from the Tools menu, its contacts sync both ways through the merge Google and Outlook contacts already use, and its password goes where Windows keeps passwords. Nothing here has met a CardDAV server.**

## Does it work

**The parts that can be answered on this computer work and are tested. The part
that matters most cannot be answered here.**

What runs: a row in the `address_books` table, a sign-in in the credential store,
the four CardDAV requests built and their verbs and addresses read off a real
socket by tests, a sync that feeds the contact merge, a screen, a menu item, and
a contacts sync that walks an account's address books and syncs each one. That
last hop is what this project's first guardrail is about, and it is in
`spawn_contacts_sync` where a test reads for it.

What has never happened: any of it against a CardDAV server. Every fixture was
written in this repository. A card this writes and this reads proves the pair
agrees with itself. Whether SabreDAV, Fastmail or Nextcloud answers the way the
fake does is six separate unknowns, and ledger entries 254 to 265 name them one
at a time.

**And nobody has heard the new screen.** That is the checkpoint at the end of
this document and it is the only thing in phase 5.1 no test here can settle.

## The checkpoint, written as instructions

**This is not answered and must not be read as answered. Nothing below claims

### Getting there

1. Start the build from this merge, `ff70115`, version `0.107.0`.
2. Have NVDA running before you open it.
3. Open the **Tools** menu with `Alt+T`, then press `r`. The item reads
   "Add an Address Book by Address".

You do not need a CardDAV server for steps 1 to 3 and 5 below. Step 4 needs one,
and if you have none, say so and skip it: what it would tell us is separate from
what the rest tell us.

### What to listen for, and what each answer means

**Step 1. Tab through every control and say what each one announces.**

There are five: the warning text, the Address box, the User name box, the
Password box, and the Add and Cancel buttons.

- *If it is right,* you hear the experimental sentence first, then "Address,
  edit", "User name, edit", "Password, protected edit" (or your reader's word
  for a password box), then "Add, button" and "Cancel, button".
- *If a box announces only "edit" with no name,* `set_accessible_name` did not
  reach the accessibility tree for that control. That is the sixteen-widgets
  defect again and it is a bug, not a wording problem.
- *If a box announces the right name,* that still does not prove this code set
  it. Windows gives a control the nearest visible label as its MSAA name when
  nothing set one, and every one of these boxes has a visible label right
  beside it. **So please say, for each box, whether the name you heard is the
  label text exactly.** If it is, we cannot tell from your run which of the two
  gave it, and that is worth knowing: it means the name would vanish if the
  layout changed.

**Step 2. Press `Alt+D`, `Alt+U`, `Alt+P`, `Alt+A` and `Alt+C` in turn.**

- *If it is right,* the first three move focus into the Address, User name and
  Password boxes, and `Alt+C` closes the window with nothing stored.
- *If one does nothing,* the mnemonic on the label is not reaching the box
  beside it. A test in this repository refuses two controls in one dialog
  claiming one letter, so a clash is already ruled out; whether the letter
  reaches anything is not, and that is what this step is for.
- *If `Alt+A` does something before you have typed an address,* say so. It
  should try and be refused, not act.

**Step 3. Type something that cannot be used and press Add. Try each of these,
one at a time:**

- nothing at all
- `http://dav.example.com/books/` (not secure)
- `https://sam@dav.example.com/books/` (a user name inside the address)
- `https://dav.example.com/a book/` (a space in it)

*If it is right,* each is refused before anything leaves the machine, with a
sentence naming which of the four it was, and you hear the sentence rather than
finding it by exploring. *If you hear nothing,* the refusal is drawn and not
announced, which is a bug. *If any sentence says the word "calendar",* something
went past three tests and I want to know.

**Step 4. If you have a CardDAV server, add one.**

*If it is right,* something says the looking has started and how long it can
take, you can stop it, and when it answers you hear how many address books were
found before you are put into the list. Then you hear which one was added.
*If the window goes quiet for up to thirty seconds,* the asking is on the wrong
thread, which would be a bug the tests say is not there. *If a count is drawn
and not said,* say so.

**Step 5. Where the warning sits.**

*If it is right,* you meet "This is experimental. Nothing here has been tried
against a real address book server yet" **before** you reach the password box,
because it is the first thing in the window. *If you reach the password box
first,* the order is wrong and that matters: a warning after the password is a
warning nobody acts on.

### Then the two scans, and they answer different questions

Run both, per window, on the new dialog:

- **Axe.Windows**, which reads UI Automation. That is what Narrator reads.
- **`scripts/msaa-names.ps1`**, which reads MSAA through `IAccessible`. That is
  what NVDA reads for native controls, and it is the only place
  `set_accessible_name` writes.

A name that fails on either channel is a name somebody does not hear. For an
edit box or a button, Windows supplies its own UI Automation provider that
shadows the MSAA object, so **Axe.Windows will report the system's name and
never the one this code set**. Do not read a clean Axe run as saying the names
in this code are right.

## What the plan got wrong against the tree

**1. The completeness guard already existed.** Premise 2 says `04-09` "has not
run" and that this plan writes the guard. `04-09-SUMMARY.md` is on disk and
`test_every_owner_of_credential_entries_is_named_where_uninstalling_reads` was
already in `forget.rs`, with a comment asking the next owner for a second test
of a particular shape. It was extended, not duplicated, which is what the plan
says to do if this happened. It caught the new owner with no test written for
it.

**2. And the guard it built was weaker than it read.** It looked for the bare
module name in `entries_for`'s source. `entries_for` grew a parameter called
`carddav_address_book_ids` and nothing else, which is exactly the failure the
guard exists to catch, and the guard was quiet, because the parameter's own name
contains the word. It now asks for the name followed by `::`, with a fixture
test holding both directions. Found by running it, not by reading it.

**3. `outward`'s census refused the new client, and its floor was a
measurement.** Nothing in the plan mentions `src/service/outward.rs`.
`test_every_module_that_names_a_way_out_is_on_one_of_these_lists` refused a file
naming `reqwest` and on no list, which is right. Then
`test_every_provider_write_is_on_one_of_the_two_wire_lists` refused the client
for having only two writes against a floor of three. The floor's own comment
said "Three is what the smallest of these clients has", which was a measurement
of the tree, and a CardDAV client legitimately has two because a card is created
and replaced by one request. The floor moved to two with the date and the
reason. The alternative, padding the client, is the failure this project keeps
describing.

**4. Task 1's guard break belonged to task 3.** The plan asks task 1 to break
the record by "writing the password into the address book row". At task 1 the
only code that could is `save_address_book`, which never sees a sign-in. The
record task 1 carries is the per-book filing word instead, broken by writing the
research's own sentence; the password-in-the-row test drives the real adding
path and lives in task 3's module.

**5. The task 3 test file is a module the plan does not list.**

**6. Every figure had moved again.** Measured at the start: `main` at `2e420fe`,

at 259, `managers.rs` 137 tests and not 139, `wx_app.rs` 199. The plan said 683
