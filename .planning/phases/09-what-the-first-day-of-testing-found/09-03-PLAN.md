**2. #56 is deeper than a sentence: the variant it lands on is documented as
delivery.**

```
grep -n 'fn send_the_answer\|fn answer_the_invitation\|fn queue_for_sending' src/presentation/wx_app.rs
  -> 13018 answer_the_invitation, 13129 send_the_answer, 15276 queue_for_sending

  -> pub enum HowItWent { /// The answer reached the organiser's mail server.  Sent, /// Nothing left this machine.  DidNotSend { because } }

```

`send_the_answer` builds a `ComposeData` with `send_at: None` and calls
`queue_for_sending`, which returns `Ok((String, GoAfter))`; the `GoAfter` is
discarded (`Ok(_) => HowItWent::Sent`). The composer's own path words a
`GoAfter::Held` through `sending_later::countdown` at `:426` and `:600`. So the
fix is to carry the `GoAfter` into `HowItWent` and word it the same way.

**3. What a held answer files is a decision, and the plan makes it.**
`answered_meetings::file_the_answer(cache, account, ready, answer, &went)` at
`wx_app.rs:13106` files the meeting on the calendar and "decides for itself
that an answer which never left the machine is not written down as though it
had", reading `went`. With a `Held` variant it must decide again. Two options:
file on `Held` as it files on `Sent` today, so the calendar says what the
person answered from the moment they pressed, and an Undo Send afterwards
takes back the reply and leaves the calendar entry, which is said plainly;
or file only when the queue drains, which needs a hook from the send loop back
to the calendar that does not exist and is a feature of its own. This plan
takes the first, because answering the same meeting again replaces the entry
(criterion 8 of phase 4.2, `answered_meetings.rs:150`), so a person who undoes
and answers differently ends with the calendar right, and the ten seconds in
between are said in the changelog and ledgered. The executor may overrule with
a reason in the summary.
